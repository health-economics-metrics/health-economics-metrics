# សេដ្ឋកិច្ចឯកតាពពក (FinOps)

សេដ្ឋកិច្ចឯកតាពពកបកប្រែការចំណាយពពកឆៅទៅជា **ថ្លៃដើមក្នុងមួយឯកតានៃលទ្ធផល** — ក្នុងមួយអតិថិជន ក្នុងមួយប្រតិបត្តិការ ក្នុងមួយករណីដែលបានដោះស្រាយ ក្នុងមួយតូខឹន។ វាជាសមត្ថភាព FinOps ដែលបម្លែង "វិក្កយបត្រ AWS របស់យើង £400k/ខែ" ទៅជា "ការបម្រើអ្នកជំងឺម្នាក់ចំណាយ £0.83"។

## ហេតុអ្វីបានជាសំខាន់

តួលេខចំណាយសរុបមិនអាចឆ្លើយសំណួរដែលសំខាន់៖ តើផលិតផលកាន់តែមានប្រសិទ្ធភាព ឬតិចជាងមុន? តើកំណើនកែលម្អ ឬបំផ្លាញរឹមប្រាក់? តើយើងគួរគិតថ្លៃប៉ុន្មាន? ថ្លៃដើមឯកតាឆ្លើយទាំងបី។ សម្រាប់សុខភាពឌីជីថលជាពិសេស "ថ្លៃដើមក្នុងមួយករណីដែលបានដោះស្រាយ" *គឺជា* ថ្លៃដើមឯកតាសេវាសុខាភិបាល — អាចប្រៀបធៀបដោយផ្ទាល់នឹងតួលេខ[National Cost Collection](../តម្លៃសេវាជាតិ-និងថ្លៃដើមឯកតា/)ដែលអ្នកកម្មវិធីសុខាភិបាលប្រើសម្រាប់សេវាផ្សេងទៀតទាំងអស់ ដែលធ្វើឱ្យវាជាភាសាធម្មជាតិសម្រាប់កំណត់តម្លៃផ្លូវឌីជីថលធៀបនឹងប្រពៃណី។

## គណិតវិទ្យា

```
Unit cost = total allocated cost (incl. shared/platform costs) / units delivered

Two families:
  resource-efficiency units: cost/GB stored, cost/vCPU-hour, cost/token,
                             cost/build-minute
  business units:            cost/customer, cost/transaction, cost/consultation,
                             cost/case-resolved

Marginal vs average discipline applies (marginal-vs-average-cost.md):
committed/reserved spend makes marginal unit cost ≈ 0 until the next
commitment step — price expansion decisions at marginal, efficiency
trends at average.
```

## ឧទាហរណ៍ដែលបានគណនា

សេវាចាត់ថ្នាក់ឌីជីថល៖ ចំណាយពពក £62,000/ខែ (គណនា £30k ទិន្នន័យ £18k ការបែងចែកវេទិកាចែករំលែក £14k) ដោះស្រាយ 380,000 ករណីចាត់ថ្នាក់/ខែ៖

```
Average cost per episode = 62,000 / 380,000 ≈ £0.163

Commissioner comparison: telephone triage ≈ £8–12/call, GP consultation ≈ £42
→ digital episode runs at ~2% of the cheapest human alternative — the
channel-shift economics of gds-service-metrics.md, from the cost side.

Trend check: last year £0.21/episode at 240k episodes → improving scale
economics (fixed platform costs amortizing), worth a headline in the QBR.
```

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

សេដ្ឋកិច្ចឯកតាគឺជាកន្លែងដែលជម្រើសវិស្វកម្មក្លាយជាអាចអានបានដោយហិរញ្ញវត្ថុ៖ ស្ថាបត្យកម្មដែលកាត់បន្ថយថ្លៃដើមក្នុងមួយករណីពាក់កណ្តាលគឺជាអត្ថប្រយោជន៍កំណត់តម្លៃ; មួយដែលពង្រីកលើសលីនេអ៊ែរគឺជាគ្រាប់បែកពេលវេលាដែលអាចមើលឃើញតែក្នុងរង្វាស់នេះ។ ការអនុវត្តដែលផ្ទេរពីការគិតថ្លៃសុខាភិបាល៖ **បោះពុម្ពច្បាប់ការបែងចែក** (ថ្លៃដើមរួមបង្ខូចតួលេខក្នុងមួយឯកតារហូតដល់ PLICS ធ្វើស្តង់ដារការគិតថ្លៃកម្រិតអ្នកជំងឺ — ការបែងចែកថ្លៃវេទិការបស់អ្នកត្រូវការភាពម៉ត់ចត់ដូចគ្នា); **ជ្រើសឯកតាដែលអ្នកទិញគិត** (អ្នកកម្មវិធីសុខាភិបាលទិញករណី មិនមែន vCPU ទេ); ហើយបញ្ចូលថ្លៃដើមឯកតាទៅក្នុងរាល់គំរូ [ICER](../សមាមាត្រប្រសិទ្ធភាពថ្លៃដើមបន្ថែម/) និង[ផលប៉ះពាល់ថវិកា](../ការវិភាគផលប៉ះពាល់ថវិកា/) ជាភាគបែងថ្លៃដើមដែលមានសិទ្ធិអំណាច។ សម្រាប់មុខងារ AI ឯកតាគឺតូខឹន — សូមមើល[សេដ្ឋកិច្ចឯកតាអនុមាន](../សេដ្ឋកិច្ចឯកតានៃការអនុមាន/)។

## កំហុសដែលត្រូវជៀសវាង

- **មិនយកចិត្តទុកដាក់ចំពោះថ្លៃដើមរួម**៖ ថ្លៃដើមឯកតាដែលមិនរួមបញ្ចូលការបែងចែកវេទិកា/សុវត្ថិភាព/on-call ប៉ាន់ស្មានទាប 30–50% ហើយដួលរលំពេលសវនកម្ម។
- **ភាគបែងឥតន័យ**៖ "ថ្លៃដើមក្នុងមួយការហៅ API" បញ្ជោរ; "ថ្លៃដើមក្នុងមួយករណីអ្នកជំងឺដែលបានបញ្ចប់" ផ្តល់ព័ត៌មាន។
- **ការកំណត់តម្លៃតាមថ្លៃដើមមធ្យមនៃការសម្រេចចិត្តរឹតបន្តឹង**៖ គិតថ្លៃក្រុមតាមថ្លៃដើមឯកតាមធ្យមសម្រាប់ការប្រើប្រាស់ដែលឥតគិតថ្លៃរឹតបន្តឹង ជំរុញល្ខោនជៀសវាងការខ្ជះខ្ជាយ (សូមមើល[តារាងតម្លៃជាតិ](../តម្លៃសេវាជាតិ-និងថ្លៃដើមឯកតា/)សម្រាប់កំហុសការលើកទឹកចិត្តកំណែ NHS)។
