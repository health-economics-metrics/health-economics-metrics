# ಹರಿವಿನ ಮಾಪನಗಳು

ಹರಿವಿನ ಮಾಪನಗಳು ಕೆಲಸ ವಿತರಣಾ ವ್ಯವಸ್ಥೆಯ ಮೂಲಕ ಹೇಗೆ ಚಲಿಸುತ್ತದೆ ಎಂದು ಅಳೆಯುತ್ತವೆ: ಚಕ್ರ ಸಮಯ, ಲೀಡ್ ಟೈಮ್, ಥ್ರೂಪುಟ್, ಪ್ರಗತಿಯಲ್ಲಿರುವ ಕೆಲಸ (WIP), ಮತ್ತು ಹರಿವಿನ ದಕ್ಷತೆ. ಇವು ಲಿಟ್ಲ್‌ನ ನಿಯಮದಿಂದ ನಿಯಂತ್ರಿಸಲ್ಪಡುತ್ತವೆ — ಆಸ್ಪತ್ರೆ ಹಾಸಿಗೆಗಳು ಮತ್ತು ಕಾಯುವ ಪಟ್ಟಿಗಳನ್ನು ನಿಯಂತ್ರಿಸುವ ಅದೇ ಸರತಿ ಗಣಿತ.

## ಇದು ಏಕೆ ಮುಖ್ಯ

ಹೆಚ್ಚಿನ ವಿತರಣಾ ಸಮಯ ಕೆಲಸವಲ್ಲ — ಕಾಯುವಿಕೆ. ಜ್ಞಾನ-ಕೆಲಸದ ಹರಿವು-ದಕ್ಷತೆ ಅಧ್ಯಯನಗಳು ವಸ್ತುಗಳ ಮೇಲೆ ಕಳೆದ ಸಮಯದ ಕೇವಲ **5–15%** ಸಕ್ರಿಯವಾಗಿ ಕೆಲಸ ಮಾಡಲಾಗುತ್ತದೆ ಎಂದು ನಿಯಮಿತವಾಗಿ ಕಂಡುಕೊಳ್ಳುತ್ತವೆ; ಉಳಿದದ್ದು ಸರತಿಗಳು. ಅಂದರೆ ಅತಿ ಅಗ್ಗದ ವೇಗವರ್ಧನೆ ನೇಮಕಾತಿಯಲ್ಲ, ಸರತಿ ತೆಗೆದುಹಾಕುವಿಕೆ — ಆಸ್ಪತ್ರೆ ರೋಗಿ-ಹರಿವು ಕಾರ್ಯಕ್ರಮಗಳು ಹಾಸಿಗೆಗಳ ಬಗ್ಗೆ ಕಂಡುಕೊಂಡ ಒಳನೋಟ. [ವಿಳಂಬದ ವೆಚ್ಚ](../ವಿಳಂಬದ-ವೆಚ್ಚ/) ಇರುವ ಯಾವುದೇ ವಿಷಯಕ್ಕೆ, ಹರಿವಿನ ಮಾಪನಗಳು ವಿಳಂಬ ವೆಚ್ಚ ಎಲ್ಲಿ ಸಂಚಯವಾಗುತ್ತದೆ ಎಂದು ಪತ್ತೆಹಚ್ಚುತ್ತವೆ.

## ಗಣಿತ

```
Cycle time      = t(finished) − t(started)
Lead time       = t(delivered) − t(requested)     (includes pre-work queue)
Throughput      = items completed / period
WIP             = items started but unfinished
Flow efficiency = active time / (active + wait time) × 100

Little's Law:  average WIP = throughput × average cycle time
               (equivalently: cycle time = WIP / throughput)
```

ಲಿಟ್ಲ್‌ನ ನಿಯಮವೇ ಸನ್ನೆಗೋಲು: ನಿಗದಿತ ಥ್ರೂಪುಟ್‌ನಲ್ಲಿ, WIP ಕಡಿತ ಚಕ್ರ ಸಮಯವನ್ನು ಅನುಪಾತದಲ್ಲಿ ಕಡಿತಗೊಳಿಸುತ್ತದೆ. ಇದು ಆಸ್ಪತ್ರೆಗಳನ್ನೂ ನಡೆಸುತ್ತದೆ: `ಆಕ್ರಮಿತ ಹಾಸಿಗೆಗಳು = ದಿನಕ್ಕೆ ದಾಖಲಾತಿಗಳು × ಉಳಿಯುವ ಅವಧಿ`.

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

ತಂಡದಲ್ಲಿ ಪ್ರಗತಿಯಲ್ಲಿ 40 ವಸ್ತುಗಳಿವೆ ಮತ್ತು ವಾರಕ್ಕೆ 10 ಪೂರ್ಣಗೊಳಿಸುತ್ತದೆ: ಚಕ್ರ ಸಮಯ = 40/10 = 4 ವಾರಗಳು. ಅವರು WIP ಮಿತಿಗಳನ್ನು ವಿಧಿಸಿ WIP ಅನ್ನು 15ಕ್ಕೆ ಇಳಿಸುತ್ತಾರೆ: ಚಕ್ರ ಸಮಯ = 15/10 = **1.5 ವಾರಗಳು** — ಅದೇ ಜನರು, ಅದೇ ಥ್ರೂಪುಟ್, 62% ವೇಗದ ವಿತರಣೆ, ಕೇವಲ ಸರತಿ ಶಿಸ್ತಿನಿಂದ.

CoD ಜೊತೆ ಬೆಲೆ ಕಟ್ಟಿ: ವಸ್ತುಗಳಿಗೆ ಸರಾಸರಿ ವಾರಕ್ಕೆ £3,000 ವಿಳಂಬ ವೆಚ್ಚ ಇದ್ದರೆ, ಪ್ರತಿ ವಸ್ತು ಈಗ 2.5 ಕಡಿಮೆ ವಾರ ಸರತಿಯಲ್ಲಿ ಕಳೆಯುತ್ತದೆ: ವಾರಕ್ಕೆ 10 ವಸ್ತುಗಳು × 2.5 × 3,000 = **ವಾರಕ್ಕೆ £75,000 ವಿಳಂಬ ವೆಚ್ಚ ನಿವಾರಣೆ** — ಏನೂ ವೆಚ್ಚವಾಗದ ನೀತಿ ಬದಲಾವಣೆಯಿಂದ.

ಆಸ್ಪತ್ರೆ ಪ್ರತಿಬಿಂಬ: ದಿನಕ್ಕೆ 40 ದಾಖಲಾತಿಗಳು × 6.0 ದಿನ LOS = 240 ಹಾಸಿಗೆಗಳು; LOS ಒಳಗಿನ ಕ್ಲಿನಿಕಲ್-ಅಲ್ಲದ ಕಾಯುವಿಕೆಯನ್ನು 5.6 ದಿನಗಳಿಗೆ ಇಳಿಸಿದರೆ 16 ಹಾಸಿಗೆಗಳು ಮುಕ್ತ ([ಉಳಿಯುವ ಅವಧಿ](../ಆಸ್ಪತ್ರೆ-ವಾಸದ-ಅವಧಿ/)) — ಅದೇ ನಿಯಮ, ಅದೇ ಸನ್ನೆಗೋಲು.

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್‌ನೊಂದಿಗಿನ ಸಂಬಂಧ

ಹರಿವಿನ ಮಾಪನಗಳು ವಿತರಣಾ ಎಂಜಿನಿಯರಿಂಗ್ ಮತ್ತು ಆರೋಗ್ಯ ಕಾರ್ಯಾಚರಣೆಗಳ ನಡುವಿನ ಹಂಚಿಕೆಯ ಭಾಷೆ:

- **PR ಉಪ-ಹಂತ ಮಾನದಂಡಗಳು** (LinearB, ~8M PRಗಳು): ಶ್ರೇಷ್ಠ ತೆಗೆದುಕೊಳ್ಳುವ ಸಮಯ < 7ಗಂ, ವಿಮರ್ಶೆ < 6ಗಂ, ಒಟ್ಟು ಚಕ್ರ < ~26ಗಂ — ತೆಗೆದುಕೊಳ್ಳುವ ಸಮಯ ಶುದ್ಧ ಸರತಿ, ಮೊದಲು ಆಕ್ರಮಿಸಬೇಕಾದದ್ದು.
- **[ಕಾಯುವ ಪಟ್ಟಿಗಳು](../ಕಾಯುವ-ಪಟ್ಟಿಯ-ಪರಿಣಾಮ/)** ಬಾಕಿಗಳು; **[RTT](../ಚಿಕಿತ್ಸೆಗೆ-ಉಲ್ಲೇಖ/)** ಲೀಡ್ ಟೈಮ್; **[ಹಾಸಿಗೆ ಆಕ್ರಮಣ](../ಉಳಿತಾಯವಾದ-ಹಾಸಿಗೆ-ದಿನಗಳು/)** WIP. ಸುಧಾರಣೆ ಎರಡೂ ದಿಕ್ಕಿನಲ್ಲಿ ವರ್ಗಾವಣೆಯಾಗುತ್ತದೆ: WIP ಮಿತಿಗಳು ↔ ದಾಖಲಾತಿ ಸುಗಮಗೊಳಿಸುವಿಕೆ; ಸರತಿ-ಸಮಯ ಉಪಕರಣ ↔ ಮಾರ್ಗ-ಹಂತ ಟ್ರ್ಯಾಕಿಂಗ್.
- 15%ಕ್ಕಿಂತ ಕಡಿಮೆ ಹರಿವಿನ ದಕ್ಷತೆ ಎರಡೂ ಕ್ಷೇತ್ರಗಳಲ್ಲಿ ಸಾಮಾನ್ಯ, ಮತ್ತು ಎರಡೂ ಅದನ್ನು ಮರೆಮಾಡುತ್ತವೆ ಏಕೆಂದರೆ *ಜನರು* ಕಾರ್ಯನಿರತರು ಆದರೆ *ಕೆಲಸ* ಕಾಯುತ್ತಿದೆ — ಕೆಲಸಗಾರರ ಗಡಿಯಾರವಲ್ಲ, ಕೆಲಸದ ಗಡಿಯಾರವನ್ನು ಅಳೆಯಿರಿ.

## ಎಡವಟ್ಟುಗಳು

- **ಬಳಕೆ ಆರಾಧನೆ**: ಕೆಲಸಗಾರರ ಬಳಕೆಯನ್ನು 100%ಕ್ಕೆ ತಳ್ಳುವುದು ಸರತಿ ಸಮಯಗಳನ್ನು ರೇಖೀಯವಲ್ಲದ ರೀತಿ ಸ್ಫೋಟಿಸುತ್ತದೆ (M/M/1: ಕಾಯುವಿಕೆ ∝ ρ/(1−ρ)) — 95%-ಆಕ್ರಮಿತ ಆಸ್ಪತ್ರೆಗಳು ಸ್ಥಗಿತಗೊಳ್ಳುವ ಮತ್ತು 95%-ಹಂಚಿಕೆಯ ತಂಡಗಳು ನಿಲ್ಲುವ ಕಾರಣ.
- **ಓರೆ ವಿತರಣೆಗಳ ಮೇಲೆ ಸರಾಸರಿಗಳು**: ಚಕ್ರ ಸಮಯಗಳು ಭಾರ-ಬಾಲದವು; ಸರಾಸರಿಗಳಲ್ಲ, ಶೇಕಡಾವಾರು ಮೌಲ್ಯಗಳೊಂದಿಗೆ (p85) ಮುನ್ಸೂಚಿಸಿ.
- **ಮೇಲ್ಭಾಗದಲ್ಲಿ ಕೆಲಸವನ್ನು ತಿರಸ್ಕರಿಸುವ ಮೂಲಕ WIP ಕಡಿತ** ಮತ್ತು ಅದನ್ನು ಹರಿವಿನ ಸುಧಾರಣೆ ಎಂದು ಕರೆಯುವುದು — ಬೇಡಿಕೆ ಮಾಯವಾಗಲಿಲ್ಲ, ಅದು ಮಾಪನ ಗಡಿಯ ಹೊರಗೆ ಸರತಿಯಾಯಿತು (ಆಸ್ಪತ್ರೆ ಆವೃತ್ತಿ: ED ಹೊರಗೆ ಕಾಯುವ ಆಂಬ್ಯುಲೆನ್ಸ್‌ಗಳು).
