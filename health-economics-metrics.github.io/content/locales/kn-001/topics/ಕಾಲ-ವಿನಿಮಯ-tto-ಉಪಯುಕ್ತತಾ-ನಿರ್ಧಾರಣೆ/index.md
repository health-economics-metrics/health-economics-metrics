# ಕಾಲ ವಿನಿಮಯ (TTO) ಉಪಯುಕ್ತತಾ ನಿರ್ಧಾರಣೆ

TTO ಎಂಬುದು ಆರೋಗ್ಯ-ಸ್ಥಿತಿ ಉಪಯುಕ್ತತಾ ಮೌಲ್ಯವನ್ನು ಸೃಷ್ಟಿಸುವ ಬದಲು ಉತ್ತರದಾತನಿಂದ ನೇರವಾಗಿ ಪಡೆಯುವ ಪ್ರಮಾಣಿತ ವಿಧಾನ. [EQ-5D](../eq-5d/) ನಂತಹ ಸಾಧನಗಳ ಹಿಂದಿನ ಮೌಲ್ಯ ಗುಚ್ಛಗಳನ್ನು — ಹೀಗಾಗಿ ಕೆಳಹರಿವಿನ ಹೆಚ್ಚಿನ [QALY](../ಗುಣಮಟ್ಟ-ಹೊಂದಾಣಿಕೆಯ-ಜೀವ-ವರ್ಷ/) ಲೆಕ್ಕಾಚಾರಗಳ ಹಿಂದಿನದನ್ನು — ಉತ್ಪಾದಿಸುವ ನಿರ್ಧಾರಣಾ ವಿಧಾನಗಳಲ್ಲಿ (ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಗ್ಯಾಂಬಲ್ ಮತ್ತು ಪ್ರತ್ಯೇಕ-ಆಯ್ಕೆ ಪ್ರಯೋಗಗಳೊಂದಿಗೆ) ಇದೂ ಒಂದು.

## ಇದು ಏಕೆ ಮುಖ್ಯ

QALY ಲೆಕ್ಕಾಚಾರಕ್ಕೆ ಹೋಗುವ ಪ್ರತಿ ಉಪಯುಕ್ತತಾ ತೂಕವೂ ಎಲ್ಲಿಂದಲೋ ಬರಬೇಕಿತ್ತು. TTO ಹೀಗೆ ಪಡೆಯುತ್ತದೆ: ಸಾವಿಗಿಂತ ಉತ್ತಮ ಎಂದು ಪರಿಗಣಿಸಲಾದ ಸ್ಥಿತಿಗೆ, ದುರ್ಬಲ ಸ್ಥಿತಿಯಲ್ಲಿನ `T` ವರ್ಷಗಳಿಗೆ ಸಮ ಎಂದು ಅವರು ಪರಿಗಣಿಸುವ ಪೂರ್ಣ ಆರೋಗ್ಯದ ವರ್ಷಗಳ ಸಂಖ್ಯೆ `X` ಎಷ್ಟು (`X < T`) ಎಂದು ಉತ್ತರದಾತರನ್ನು ಕೇಳಲಾಗುತ್ತದೆ; ಉಪಯುಕ್ತತೆ `X / T`. ಕೆಲವು ಉತ್ತರದಾತರು ಸಾವಿಗಿಂತ ಕೆಟ್ಟದೆಂದು ಪರಿಗಣಿಸುವ ಸ್ಥಿತಿಗೆ, ಪ್ರಮಾಣಿತ ಸೂತ್ರ ಕುಸಿಯುತ್ತದೆ (ಸೊನ್ನೆಗಿಂತ ಕೆಳಗಿನ ಉಪಯುಕ್ತತೆಗಳನ್ನು ಸ್ವಚ್ಛವಾಗಿ ಪ್ರತಿನಿಧಿಸಲಾಗದು), ಆದ್ದರಿಂದ ವಿಸ್ತೃತ TTO ಅನ್ವಯಿಸುತ್ತದೆ. ಉಪಯುಕ್ತತಾ ತೂಕವನ್ನು, ಅದನ್ನು ಉತ್ಪಾದಿಸಲು ಮಾನ್ಯತೆ ಪಡೆದ ನಿರ್ಧಾರಣಾ ಪ್ರೋಟೋಕಾಲ್ ಬೇಕಿತ್ತು ಎಂದು ತಿಳಿಯದೆ ಕೊಟ್ಟ ಇನ್‌ಪುಟ್ ಎಂದು ಪರಿಗಣಿಸುವ ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರ್ ಅಥವಾ ವಿಶ್ಲೇಷಕ, ಪ್ರಶ್ನಿಸಿದರೆ ಸಮರ್ಥಿಸಲಾಗದ ಸಂಖ್ಯೆಯಿಂದ ಒಂದು ಹೆಜ್ಜೆ ದೂರದಲ್ಲಿದ್ದಾರೆ.

## ಗಣಿತ

```
Standard TTO (state better than death):
  utility = time_in_full_health / time_in_impaired_state

Extended TTO (state worse than death):
  utility = -time_traded_for_death / (total_duration - time_traded_for_death)
```

`time_in_full_health` / `time_in_impaired_state` — ದುರ್ಬಲ ಸ್ಥಿತಿಯಲ್ಲಿನ `T` ವರ್ಷಗಳಿಗೆ ಸಮ ಎಂದು ನಿರ್ಣಯಿಸಲಾದ ಪೂರ್ಣ ಆರೋಗ್ಯದ ವರ್ಷಗಳು `X`. `time_traded_for_death` / `total_duration` — ಸಾವಿಗಿಂತ-ಕೆಟ್ಟ ರೂಪದಲ್ಲಿ, `T`-ವರ್ಷದ ಉಳಿದ ಜೀವನದಲ್ಲಿ ತಕ್ಷಣದ ಸಾವಿಗಾಗಿ ಉತ್ತರದಾತರು ವಿನಿಮಯ ಮಾಡಿಕೊಳ್ಳುವ ವರ್ಷಗಳು `a`; ಸಾವಿಗಿಂತ-ಕೆಟ್ಟ ಸ್ಥಿತಿಯಲ್ಲಿ `T` ವರ್ಷಗಳ ಬದಲು ಪೂರ್ಣ ಆರೋಗ್ಯದಲ್ಲಿ `T − a` ವರ್ಷಗಳ ನಂತರ ಸಾವನ್ನು ಅವರು ಆದ್ಯತೆ ನೀಡುತ್ತಾರೆ. ಫಲಿತಾಂಶ ಋಣಾತ್ಮಕ, ಸಾವು = 0 ಎಂದು ಲಂಗರು ಹಾಕಲಾಗಿದೆ.

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

**ಪ್ರಮಾಣಿತ**: ಉತ್ತರದಾತರು 10 ವರ್ಷ ದುರ್ಬಲ ಸ್ಥಿತಿಯಲ್ಲಿದ್ದಾರೆ ಮತ್ತು ಪೂರ್ಣ ಆರೋಗ್ಯದ 7 ವರ್ಷಗಳೊಂದಿಗೆ ಉದಾಸೀನರಾಗಿದ್ದಾರೆ: ಉಪಯುಕ್ತತೆ = 7 / 10 = **0.7**.

**ಸಾವಿಗಿಂತ ಕೆಟ್ಟದು**: 10-ವರ್ಷದ ಉಳಿದ ಜೀವನದಲ್ಲಿ, ಉತ್ತರದಾತರು ತಕ್ಷಣದ ಸಾವಿಗಾಗಿ 2 ವರ್ಷ ವಿನಿಮಯ ಮಾಡಿಕೊಳ್ಳುತ್ತಾರೆ — ಸಾವಿಗಿಂತ-ಕೆಟ್ಟ ಸ್ಥಿತಿಯಲ್ಲಿ 10 ವರ್ಷಗಳಿಗಿಂತ ಪೂರ್ಣ ಆರೋಗ್ಯದಲ್ಲಿ 8 ವರ್ಷಗಳ ನಂತರ ಸಾವನ್ನು ಆದ್ಯತೆ ನೀಡುತ್ತಾರೆ: ಉಪಯುಕ್ತತೆ = −2 / (10 − 2) = −2 / 8 = **−0.25**.

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್‌ನೊಂದಿಗಿನ ಸಂಬಂಧ

DevEx ಅಥವಾ ತೊಡಗಿಸಿಕೊಳ್ಳುವಿಕೆ ಸಮೀಕ್ಷೆಯು ಜನರನ್ನು ಪರಿಶೀಲಿಸದ 0–10 ಮಾಪಕದಲ್ಲಿ ಏನನ್ನಾದರೂ ರೇಟ್ ಮಾಡಲು ಕೇಳಿದಾಗ ಎದುರಿಸುವ ಅದೇ ಅಂಶ ಇಲ್ಲಿ ಉಲ್ಟಾ ಅನ್ವಯಿಸುತ್ತದೆ: "ಸುಮ್ಮನೆ ರೇಟ್ ಮಾಡಲು ಜನರನ್ನು ಕೇಳು" ಎಂಬುದು ತನ್ನಷ್ಟಕ್ಕೆ ಮಾನ್ಯತೆ ಪಡೆದ ನಿರ್ಧಾರಣಾ ವಿಧಾನವಲ್ಲ ಎಂಬ ಕಾರಣಕ್ಕೇ TTO ಅಸ್ತಿತ್ವದಲ್ಲಿದೆ. ಸ್ವ-ರೇಟಿಂಗ್ ಸಂಖ್ಯೆಯ ಮೇಲೆ ಸಂಯೋಜಿತ ಸೂಚ್ಯಂಕ — DevEx ಅಂಕ, ತೊಡಗಿಸಿಕೊಳ್ಳುವಿಕೆ ಸೂಚ್ಯಂಕ, ಬಳಲಿಕೆ ಮಾಪಕ — ನಿರ್ಮಿಸುವ ಮೊದಲು, ಅದನ್ನು ಯಾವುದು ಪಡೆಯಿತು ಮತ್ತು ಆ ವಿಧಾನ ಮಾನ್ಯತೆ ಪಡೆದಿತ್ತೇ ಎಂದು ಕೇಳಿ — ಆರೋಗ್ಯ ಅರ್ಥಶಾಸ್ತ್ರಜ್ಞರು QALYಗೆ ಹೋಗುವ ಮೊದಲು ಉಪಯುಕ್ತತಾ ತೂಕವನ್ನು ಕೇಳುವ ಅದೇ ಪ್ರಶ್ನೆ.

## ಎಡವಟ್ಟುಗಳು

- **ವೈಯಕ್ತಿಕ-ಮೌಲ್ಯ ಸಾಮಾನ್ಯೀಕರಣ**: TTO ಮೌಲ್ಯಗಳನ್ನು ಸಾರ್ವಜನಿಕರ (ಅಥವಾ ರೋಗಿಗಳ) *ಮಾದರಿ*ಯಿಂದ ಪಡೆಯಲಾಗುತ್ತದೆ, ಆರೈಕೆ ನಿರ್ಧರಿಸಲಾಗುತ್ತಿರುವ ವ್ಯಕ್ತಿಯಿಂದಲ್ಲ — ಒಬ್ಬ ಉತ್ತರದಾತನ TTO ಮೌಲ್ಯ ಸಾಮಾನ್ಯೀಕರಿಸುತ್ತದೆ ಎಂಬಂತೆ ಬಳಸುವುದು ಮಾದರಿ ದೋಷ.
- **ಸ್ಥಿತಿಗೆ ತಪ್ಪು ರೂಪ**: ಪ್ರಮಾಣಿತ TTO ಸೂತ್ರ ಸ್ಥಿತಿ ಸಾವಿಗಿಂತ ಸ್ಪಷ್ಟವಾಗಿ ಉತ್ತಮ ಎಂದು ಊಹಿಸುತ್ತದೆ; ಕೆಲವು ಉತ್ತರದಾತರು ಸಾವಿಗಿಂತ ಕೆಟ್ಟದೆಂದು ಪರಿಗಣಿಸುವ ಸ್ಥಿತಿಗೆ ವಿಸ್ತೃತ ರೂಪಕ್ಕೆ ಬದಲಾಯಿಸದೆ ಅನ್ವಯಿಸಿದರೆ, ಮೌನವಾಗಿ ತಪ್ಪಾದ (ಧನಾತ್ಮಕ) ಉಪಯುಕ್ತತೆ ಬರುತ್ತದೆ.
- **ಹೋಲಿಸಲಾಗದ ಅವಧಿಗಳು**: ಸಾವಿಗಿಂತ-ಕೆಟ್ಟ ಹೋಲಿಕೆಗೆ ಬೇರೆ ಬೇರೆ ಉಳಿದ-ಜೀವನ ಅವಧಿಗಳನ್ನು `T` ಬಳಸಿ ಪಡೆದ TTO ಮೌಲ್ಯಗಳು, ಅಧ್ಯಯನ ವಿನ್ಯಾಸ `T` ಅನ್ನು ಸ್ಥಿರವಾಗಿರಿಸಿತ್ತೇ ಎಂದು ಪರಿಶೀಲಿಸದೆ ನೇರವಾಗಿ ಹೋಲಿಸಲಾಗದು.
