# ಚಿಕಿತ್ಸೆ ನೀಡಬೇಕಾದ ಸಂಖ್ಯೆ (NNT)

NNT ಎಂದರೆ ನಿಗದಿತ ಕಾಲಾವಧಿಯಲ್ಲಿ **ಒಬ್ಬ** ಹೆಚ್ಚುವರಿ ರೋಗಿ ಲಾಭ ಪಡೆಯಲು ಮಧ್ಯಸ್ಥಿಕೆ ಪಡೆಯಬೇಕಾದ ರೋಗಿಗಳ ಸಂಖ್ಯೆ. ಇದು ದಾರಿತಪ್ಪಿಸುವ ಶೇಕಡಾ ಅಪಾಯ ಇಳಿಕೆಗಳನ್ನು ಯಾರೂ ತರ್ಕಿಸಬಹುದಾದ ಲಾಭ-ಪ್ರತಿ-ಪ್ರಯತ್ನ ಘಟಕಗಳಾಗಿ ಪರಿವರ್ತಿಸುತ್ತದೆ.

## ಇದು ಏಕೆ ಮುಖ್ಯ

"ಹೃದಯಾಘಾತಗಳನ್ನು 25% ಕಡಿಮೆ ಮಾಡುತ್ತದೆ!" ನಿರ್ಣಾಯಕವಾಗಿ ಕೇಳಿಸುತ್ತದೆ. ಮೂಲ ಅಪಾಯ 5 ವರ್ಷಗಳಲ್ಲಿ 4% ಆಗಿದ್ದರೆ, ಸಂಪೂರ್ಣ ಇಳಿಕೆ 1 ಶೇಕಡಾ-ಅಂಕ, ಆದ್ದರಿಂದ **5 ವರ್ಷ ಔಷಧ ತೆಗೆದುಕೊಳ್ಳುವ 100 ಜನರಲ್ಲಿ 1 ಜನರಿಗೆ ಮಾತ್ರ ಲಾಭ** — ಮತ್ತು ಎಲ್ಲ 100 ಜನರೂ ವೆಚ್ಚ ಮತ್ತು ಅಡ್ಡ ಪರಿಣಾಮಗಳನ್ನು ಭರಿಸುತ್ತಾರೆ. NNT ಸಾಪೇಕ್ಷ-ಅಪಾಯ ಮಾರುಕಟ್ಟೆಗೆ ಪ್ರತಿವಿಷ, ಆದ್ದರಿಂದಲೇ ಸಾಕ್ಷ್ಯಾಧಾರಿತ ವೈದ್ಯಕೀಯ ಅದರೊಂದಿಗೆ ಮುನ್ನಡೆಸುತ್ತದೆ. ಪ್ರಾಥಮಿಕ ತಡೆಗಟ್ಟುವಿಕೆಗೆ ಸ್ಟ್ಯಾಟಿನ್‌ಗಳು: ತಪ್ಪಿಸಿದ ಪ್ರತಿ ಹೃದಯಾಘಾತಕ್ಕೆ 5 ವರ್ಷಗಳಲ್ಲಿ NNT ≈ 50–100. ಅದರ ಪ್ರತಿಬಿಂಬ **NNH** (ಹಾನಿ ಮಾಡುವ ಸಂಖ್ಯೆ), ಪ್ರತಿ ಹಾನಿಗೊಳಗಾದ ವ್ಯಕ್ತಿಗೆ ಎಷ್ಟು ಜನರಿಗೆ ಚಿಕಿತ್ಸೆ ನೀಡಲಾಗಿದೆ ಎಂದು ಎಣಿಸುತ್ತದೆ.

## ಗಣಿತ

```
ARR = control event rate − treatment event rate   (absolute risk reduction)
NNT = 1 / ARR

NNH = 1 / (harm rate_treatment − harm rate_control)

Economic bridge:
cost per event prevented = NNT × cost per treatment course
```

ಯಾವಾಗಲೂ ಕಾಲಾವಧಿ ಮತ್ತು ಮೂಲ ಜನಸಂಖ್ಯೆಯನ್ನು ಹೇಳಿ — ಎರಡೂ ಇಲ್ಲದೆ NNTಗೆ ಅರ್ಥವಿಲ್ಲ.

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

ಆಸ್ಪತ್ರೆಯ ಬೀಳುವಿಕೆ-ಮುನ್ಸೂಚನೆ ವ್ಯವಸ್ಥೆ ಹೆಚ್ಚು-ಅಪಾಯದ ರೋಗಿಗಳನ್ನು ಮಧ್ಯಸ್ಥಿಕೆಗೆ ಗುರುತಿಸುತ್ತದೆ (ಹಾಸಿಗೆ ಸಂವೇದಕಗಳು, ವಿಮರ್ಶೆ, ಮೇಲ್ವಿಚಾರಣೆ). ಪ್ರಯೋಗ: ಗಾಯದೊಂದಿಗೆ ಬೀಳುವಿಕೆಗಳು ದಾಖಲಾತಿಗಳ 3.2%ರಿಂದ 2.4%ಕ್ಕೆ ಇಳಿಯುತ್ತವೆ.

```
ARR = 0.8 percentage points → NNT = 1/0.008 = 125
   (125 patients must get the intervention bundle to prevent 1 injurious fall)

Intervention cost ≈ £40/patient → cost per fall prevented = 125 × 40 = £5,000
Cost of an injurious inpatient fall (extra stay, imaging, litigation) ≈ £12,000
Net: prevention pays ~2.4:1 — and the QALY gain is on top.
```

NNT ಹಕ್ಕನ್ನು ಹೇಗೆ ಪ್ರಾಮಾಣಿಕವಾಗಿಡುತ್ತದೆ ಎಂಬುದನ್ನು ಗಮನಿಸಿ: "ಬೀಳುವಿಕೆಗಳನ್ನು 25% ಕಡಿಮೆ ಮಾಡುತ್ತದೆ" ಮತ್ತು "ಚಿಕಿತ್ಸೆ ನೀಡಿದ ಪ್ರತಿ 125 ರೋಗಿಗಳಿಗೆ ಒಂದು ಬೀಳುವಿಕೆ ತಡೆಯಿರಿ" ಒಂದೇ ಫಲಿತಾಂಶ, ಬೇರೆ ರೀತಿಯಲ್ಲಿ ಮನವರಿಕೆ ಮಾಡುವುದು.

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್‌ನೊಂದಿಗಿನ ಸಂಬಂಧ

ಕೆಲವನ್ನು ಹಿಡಿಯಲು ಅನೇಕ ವಸ್ತುಗಳ ಮೇಲೆ ಕಾರ್ಯನಿರ್ವಹಿಸುವ ಯಾವುದೇ ದ್ವಾರ ಅಥವಾ ಪರಿಶೀಲನೆಗೆ NNT ಸರಿಯಾದ ಘಟಕ: **"ಉತ್ಪಾದನೆಗೆ ಹೋಗುವ ಒಂದು ದೋಷವನ್ನು ಹಿಡಿಯಲು AI ವಿಮರ್ಶೆ ದ್ವಾರದ ಮೂಲಕ ಹಾದುಹೋಗಬೇಕಾದ PRಗಳ ಸಂಖ್ಯೆ."** ದ್ವಾರ ಪ್ರತಿ ನಿಜ ಹಿಡಿತಕ್ಕೆ 400 PRಗಳನ್ನು ವಿಮರ್ಶಿಸಿದರೆ (NNT = 400) ಪ್ರತಿಯೊಂದಕ್ಕೂ 4 ನಿಮಿಷಗಳ ಡೆವಲಪರ್ ಗಮನದಲ್ಲಿ, ಒಂದು ಹಿಡಿತಕ್ಕೆ ~27 ಡೆವಲಪರ್-ಗಂಟೆಗಳು ವೆಚ್ಚ — ಈಗ ಅದನ್ನು ಅದು ತಡೆಯುವ ಘಟನೆ ವೆಚ್ಚಕ್ಕೆ ಹೋಲಿಸಿ. NNH ಸುಳ್ಳು ಧನಾತ್ಮಕಗಳಿಗೆ ಹೊಂದುತ್ತದೆ: *ಸುಳ್ಳು* ಫ್ಲ್ಯಾಗ್‌ಗೆ ಎಷ್ಟು PRಗಳು, ಮತ್ತು ಪ್ರತಿಯೊಂದು ಗಮನ ಮತ್ತು ನಂಬಿಕೆಯಲ್ಲಿ ಎಷ್ಟು ವೆಚ್ಚ? ಸ್ಕ್ರೀನಿಂಗ್-ಶೈಲಿಯ ಸಾಧನಗಳು (ಲಿಂಟರ್‌ಗಳು, ಭದ್ರತಾ ಸ್ಕ್ಯಾನರ್‌ಗಳು, ಅಸಂಗತಿ ಪತ್ತೆ) NNT/NNH ಅಂಕಗಣಿತದೊಂದಿಗೆ ಬರಬೇಕು — ಕಡಿಮೆ ಹರಡುವಿಕೆ ಈ ಸಂಖ್ಯೆಗಳನ್ನು ಏಕೆ ಕ್ರೂರಗೊಳಿಸುತ್ತದೆ ಎಂಬುದಕ್ಕೆ [ಸ್ಕ್ರೀನಿಂಗ್ ಅರ್ಥಶಾಸ್ತ್ರ](../ಸ್ಕ್ರೀನಿಂಗ್-ಅರ್ಥಶಾಸ್ತ್ರ/) ನೋಡಿ. [ಸ್ಕ್ರೀನ್ ಮಾಡಬೇಕಾದ ಸಂಖ್ಯೆ](../ಸ್ಕ್ರೀನ್-ಮಾಡಬೇಕಾದ-ಸಂಖ್ಯೆ/) ಒಂದು ಹಂತ ಮೇಲಿನ ಸಮಾನ ಅಂಕಿ, ಚಿಕಿತ್ಸೆ ಮಾತ್ರವಲ್ಲ, ಇಡೀ ಸ್ಕ್ರೀನ್-ನಂತರ-ಚಿಕಿತ್ಸೆ ಕಾರ್ಯಕ್ರಮಕ್ಕೆ.

## ಎಡವಟ್ಟುಗಳು

- **ಕಾಲಾವಧಿ ಇಲ್ಲ**: "NNT = 50" ಏನನ್ನೂ ಅರ್ಥೈಸುವುದಿಲ್ಲ; "5 ವರ್ಷಗಳಲ್ಲಿ NNT = 50" ಒಂದು ಹಕ್ಕು.
- **ಮೂಲ-ಅಪಾಯ ಕಸಿ**: ಹೆಚ್ಚು-ಅಪಾಯದ ಪ್ರಯೋಗ ಜನಸಂಖ್ಯೆಯಲ್ಲಿ ಲೆಕ್ಕ ಹಾಕಿದ NNT ಕಡಿಮೆ-ಅಪಾಯದ ನಿಯೋಜನೆ ಜನಸಂಖ್ಯೆಯಲ್ಲಿ ಕುಸಿಯುತ್ತದೆ.
- **NNH ನಿರ್ಲಕ್ಷ್ಯ** — NNT 400 ಮತ್ತು NNH 3 ಇರುವ ದ್ವಾರ ಸುರಕ್ಷತಾ ವ್ಯವಸ್ಥೆಯಲ್ಲ, ತೊಂದರೆ ಉತ್ಪಾದಕ.
