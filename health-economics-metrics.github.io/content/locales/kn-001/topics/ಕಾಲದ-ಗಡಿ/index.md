# ಕಾಲದ ಗಡಿ

ಕಾಲದ ಗಡಿ (ಟೈಮ್ ಹಾರಿಜಾನ್) ಎಂದರೆ ವಿಶ್ಲೇಷಣೆಯು ವೆಚ್ಚ ಮತ್ತು ಪರಿಣಾಮಗಳನ್ನು ಲೆಕ್ಕಿಸುವ ಅವಧಿ. ಹೋಲಿಸಲಾಗುತ್ತಿರುವ ಆಯ್ಕೆಗಳ ನಡುವಿನ ಎಲ್ಲ ಅರ್ಥಪೂರ್ಣ ವ್ಯತ್ಯಾಸಗಳನ್ನು ಸೆರೆಹಿಡಿಯುವಷ್ಟು ಅದು ಉದ್ದವಾಗಿರಬೇಕು.

## ಇದು ಏಕೆ ಮುಖ್ಯ

ಚಿಕ್ಕ ಗಡಿಯನ್ನು ಆರಿಸಿದರೆ ತಡವಾದ ಲಾಭಗಳನ್ನು (ತಡೆಗಟ್ಟುವಿಕೆ) ಮತ್ತು ತಡವಾದ ವೆಚ್ಚಗಳನ್ನು (ನಿರ್ವಹಣೆ) ತಪ್ಪಿಸಿಕೊಳ್ಳುತ್ತೀರಿ. ಅತಿ ಉದ್ದದ ಗಡಿಯನ್ನು ಆರಿಸಿದರೆ ಎಲ್ಲವೂ ಅನಿಶ್ಚಿತತೆಯಲ್ಲಿ ಮುಳುಗುತ್ತದೆ. ಆರೋಗ್ಯ ತಂತ್ರಜ್ಞಾನ ಮೌಲ್ಯಮಾಪನವು ಮರಣ ಪರಿಣಾಮಗಳಿರುವ ಚಿಕಿತ್ಸೆಗಳಿಗೆ ಸಾಮಾನ್ಯವಾಗಿ **ಜೀವಿತಾವಧಿ** ಗಡಿಯನ್ನು ಬಳಸುತ್ತದೆ; [ಬಜೆಟ್ ಪರಿಣಾಮ ವಿಶ್ಲೇಷಣೆ](../ಬಜೆಟ್-ಪರಿಣಾಮ-ವಿಶ್ಲೇಷಣೆ/) ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಚಿಕ್ಕ **1–5 ವರ್ಷದ** ಗಡಿಯನ್ನು ಬಳಸುತ್ತದೆ, ಏಕೆಂದರೆ ಅದರ ಪ್ರಶ್ನೆ ಮೌಲ್ಯವಲ್ಲ, ಭರಿಸಬಲ್ಲ ಸಾಮರ್ಥ್ಯ. ಗಡಿಯು ಘೋಷಿತ ಮಾದರಿ ಆಯ್ಕೆ, ಮತ್ತು ಹೊಂದಿಕೆಯಾಗದ ಗಡಿಗಳು ಹೋಲಿಕೆಯನ್ನು ತಿರುಚುವ ಶ್ರೇಷ್ಠ ವಿಧಾನ.

## ಗಣಿತ

ಗಡಿಯು ಯಾವುದೇ ಮೌಲ್ಯಮಾಪನದಲ್ಲಿನ ಸಂಕಲನದ ಮೇಲಿನ ಮಿತಿ:

```
Net present value = Σ (t = 0 … T) [ (Benefits_t − Costs_t) / (1 + r)^t ]

T = time horizon (years)
r = discount rate (see discounting-and-time-preference.md)
```

ಫಲಿತಾಂಶಗಳನ್ನು ಗಡಿಯನ್ನು ಹೇಳಿ ವರದಿ ಮಾಡಬೇಕು, ಮತ್ತು ಆದರ್ಶವಾಗಿ ಹಲವು ಗಡಿಗಳಲ್ಲಿ ತೋರಿಸಬೇಕು.

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

ಒಂದು ಎಲೆಕ್ಟ್ರಾನಿಕ್ ಔಷಧ ಚೀಟಿ ವ್ಯವಸ್ಥೆ ಅಳವಡಿಸಲು £2 ಮಿಲಿಯನ್ ಮತ್ತು ನಡೆಸಲು ವರ್ಷಕ್ಕೆ £200,000 ವೆಚ್ಚವಾಗುತ್ತದೆ. ಇದು ವರ್ಷಕ್ಕೆ £600,000 ಮೌಲ್ಯದ ಔಷಧ ತಪ್ಪುಗಳನ್ನು (ತಪ್ಪಿಸಲಾದ ಹಾನಿಯ ಚಿಕಿತ್ಸಾ ವೆಚ್ಚ) ತಡೆಯುತ್ತದೆ.

ಗಡಿಯ ಪ್ರಕಾರ ನಿವ್ವಳ ಲಾಭ (ಸ್ಪಷ್ಟತೆಗಾಗಿ ರಿಯಾಯಿತಿ ಇಲ್ಲದೆ):

```
Horizon 1 year:  −2,000,000 − 200,000 + 600,000  = −£1,600,000
Horizon 3 years: −2,000,000 + 3 × 400,000        = −£800,000
Horizon 5 years: −2,000,000 + 5 × 400,000        =  £0
Horizon 10 years:−2,000,000 + 10 × 400,000       = +£2,000,000
```

ವ್ಯವಸ್ಥೆಯು 5 ವರ್ಷಕ್ಕಿಂತ ಕಡಿಮೆಯ ಯಾವುದೇ ಗಡಿಯಲ್ಲಿ "ವಿಫಲ"ವಾಗುತ್ತದೆ ಮತ್ತು 10ರಲ್ಲಿ "ಯಶಸ್ವಿ"ಯಾಗುತ್ತದೆ. ಎರಡೂ ನಿಜವಾದ ಉತ್ತರವಲ್ಲ; ಪ್ರಾಮಾಣಿಕ ವರದಿಯು ಸಮತೋಲನ ಬಿಂದುವನ್ನು ಹೇಳುತ್ತದೆ ಮತ್ತು ವ್ಯವಸ್ಥೆಯ ಜೀವಿತಾವಧಿಯಿಂದ (ಬದಲಿಸುವ ಮೊದಲು ಎಷ್ಟು ಕಾಲ?) ಗಡಿಯನ್ನು ಸಮರ್ಥಿಸುತ್ತದೆ.

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್‌ನೊಂದಿಗಿನ ಸಂಬಂಧ

- **ಒಂದು ಸ್ಪ್ರಿಂಟ್‌ನಲ್ಲಿ ಅಳೆದ ಟೂಲ್ ಮೌಲ್ಯಮಾಪನಗಳು** ಕಲಿಕೆಯ ವಕ್ರರೇಖೆಯ ಕುಸಿತ (ವೆಚ್ಚಗಳು ಮುಂಗಡ) ಮತ್ತು ದೀರ್ಘಕಾಲೀನ ನಿರ್ವಹಣೆ (ವೆಚ್ಚಗಳು ಹಿಂಗಡೆ) ಎರಡನ್ನೂ ವ್ಯವಸ್ಥಿತವಾಗಿ ತಪ್ಪಿಸಿಕೊಳ್ಳುತ್ತವೆ. 2ನೇ ವಾರದಲ್ಲಿ ಅಳೆದ AI ಕೋಡಿಂಗ್-ಸಹಾಯಕ ಪೈಲಟ್‌ಗಳು ಸ್ಥಿರ ಸ್ಥಿತಿಯನ್ನಲ್ಲ, ನವೀನತೆಯ ಗರಿಷ್ಠವನ್ನು ಸೆರೆಹಿಡಿಯುತ್ತವೆ.
- **ಒಪ್ಪಂದದ ಅವಧಿ ≠ ಲಾಭದ ಗಡಿ.** 1-ವರ್ಷದ SaaS ಒಪ್ಪಂದವನ್ನು ನವೀಕರಣವನ್ನು ವಾಸ್ತವಿಕವಾಗಿ ನಿರೀಕ್ಷಿಸುವುದಾದರೆ 5 ವರ್ಷಗಳ ಮೇಲೆ ಮೌಲ್ಯಮಾಪನ ಮಾಡಬಹುದು — ಆದರೆ ಅದನ್ನು ಹೇಳಿ.
- **ಹಳೆಯ ವ್ಯವಸ್ಥೆ ಬದಲಿ ಪ್ರಕರಣಗಳು** ಹಳೆಯ ವ್ಯವಸ್ಥೆಯ ನಂಬಲರ್ಹ ಜೀವಿತಾಂತ್ಯದವರೆಗೆ ನಡೆಯಬೇಕು, ಯಾವುದೋ ಇಚ್ಛಾನುಸಾರದ ದುಂಡು ಸಂಖ್ಯೆಯವರೆಗೆ ಅಲ್ಲ.

## ಎಡವಟ್ಟುಗಳು

- **ಗಡಿ ಶಾಪಿಂಗ್**: ನಿಮ್ಮ ಆಯ್ಕೆಯನ್ನು ಗೆಲ್ಲಿಸುವ ಗಡಿಯನ್ನು ಆರಿಸುವುದು. ಫಲಿತಾಂಶ ಲೆಕ್ಕಿಸುವ ಮೊದಲು ಗಡಿಯನ್ನು ಪೂರ್ವ-ನೋಂದಾಯಿಸಿ.
- ಒಂದೇ ಹೋಲಿಕೆಯಲ್ಲಿ **ವಿಭಿನ್ನ ಆಯ್ಕೆಗಳಿಗೆ ವಿಭಿನ್ನ ಗಡಿಗಳು**.
- **ರಿಯಾಯಿತಿ ಅಥವಾ ಅನಿಶ್ಚಿತತೆ ವಿಶ್ಲೇಷಣೆ ಇಲ್ಲದ ಜೀವಿತಾವಧಿ ಗಡಿಗಳು** — 30ನೇ ವರ್ಷದ ಲಾಭಗಳನ್ನು ಮೌಲ್ಯ ಹಾಗೆಯೇ ತೆಗೆದುಕೊಂಡರೆ ಅದು ಕಾಲ್ಪನಿಕ. ಉದ್ದದ ಗಡಿಗಳನ್ನು [ಸಂವೇದನಾ ವಿಶ್ಲೇಷಣೆ](../ಸಂವೇದನಾ-ವಿಶ್ಲೇಷಣೆ/)ಯೊಂದಿಗೆ ಜೋಡಿಸಿ.
