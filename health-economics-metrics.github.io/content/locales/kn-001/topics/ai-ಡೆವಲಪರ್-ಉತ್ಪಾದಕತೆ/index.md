# AI ಡೆವಲಪರ್ ಉತ್ಪಾದಕತೆ

AI ಕೋಡಿಂಗ್ ನೆರವು ಎಂಜಿನಿಯರಿಂಗ್ ಉತ್ಪಾದನೆಗೆ ನಿಜವಾಗಿ ಏನು ಮಾಡುತ್ತದೆ ಎಂಬುದರ ಮಾಪನಗಳು: ಸಲಹೆ ಸ್ವೀಕಾರ ದರಗಳು, ನಿಯಂತ್ರಿತ-ಅಧ್ಯಯನದ ವೇಗವರ್ಧನೆ, PR ಥ್ರೂಪುಟ್ ಮತ್ತು ಕೋಡ್ ಉಳಿಕೆ. ಸಾಕ್ಷ್ಯದ ನೆಲೆ ನಿಜವಾಗಿಯೂ ವಿರೋಧಾತ್ಮಕ — ಇದು ಆರೋಗ್ಯ ಅರ್ಥಶಾಸ್ತ್ರ ನಿಭಾಯಿಸಲೆಂದೇ ರೂಪುಗೊಂಡ ಪರಿಣಾಮಕಾರಿತ್ವ-vs-ಪರಿಣಾಮಶೀಲತೆ ವ್ಯತ್ಯಾಸಕ್ಕೆ ಅತ್ಯುತ್ತಮ ಪ್ರಕರಣ ಅಧ್ಯಯನ.

## ಇದು ಏಕೆ ಮುಖ್ಯ

ಅತಿ ಹೆಚ್ಚು ಉಲ್ಲೇಖಿತ ಎರಡು ನಿಯಂತ್ರಿತ ಅಧ್ಯಯನಗಳು ವಿರುದ್ಧ ದಿಕ್ಕುಗಳನ್ನು ತೋರಿಸುತ್ತವೆ:

- **Peng ಮತ್ತು ಇತರರು 2023 (GitHub Copilot RCT)**: ಡೆವಲಪರ್‌ಗಳು Copilot ಜೊತೆ ಹೊಸ-ಯೋಜನೆಯ HTTP-ಸರ್ವರ್ ಕಾರ್ಯವನ್ನು **55.8% ವೇಗವಾಗಿ** ಪೂರ್ಣಗೊಳಿಸಿದರು (1ಗಂ11ನಿ vs 2ಗಂ41ನಿ, n=95).
- **METR 2025 RCT**: *ತಮ್ಮದೇ ಪ್ರೌಢ ರೆಪೊಸಿಟರಿಗಳಲ್ಲಿ* ಕೆಲಸ ಮಾಡುವ ಅನುಭವಿ ಮುಕ್ತ-ಮೂಲ ಡೆವಲಪರ್‌ಗಳು 2025ರ ಆರಂಭದ AI ಸಾಧನಗಳೊಂದಿಗೆ **19% ನಿಧಾನ** (16 ಡೆವಲಪರ್‌ಗಳು, 246 ಕಾರ್ಯಗಳು) — ಆದರೆ ತಾವು 20% ವೇಗವಾಗಿದ್ದೇವೆ ಎಂದು *ನಂಬಿದ್ದರು*.

ಎರಡೂ ಉತ್ತಮ ಅಧ್ಯಯನಗಳು. ವಿರೋಧಾಭಾಸವೇ ಸಂಶೋಧನೆ: ಹೊಸ-ಕಾರ್ಯದ ಪರಿಣಾಮಕಾರಿತ್ವ ಪ್ರೌಢ-ಕೋಡ್‌ಬೇಸ್ ಪರಿಣಾಮಶೀಲತೆಗೆ ವರ್ಗಾವಣೆಯಾಗುವುದಿಲ್ಲ, ಮತ್ತು *ಗ್ರಹಿಸಿದ* ಲಾಭ ಅಳೆದ ಲಾಭಕ್ಕೆ ಬದಲಿಯಾಗದು. ವೈದ್ಯಕೀಯದಲ್ಲಿ ಎರಡೂ ವಿದ್ಯಮಾನಗಳಿಗೆ ಹೆಸರುಗಳಿವೆ (ವಿವರಣಾತ್ಮಕ vs ಪ್ರಾಯೋಗಿಕ ಪ್ರಯೋಗಗಳು; ಪ್ಲಸೀಬೊ ಸಮಸ್ಯೆ) ಮತ್ತು ಅವನ್ನು ನಿಭಾಯಿಸುವ ವ್ಯವಸ್ಥೆ ಇದೆ.

## ಗಣಿತ

```
Acceptance rate  = accepted suggestions / shown suggestions
                   (GitHub telemetry ~30% avg; varies: SQL 45%, Python 35%, JS 28%)
Retention rate   = AI code surviving to merge / accepted AI code (~88% reported)
Speedup          = (t_control − t_AI) / t_control  (from controlled comparison ONLY)
Throughput delta = Δ merged PRs/dev/week (GitHub/Accenture field data: +8.7%)

Value model     = devs × time saved × loaded rate × utilization factor
                  — every term needs local measurement; see the tornado in
                  sensitivity-analysis.md, where time-saved dominates all
                  other parameters combined
```

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

500 ಡೆವಲಪರ್‌ಗಳ ಸಂಸ್ಥೆ ಸರಿಯಾದ ನಿಯಂತ್ರಣದೊಂದಿಗೆ (ಹೊಂದಿಸಿದ ತಂಡಗಳು, 3 ತಿಂಗಳು, ಪೂರ್ವ-ನೋಂದಾಯಿತ ಮಾಪನಗಳು) ಸಹಾಯಕವನ್ನು ಪ್ರಾಯೋಗಿಕವಾಗಿ ಬಳಸುತ್ತದೆ:

```
Pilot result: PR cycle time −18%; merged PRs +6%; CFR unchanged;
              self-reported time saved 45 min/day; measured task-level ≈ 15 min/day

Value the MEASURED number: 500 × 0.25h × 220d × £60 × 0.6 utilization
                          ≈ £990,000/year capacity (non-cash-releasing)
Cost: 500 × £39/mo × 12 ≈ £234,000/year
Net capacity ratio ≈ 4:1 — fundable, at one-third the self-reported claim.
```

ಗ್ರಹಿಸಿದ ಮತ್ತು ಅಳೆದ ನಡುವಿನ 3× ಅಂತರ ವಾಸ್ತವದಲ್ಲಿ ಕೆಲಸ ಮಾಡುತ್ತಿರುವ METR ಸಂಶೋಧನೆ; ಸ್ವಯಂ-ವರದಿಯ ಮೇಲೆ ಬಜೆಟ್ ಮಾಡಿದ್ದರೆ ಲಾಭದ ಸಾಲು ಮೂರು ಪಟ್ಟಾಗುತ್ತಿತ್ತು.

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್‌ನೊಂದಿಗಿನ ಸಂಬಂಧ

AI ಸಾಧನಗಳನ್ನು ಮೌಲ್ಯಮಾಪನ ಮಾಡುವ ಯಾರಿಗೂ ಆರೋಗ್ಯ ಅರ್ಥಶಾಸ್ತ್ರದ ಆಮದುಗಳು: **ಪ್ರಾಯೋಗಿಕ ಪ್ರಯೋಗಗಳನ್ನು** ನಡೆಸಿ (ನಿಮ್ಮ ಕೋಡ್‌ಬೇಸ್, ನಿಮ್ಮ ಎಂಜಿನಿಯರ್‌ಗಳು, ನಿಜವಾದ ಟಿಕೆಟ್‌ಗಳು — ಮಾರಾಟಗಾರರ ಡೆಮೊ ಕಾರ್ಯಗಳಲ್ಲ); **ಸ್ವೀಕಾರ ದರವನ್ನು ಬದಲಿ ಮಾಪನವಾಗಿ ಪರಿಗಣಿಸಿ, ಫಲಿತಾಂಶವಲ್ಲ** (ಇದು ಡೆವಲಪರ್ ದೃಷ್ಟಿಯಿಂದ ಸಲಹೆಗಳ [PPV](../ಕ್ಲಿನಿಕಲ್-ai-ಮೌಲ್ಯಮಾಪನ/) — ಹೆಚ್ಚು ಸ್ವೀಕಾರ ಆದರೆ ಕಡಿಮೆ ಉಳಿಕೆ ಎಂದರೆ ಅತಿರೋಗನಿರ್ಣಯ); ಪ್ರತಿ ಥ್ರೂಪುಟ್ ಲಾಭವನ್ನು **ಸ್ಥಿರತೆ ಪರಿಶೀಲನೆ**ಯೊಂದಿಗೆ ಜೋಡಿಸಿ (DORA 2025: AI ಥ್ರೂಪುಟ್ ಹೆಚ್ಚಿಸುತ್ತದೆ, ಸ್ಥಿರತೆಗೆ ಹಾನಿ ಮಾಡುತ್ತದೆ — ಅಡ್ಡಪರಿಣಾಮಗಳಿರುವ ಮಧ್ಯಸ್ಥಿಕೆಗೆ ನಿವ್ವಳ-ಲಾಭ ವಿಶ್ಲೇಷಣೆ ಬೇಕು, [DORA ಮಾಪನಗಳು](../dora-ಮಾಪನಗಳು/) ಪ್ರಕಾರ); ಮತ್ತು ಲಾಭವನ್ನು ಪ್ರಾಮಾಣಿಕವಾಗಿ ಸಾಮರ್ಥ್ಯ ಎಂದು ವರ್ಗೀಕರಿಸಿ ([ನಗದು-ಬಿಡುಗಡೆ vs ನಗದು-ರಹಿತ](../ನಗದು-ಬಿಡುಗಡೆ-vs-ನಗದು-ರಹಿತ-ಉಳಿತಾಯ/)).

## ಎಡವಟ್ಟುಗಳು

- **ಮಾರಾಟಗಾರ-ಅಧ್ಯಯನ ಕಸಿ**: ಹೊಸ-ಯೋಜನೆಯ RCT ಸಂಖ್ಯೆಗಳನ್ನು ಹಳೆಯ-ಕೋಡ್‌ಬೇಸ್ ಕೆಲಸಕ್ಕೆ ಅನ್ವಯಿಸುವುದು — METR ಅಧ್ಯಯನ ಬಯಲುಮಾಡಿದ ಅದೇ ತಪ್ಪು.
- **ಸ್ವಯಂ-ವರದಿಯೇ ಮಾಪನ**: 20 ಶೇಕಡಾ-ಅಂಕಗಳ ಗ್ರಹಿಕೆ ಅಂತರ ಈ ಸಾಹಿತ್ಯದಲ್ಲಿ ತಿಳಿದ ಅತಿ ದೊಡ್ಡ ಪಕ್ಷಪಾತ.
- **ಚಟುವಟಿಕೆ ಉಬ್ಬರ**: ಹೆಚ್ಚು PRಗಳು ಮತ್ತು ಹೆಚ್ಚು ಕೋಡ್ ಚಟುವಟಿಕೆ, ಫಲಿತಾಂಶಗಳಲ್ಲ ([SPACE](../space-ಮತ್ತು-devex/)); ಮರುಕೆಲಸ ಮತ್ತು CFR ಜೊತೆ ಜೋಡಿಸಿ.
- **ಕಲಿಕೆ ವಕ್ರರೇಖೆಯ ನಿರ್ಲಕ್ಷ್ಯ**: 2ನೇ ವಾರದ ಮಾಪನಗಳು ಹೊಸತನದ ಪರಿಣಾಮಗಳನ್ನು (ಯಾವ ದಿಕ್ಕಿನಲ್ಲೂ) ಹಿಡಿಯುತ್ತವೆ; ಸ್ಥಿರ ಸ್ಥಿತಿಯಲ್ಲಿ ಅಳೆಯಿರಿ ([ಕಾಲದ ಗಡಿ](../ಕಾಲದ-ಗಡಿ/)).
