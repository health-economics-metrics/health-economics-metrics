# ការបែងចែកថ្លៃដើមត្រឹមសេនពិតប្រាកដ

ការបំបែកចំនួនប្រាក់សរុប — ជំនួយធនចែករំលែក វិក្កយបត្រហេដ្ឋារចនាសម្ព័ន្ធ តួលេខផលប៉ះពាល់ថវិកា — ទៅអ្នកទទួលច្រើនដោយនព្វន្ធភាគរយអយុត្តិធម៌ ជាប្រចាំបង្កើតផ្នែកដែលមិនបូកត្រឡប់ទៅផលបូកដើមទេ។ ការបែងចែកត្រឹមសេនពិតប្រាកដ គឺជាការជួសជុល៖ វិធីសាស្ត្រចំនួនគត់/ទសភាគ ធ្វើការក្នុងឯកតារូបិយប័ណ្ណតូច (សេន) ដែលធានាថាផ្នែកបូកស្មើ *យ៉ាងពិតប្រាកដ* នឹងទាំងមូល មិនថាវាបែងចែកមិនស្មើប៉ុណ្ណាក៏ដោយ។ វិស្វករកម្មវិធីណាដែលត្រូវផ្សះផ្សាផលបូកបំបែកទៅសេន — បៀវត្សរ៍ ការចែកជំនួយ ការគិតថ្លៃសេវាចែករំលែក — ត្រូវការគំរូនេះ មិនមែនភាគរយចំណុចអណ្តែតទេ។

## ហេតុអ្វីបានជាសំខាន់

នេះគឺជាគំរូមូលដ្ឋានមានឈ្មោះក្នុងវិស្វកម្មកម្មវិធីសហគ្រាស៖ *Patterns of Enterprise Application Architecture* (2002) របស់ Martin Fowler ចងក្រង `Money` និង `Allocate` ពិតជាព្រោះ "បំបែក $100 បីផ្លូវ" គឺជាបញ្ហាដែលកូដអយុត្តិធម៌ធ្វើខុសជាប្រចាំ ហើយធ្វើខុសដោយស្ងាត់ — កំហុសលេចឡើងតែនៅពេលនរណាម្នាក់ផ្សះផ្សាសៀវភៅ ហើយរកឃើញផ្នែកខ្វះ (ឬលើស) មួយសេនពីផលបូក។ ក្នុងការងារសេដ្ឋកិច្ចសុខាភិបាល និងហិរញ្ញវត្ថុ NHS នេះមិនមែនជាការសិក្សាទេ៖ ផលបូកផលប៉ះពាល់ថវិកាត្រូវបានបំបែកឆ្លងទីតាំង ឆ្នាំ ឬនាយកដ្ឋាន; ថ្លៃហេដ្ឋារចនាសម្ព័ន្ធចែករំលែក និងអាជ្ញាប័ណ្ណត្រូវបានបែងចែកឆ្លងនាយកដ្ឋានតាមចំនួនបុគ្គលិក ឬចំណែកសកម្មភាព។ រាល់ការបំបែកទាំងនោះត្រូវតែផ្សះផ្សាយ៉ាងត្រឹមត្រូវ ព្រោះនាយកហិរញ្ញវត្ថុដែលត្រូវបានប្រគល់ផ្នែកដែលមិនបូកស្មើផលបូកឈប់ទុកចិត្តគំរូទាំងមូល។

## គណិតវិទ្យា

```
Naive (broken) method:
  part_i = round(total × share_i / Σ shares)     — rounds each part independently

Exact method (largest remainder / "largest remainder allocation"):
  1. base_i = floor(total_minor_units × share_i / Σ shares)   — whole minor units (cents) only
  2. remainder = total_minor_units − Σ base_i                  — leftover cents, always < number of recipients
  3. distribute 1 extra minor unit each to the `remainder` recipients with the
     largest fractional remainder from step 1, until the leftover is exhausted

Result: Σ part_i == total, always, by construction.
```

វិធីសាស្ត្រត្រឹមត្រូវមិនដែលបង្គត់ផ្នែកដាច់ដោយឡែកទេ — វាបង្គត់ *ការបែងចែកទាំងមូល* ជាប្រតិបត្តិការមួយ ដែលជាអ្វីដែលធ្វើឱ្យអថេរផលបូកកាន់។

## ឧទាហរណ៍ដែលបានគណនា

បំបែក $100.00 បីផ្លូវស្មើគ្នា (`shares = [1, 1, 1]`)។

វិធីសាស្ត្រអយុត្តិធម៌៖ $100.00 ÷ 3 = $33.333… បង្គត់ដោយឡែកទៅសេនជិតបំផុតផ្តល់ $33.33 សម្រាប់អ្នកទទួលម្នាក់ៗ។ បូក៖ $33.33 × 3 = $99.99 — សេនមួយបានបាត់ ហើយគ្មានធាតុបន្ទាត់ណា "ខុស" គ្រប់គ្រាន់ដើម្បីរកឃើញដោយការពិនិត្យទេ។

វិធីសាស្ត្រត្រឹមត្រូវ៖ `base` = $33.33 សម្រាប់ទាំងបី (9,999 ឯកតាតូចសរុបពី `floor(10,000 / 3) = 3,333` សេនក្នុងមួយ) ទុកសំណល់ 1 សេន (10,000 − 9,999)។ សេនសល់តែមួយនោះទៅអ្នកទទួលណាដែលមានសំណល់ប្រភាគធំបំផុតក្នុងការចែក — អ្នកទទួលជាក់លាក់គឺជាព័ត៌មានលម្អិត tie-break ផ្ទៃក្នុង មិនមែនអ្វីដែលអ្នកហៅគួរពឹងផ្អែកទេ។ អ្នកទទួលពីរនាក់ចុងក្រោយបាន $33.33 ហើយម្នាក់បាន $33.34 ហើយបីផ្នែកបូកស្មើ $100.00 យ៉ាងពិតប្រាកដ។

នេះគឺជានព្វន្ធដែល[ការវិភាគផលប៉ះពាល់ថវិកា](../ការវិភាគផលប៉ះពាល់ថវិកា/)ត្រូវការនៅពេលដែលតួលេខផលប៉ះពាល់ថវិកាសរុបត្រូវបានបំបែកឆ្លងទីតាំង ក្រុម ឬឆ្នាំសារពើពន្ធ ហើយផ្សះផ្សាត្រឡប់ទៅផលបូកដែលបានបោះពុម្ព — សូមមើល[ការបូកសរុបថ្លៃដើមសុវត្ថិភាពរូបិយប័ណ្ណ](../ការបូកសរុបថ្លៃដើមសុវត្ថិភាពរូបិយប័ណ្ណ/)សម្រាប់បញ្ហាដៃគូនៃការបូកធាតុបន្ទាត់ជាច្រើនដោយគ្មានការរសាត់។

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

នេះគឺជា "គំរូ Money" ព្យញ្ជនៈពីស្ថាបត្យកម្មកម្មវិធីសហគ្រាស — គំរូមូលដ្ឋានមានឈ្មោះសម្រាប់ថ្នាក់កំហុសនេះពិតប្រាកដ មិនមែនល្បិចតែមួយដងទេ។ ការបរាជ័យផ្សះផ្សាហិរញ្ញវត្ថុពិតបានចេញពីថ្នាក់កំហុសនេះ៖ ការបំបែកភាគរយគណនាក្នុង `f64` បង្គត់ក្នុងមួយអ្នកទទួល និងមិនដែលពិនិត្យធៀបនឹងផលបូកដើម។ វាតភ្ជាប់ដោយផ្ទាល់ទៅម៉ូឌុល[ថ្លៃដើមសរុបនៃភាពជាម្ចាស់](../ថ្លៃដើមសរុបនៃភាពជាម្ចាស់/)របស់ឃ្លាំងនេះ ដែលបច្ចុប្បន្នបូកថ្លៃចំណុចអណ្តែតធម្មតាឆ្លងឆ្នាំ និងជម្រើស — វិន័យភាពត្រឹមត្រូវដូចគ្នាអនុវត្តនៅពេលផលបូក TCO ឬផលប៉ះពាល់ថវិកាត្រូវតែបែងចែក ជាជាងគ្រាន់តែបូក។

## កំហុសដែលត្រូវជៀសវាង

- **ភាគរយបន្ទាប់មកបង្គត់ ជំនួសសំណល់ធំបំផុត**៖ ការបែងចែកដោយភាគរយចំណុចអណ្តែត ហើយបង្គត់អ្នកទទួលម្នាក់ៗដោយឡែក ដែលបង្កើនកំហុសបង្គត់ និងកម្របូកត្រឡប់ទៅផលបូក ជាពិសេសឆ្លងអ្នកទទួលច្រើន។
- **មិនយកចិត្តទុកដាក់ចំពោះនិទស្សន្តឯកតាតូចរូបិយប័ណ្ណ**៖ សន្មតថារូបិយប័ណ្ណគ្រប់មុខមាន 2 ខ្ទង់ទសភាគ — យ៉េនជប៉ុនមាន 0 រូបិយប័ណ្ណខ្លះមាន 3 — ការបំបែកភាគរយដោយដៃជាធម្មតាកូដរឹង 2 ហើយបែកដោយស្ងាត់សម្រាប់រូបិយប័ណ្ណផ្សេង; ទម្លាប់បែងចែកត្រឹមត្រូវអាននិទស្សន្តពីរូបិយប័ណ្ណខ្លួនឯង (ISO 4217)។
- **ការបែងចែកសំណល់ដែលបានបែងចែករួចឡើងវិញ**៖ ដំណើរការទម្លាប់បែងចែកម្តងទៀតលើអ្វីដែលនៅសល់ពីការបែងចែកមុន ដោយគ្មានការពិនិត្យ idempotency ដែលអាចឥណទានសេនដូចគ្នាទ្វេដងដល់អ្នកទទួលដូចគ្នា។
