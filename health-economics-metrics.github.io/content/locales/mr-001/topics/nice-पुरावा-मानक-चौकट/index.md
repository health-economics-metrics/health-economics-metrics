# NICE पुरावा मानक चौकट (ESF)

ESF ही NICE ची चौकट आहे जी डिजिटल आरोग्य तंत्रज्ञानाला त्याच्या जोखमीच्या प्रमाणात **किती पुरावा लागतो** ते निर्दिष्ट करते. "NHS आमचे अ‍ॅप विकत घेण्यापूर्वी आम्हाला काय सिद्ध करावे लागेल?" याच्या अधिकृत उत्तराच्या सर्वात जवळची ही गोष्ट आहे.

## हे का महत्त्वाचे आहे

ESF (2019 मध्ये प्रथम प्रकाशित, AI आणि अनुकूलनशील अल्गोरिदम समाविष्ट करण्यासाठी 2022 मध्ये अद्ययावत) डिजिटल आरोग्य तंत्रज्ञानाचे क्लिनिकल कार्यानुसार स्तरांमध्ये वर्गीकरण करते, **संचयी** पुरावा मानकांसह — 5 गटांमध्ये 21 मानके (रचना घटक, मूल्य, कामगिरी/परिणामकारकता, आर्थिक परिणाम, तैनाती):

```
Tier A — system services, no direct patient outcome (e.g., e-rostering)
         → basic standards: credibility, data protection, technical assurance
Tier B — inform, simple monitoring, communication (e.g., symptom diary)
         → + evidence of user benefit, appropriate reliability
Tier C — treat, diagnose, or actively guide clinical management
         → + high-quality comparative effectiveness evidence (ideally RCT)
           and economic analysis
```

आर्थिक पुराव्यासाठी, बहुतेक स्तरांसाठी [खर्च-परिणाम विश्लेषण](../खर्च-परिणाम-विश्लेषण/) स्वीकार्य आहे; सर्वोच्च जोखमीवर [खर्च-उपयुक्तता विश्लेषण](../खर्च-उपयुक्तता-विश्लेषण/) अपेक्षित. ESF तुमचा **बाजार प्रवेशाचा पुरावा खर्च** परिभाषित करते — इतर कोणत्याही बांधणी खर्चाप्रमाणे त्याचे अंदाजपत्रक करा.

## गणित

सूत्रे नाहीत — निर्णय सारणी. कार्यरत गणना व्यावसायिक आहे:

```
Evidence investment required = f(tier)
  Tier A: documentation + assurance ≈ £10k–50k
  Tier B: observational/comparative user-benefit study ≈ £50k–250k
  Tier C: RCT-grade comparative study + economic model ≈ £250k–£2M+

Position your product's claims deliberately: claiming "supports clinical
decisions" instead of "informs patients" moves you a tier and can 10× the bill.
```

## सोडवलेले उदाहरण

एक औषध-स्मरणपत्र अ‍ॅप निर्माता मात्रा-समायोजन शिफारस वैशिष्ट्य जोडण्याचा विचार करतो.

- स्मरणपत्र अ‍ॅप म्हणून: **स्तर B** — पालन सुधारणा दाखवणारा कोहॉर्ट अभ्यास पुरेसा.
- मात्रा शिफारशींसह: **स्तर C** — तुलनात्मक परिणामकारकता पुरावा (बहुधा नेहमीच्या काळजीविरुद्ध RCT) अधिक आर्थिक विश्लेषण.

RCT £600k खर्च करत असेल आणि मात्रा वैशिष्ट्याचा वाढीव महसूल £200k/वर्ष असेल, तर पुरावा खर्च भरून निघण्यापूर्वी वैशिष्ट्याला 3+ वर्षे मूल्य टिकवावे लागते — ESF स्तराची किंमत धरल्यावर पूर्णपणे वेगळा दिसणारा उत्पादन निर्णय. अनेक संघ स्तर B उत्पादन पाठवतात आणि स्तर C दावा निधी मिळेपर्यंत टप्प्याटप्प्याने ठेवतात.

## सॉफ्टवेअर अभियांत्रिकीशी संबंध

ESF हा या रेपॉझिटरीतील सर्वात हस्तांतरणीय प्रशासन नमुना आहे: **टूल स्वीकारासाठी जोखीम-स्तरित पुरावा आवश्यकता**. अंतर्गत आवृत्ती: कोड फॉरमॅटरला डेमो हवा (स्तर A); वाचलेल्या तासांचा दावा करणाऱ्या उत्पादकता टूलला मोजलेला पायलट हवा (स्तर B); तैनाती स्वयं-रोखणारा किंवा क्लिनिकल कोड स्वयं-लिहिणारा AI गेटला संस्था-व्यापी रोलआउटपूर्वी नियंत्रित-चाचणी-दर्जाचा पुरावा हवा (स्तर C). प्रमाणशीर पुरावा दोन्ही अपयश प्रकार थांबवतो — क्षुल्लक टूल्सचा नोकरशाहीने गळा घोटणे, आणि परिणामकारक टूल्स भावनेवर पाठवणे. "पुरावा मुदतीसह तात्पुरता स्वीकार" या पूरकासाठी [जर्मनीचा DiGA फास्ट-ट्रॅक](../जर्मनीचा-diga-फास्ट-ट्रॅक/) देखील पहा.

## सामान्य चुका

- **इच्छाधारी विचारातून स्तराचे चुकीचे वर्गीकरण** — नियामक आणि खरेदीदार उत्पादन *काय करते* त्यावरून वर्गीकरण करतात, विपणन काय म्हणते त्यावरून नाही.
- **उत्पादनानंतर बांधलेला पुरावा**: इन्स्ट्रुमेंटेशन किंवा equipoise शिवाय पाठवलेल्या उत्पादनावर RCT नंतर बसवणे संथ आणि अनेकदा अशक्य असते.
- **ESF पूर्ण करणे आणि बाकी विसरणे**: ESF DTAC (क्लिनिकल सुरक्षा, डेटा संरक्षण, इंटरऑपरेबिलिटी) आणि AI साठी नियामक मंजुरीसोबत असते — [AI नियामक मूल्यमापन](../ai-नियामक-मूल्यमापन/) पहा.
