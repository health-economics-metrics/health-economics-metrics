# क्लिनिकल AI मूल्यमापन

क्लिनिकल AI किंवा निदान मॉडेलच्या मूल्यमापनासाठी मूलभूत सांख्यिकी: संवेदनशीलता, विशिष्टता, AUROC, भविष्यसूचक मूल्ये आणि तपासणीसाठी आवश्यक संख्या. मध्यवर्ती आर्थिक धडा: **उत्कृष्ट AUROC म्हणजे खर्च-परिणामकारक तैनाती नव्हे** — मूल्य ऑपरेटिंग बिंदू, प्रसार आणि प्रत्येक सकारात्मक निकालानंतर पुढे काय घडते यावर अवलंबून असते.

## हे का महत्त्वाचे आहे

नियामक (FDA, MHRA) क्लिनिकल AI ला **लॉक केलेल्या ऑपरेटिंग बिंदूवर** अधिकृत करतात — विशिष्ट संवेदनशीलता/विशिष्टता जोडी (उदा., पहिली FDA-मंजूर स्वायत्त डायबेटिक-रेटिनोपॅथी प्रणाली: तिच्या निर्णायक चाचणीत संवेदनशीलता 87.2%, विशिष्टता 90.7%). त्यानंतर आरोग्य अर्थशास्त्रज्ञ असा प्रश्न विचारतात ज्याचे उत्तर अचूकता मेट्रिक्स देऊ शकत नाहीत: तुमच्या तैनाती लोकसंख्येच्या प्रसारात प्रत्येक शोधाला *किती खर्च येतो*, आणि त्यावर कृती करणे योग्य आहे का? रेटिनोपॅथी-तपासणी AI च्या आर्थिक मूल्यमापनाने (npj Digital Medicine 2024) दाखवले की रेफरल खर्च मोजल्यावर केवळ उच्च अचूकता खर्च-परिणामकारकतेची हमी देत नाही.

## गणित

```
Sensitivity = TP / (TP + FN)        — of the truly positive, share caught
Specificity = TN / (TN + FP)        — of the truly negative, share cleared
AUROC       = P(model ranks a random positive above a random negative)
              0.5 chance … 1.0 perfect; threshold-independent — and therefore
              deployment-decision-insufficient

PPV = TP / (TP + FP)   ← prevalence-dependent (Bayes); collapses when rare
NPV = TN / (TN + FN)

NNS  ≈ 1 / (prevalence × sensitivity)       — screened per true case found
Cost per true case = programme cost / TP      — the economic bottom line
```

## सोडवलेले उदाहरण

तेच मॉडेल, दोन ठिकाणी — संवेदनशीलता 90%, विशिष्टता 93%:

```
Specialist clinic (prevalence 20%):
  PPV = (0.9×0.2)/(0.9×0.2 + 0.07×0.8) = 0.18/0.236 ≈ 76%  → 3 in 4 alerts real

Primary care (prevalence 1%):
  PPV = (0.9×0.01)/(0.9×0.01 + 0.07×0.99) = 0.009/0.0783 ≈ 11.5%
  → 8 in 9 alerts false; workup at £350 each:
  cost per true case = (0.009 + 0.0693) × 350 / 0.009 ≈ £3,045 per case found
```

तेच मॉडेल, पण आमूलाग्र वेगळे अर्थशास्त्र — म्हणूनच स्थळ-विशिष्ट मूल्यमापन हा नियामक विषय आहे, आणि "आमच्या मॉडेलचा AUROC 0.95 आहे" ही आर्थिक प्रकरणाची सुरुवात आहे, शेवट नाही. संपूर्ण कार्यक्रम गणितासाठी [तपासणी अर्थशास्त्र](../तपासणी-अर्थशास्त्र/) पहा.

## सॉफ्टवेअर अभियांत्रिकीशी संबंध

क्लिनिकल AI बनवणाऱ्या किंवा खरेदी करणाऱ्या अभियंत्यांसाठी: **ROC वक्रावरच न थांबता तैनाती प्रसारावरील confusion matrix पाठवा**; **थ्रेशोल्डला आर्थिक निर्णय होऊ द्या** — संवेदनशीलता/विशिष्टता तडजोडीने अपेक्षित खर्च कमीत कमी करावा (चुकलेली प्रकरणे × चुकण्याचा खर्च विरुद्ध खोटे गजर × तपासणी खर्च), बेंचमार्क सांख्यिकी वाढवू नये; आणि तुमच्या स्वतःच्या टूलिंगमध्ये तेच गणित ओळखा — अलर्ट प्रणाली, विसंगती-शोधक आणि सुरक्षा स्कॅनर हे कमी-प्रसाराच्या घटना प्रवाहांवरील निदान चाचण्या आहेत, ज्यांचा अलर्ट थकवा हा [NNH](../उपचारासाठी-आवश्यक-संख्या/) आहे. ऑपरेटिंग बिंदू हलवणारी मॉडेल अद्यतने अर्थशास्त्र पुन्हा उघडतात (आणि नियामक मंजुरीही — [AI नियामक मूल्यमापन](../ai-नियामक-मूल्यमापन/) पहा).

## सामान्य चुका

- **AUROC खरेदी**: मॉडेल एकाच थ्रेशोल्डवर चालणार असताना AUROC वर तुलना करणे — ऑपरेटिंग बिंदूवर तुलना करा.
- **प्रत्यक्ष तैनातीसाठी चाचणी-प्रसारातील PPV उद्धृत करणे** — नेहमीचे उदाहरण; नेहमी स्थानिक प्रसारावर पुन्हा मोजा.
- **स्पेक्ट्रम पक्षपात**: स्पष्ट प्रकरणे विरुद्ध निरोगी नियंत्रणे यावर प्रमाणित केलेली मॉडेल्स व्यवहारात प्रबळ असलेल्या अस्पष्ट मधल्या भागात अपेक्षेपेक्षा कमी कामगिरी करतात.
- **खालच्या मार्गाचा खर्च न मोजणे**: प्रत्येक सकारात्मक निकाल तपासणी सुरू करतो; मॉडेल हा *संपूर्ण मार्गाच्या* अर्थशास्त्रावरील हस्तक्षेप आहे.
