# עלות בעלות כוללת (TCO)

TCO היא העלות המלאה של מערכת לאורך חייה: רכישה או בנייה, אינטגרציה, הפעלה, תחזוקה, תמיכה, הדרכה והוצאה משימוש. קו הבסיס הלא נוח: **תחזוקה היא 50–80% מה-TCO של תוכנה** — בערך שלושה רבעים מעלות החיים מגיעים *אחרי* ההשקה.

## למה זה חשוב

הערכת טכנולוגיות בריאות למדה מזמן שמחיר התרופה אינו עלותה — מתן, ניטור וטיפול בתופעות לוואי שייכים כולם למודל. תיקי עסקים של תוכנה שסופרים רק עלות בנייה/רישוי חוזרים על טעות מחיר התרופה הנאיבי, ומקטינים באופן שיטתי את צד העלות של כל [ICER](../יחס-עלות-אפקטיביות-מצטבר/) ו[השפעה תקציבית](../ניתוח-השפעה-תקציבית/) שהם מזינים. ברכש של ה-NHS, משמעת TCO היא מה שהופך את טענת העלות-תועלת של מוצר דיגיטלי לישרה — ושם אפשרויות שנראות זולות מפסידות.

## המתמטיקה

```
TCO = initial cost (build/licence + integration + data migration + training)
    + Σ_t [operations + maintenance + support + infrastructure + upgrades
           + compliance/assurance]_t / (1 + r)^t
    + decommissioning cost (exit, data extraction, parallel running)

Horizon: 3–5 years commercial, system-lifetime for clinical infrastructure
r: 3.5% public sector (Green Book), 8–12% commercial
Benchmarks: annual maintenance ≈ 15–20% of build cost; ~78% of lifetime
TCO post-launch; ignore decommissioning and vendor lock-in prices itself.
```

## דוגמה מחושבת

שתי אפשרויות למערכת תצפיות אלקטרונית, אופק של 5 שנים:

```
                        Vendor SaaS     In-house build
Year 0 (licence/build)  £250,000        £900,000
Integration + training  £180,000        £150,000
Annual run (yrs 1–5)    £120,000/yr     £190,000/yr  (hosting + 1.5 FTE maint.)
Exit/decommission       £60,000         £30,000

Undiscounted TCO        £1,090,000      £2,030,000
```

אומדן ההנדסה של אפשרות הבנייה (£900k) היה רק 44% מה-TCO האמיתי שלה — ואומדני בנייה עצמם חורגים בדרך כלל ב-30–40% (ראו [לבנות או לקנות](../לבנות-או-לקנות/)). אלא אם האפשרות הפנימית מספקת *תוצאות* שונות מהותית, חלה לוגיקת [מזעור עלויות](../ניתוח-מזעור-עלויות/) וה-SaaS מנצח בכ-£940k.

## הקשר להנדסת תוכנה

מהנדסים נותנים משקל חסר לנתוני התחזוקה של תחומם כשהם דוגלים בבנייה: כלל התחזוקה השנתית של 15–20% מעלות הבנייה אומר שכל מערכת של £1M מתחייבת בשקט ל-£150–200k בשנה של קיבולת עתידית — התחייבות ששייכת לאותה מאזן מנטלי כמו [חוב טכני](../חוב-טכני/). TCO הוא גם חצי העלות של כל מדד במאגר זה: עלות לפריסה, [כלכלת יחידה בענן](../כלכלת-יחידה-בענן/), ומשמעת המכנה ש-HTA כופה על נותני חסות לתרופות. כשמחיר המוצר שלכם מאותגר, השוואת TCO הכוללת את עלויות ההפעלה האמיתיות של המתחרה המבוסס היא בדרך כלל המסגור מחדש החזק ביותר. נתון TCO רב-שנתי כמו לעיל הוא סכום של פריטי עלות רבים לאורך זמן — ראו [סיכום עלויות בטוח למטבע](../סיכום-עלויות-בטוח-מטבע/) להסבר מדוע הסכום צריך להיות עשרוני מדויק ולא נקודה צפה כשמודל חייב להתיישב עד הפני, ו[הקצאת עלויות עד הסנט](../הקצאת-עלות-בסנטים-מדויקים/) לפיצול סך TCO בין מרכזי עלות בלי לאבד פני.

## מלכודות נפוצות

- **עיגון בעלות ההשקה**: השוואת אפשרויות בעלות שנה 0 כשהדירוג מתהפך עד שנה 3.
- **כשל העבודה הפנימית החינמית**: תחזוקה פנימית מתומחרת באפס כי "הצוות כבר משולם" — ראו [עלות הזדמנות](../עלות-הזדמנות/).
- **התעלמות מעלויות יציאה**: הוצאת נתונים, סיום חוזה והפעלה מקבילה הם המקום שבו SaaS "זול" נעשה יקר.
- **הפרות אותו-אופק**: השוואת TCO של SaaS ל-3 שנים מול הפחתת בנייה ל-10 שנים (ראו [אופק זמן](../אופק-זמן/)).
