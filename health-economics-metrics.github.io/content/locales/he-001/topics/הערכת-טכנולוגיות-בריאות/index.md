# הערכת טכנולוגיות בריאות (HTA)

HTA הוא התהליך הפורמלי והממוסד שבו מערכות בריאות מחליטות אם טכנולוגיה — תרופה, מכשיר או תוכנה — שווה תשלום. הוא משלב ראיות ליעילות קלינית עם הערכה כלכלית במתודולוגיה מפורסמת וחובה.

## למה זה חשוב

אם אתם מוכרים לשירות בריאות לאומי, גוף HTA עשוי להכריע ממש בגישתכם לשוק. הכרת התהליך המקומי היא הכרת הרגולטור האמיתי של הערך:

- **NICE (אנגליה)**: הערכות סטטוטוריות לפי *מקרה ייחוס* מוגדר — QALY מ-[EQ-5D](../eq-5d/), [נקודת מבט](../נקודת-מבט-הניתוח/) NHS+PSS, [היוון](../היוון-והעדפת-זמן/) של 3.5%, [PSA](../ניתוח-רגישות-הסתברותי/) נדרש — נשפטות מול £20k–£30k/QALY עם [מתקני חומרה](../חסר-qaly-ומתקני-חומרה/); טכנולוגיות מיוחדות במיוחד עד £100k+ עם שקלול.
- **ICER (ארה"ב, לא ממשלתי)**: דוחות ראיות עם *אמת מידה למחיר תועלת בריאותית* — המחיר שבו מוצר יהיה עלות-אפקטיבי ב-$100k–$150k ל-QALY/evLYG — משמש כמנוף משא ומתן; בתוספת "התראות יכולת עמידה" של השפעה תקציבית.
- **קנדה (CADTH → CDA-AMC)**: סקירות החזר בכ-CAD$50k/QALY; היסטורית ביקשו הורדות מחיר בכ-95% מההגשות.

## המתמטיקה

כוחו של HTA אינו נוסחה אלא **שיטה מחויבת**: כל הגשה מחשבת את אותו [ICER](../יחס-עלות-אפקטיביות-מצטבר/) תחת אותם כללי מקרה ייחוס, כך שהתוצאות ברות השוואה בין מוצרים ושנים. מקרה הייחוס מגדיר מדד תוצאה, מכשיר תועלתנות, נקודת מבט, בחירת קבוצת השוואה, שיעור היוון, אופק זמן וניתוח אי-ודאות — ומסיר כל דרגת חופש שמממן יכול לשחק בה.

## דוגמה מחושבת

טיפול דיגיטלי מוגש להערכה בסגנון NICE:

```
Model: ΔC = +£450/patient, ΔE = +0.03 QALYs → ICER = £15,000/QALY ✓ under £20k
Reference-case checks:
  utilities from EQ-5D-5L with UK value set              ✓
  comparator = current care pathway (not "no treatment") ✓
  PSA: 71% probability cost-effective at £20k            ✓ (reported)
  severity modifier: shortfall below ×1.2 bounds         — none claimed
Recommendation: routine commissioning, with real-world data collection.
```

הניתוח המועדף על המממן עצמו הראה £9,000/QALY; מקרה הייחוס דחף אותו ל-£15,000 בכפיית קבוצת השוואה כנה. הפער הזה הוא *הסיבה* שמקרי ייחוס קיימים.

## הקשר להנדסת תוכנה

הארטיפקט הניתן להעברה הוא **מקרה הייחוס הפנימי**: שיטה מחויבת אחת לכל התיקים העסקיים של כלים/פלטפורמות — קבוצת השוואה מוצהרת, עלויות יחידה סטנדרטיות (ראו [תעריף לאומי ועלויות יחידה](../תעריף-לאומי-ועלויות-יחידה/) לתבנית), שיעור היוון קבוע, ניתוח רגישות נדרש, תבנית סטנדרטית. "תיק AMCP לכלים" שמוגש למועצת פלטפורמה הופך הצעות לברות השוואה ומשחק לגלוי, בדיוק כפי ש-HTA עושה לרפואה. התחילו קטן יותר מ-NICE: תבנית של שני עמודים בתוספת מחירון שפורסם עדיפה על היעדר תקן.

לאופן שבו מודל HTA רב-מחזורי מדומה בפועל קוהורטה-אחר-מחזור, ראו [סימולציית קוהורטת מרקוב](../סימולציית-קוהורטת-מרקוב/).

## מלכודות נפוצות

- **התייחסות ל-HTA כפורמליות אחרי אישור רגולטורי** — אישור CE/UKCA/FDA אומר שמוצר בטוח; HTA מחליט אם הוא *שווה קנייה*. מכשול אחר, ראיות אחרות.
- **בניית המודל הכלכלי אחרי הניסוי** — הפקת ראיות צריכה להיות מתוכננת לאחור מדרישות מקרה הייחוס.
- **התעלמות מהבדלי תחום שיפוט**: ICER שניתן לממן בארה"ב ב-$120k/QALY נכשל ב-NICE ב-£30k; תכננו ראיות ותמחור לכל שוק.
