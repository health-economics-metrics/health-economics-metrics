# ניתוח החלטות רב-קריטריונים (MCDA)

ניתוח החלטות רב-קריטריונים (MCDA) הוא מודל ניקוד בסכום משוקלל המשמש בהערכת טכנולוגיות בריאות כשסף ICER/נכונות-לשלם יחיד אינו לוכד את כל מה שמקבל ההחלטות אכפתי לו: שוויון, צורך שלא נענה, חדשנות, השפעה תקציבית, חומרת מחלה. לכל קריטריון ניתן משקל המשקף את חשיבותו (נשלף מבעלי עניין, משקלות מסתכמים ל-1), לכל אפשרות ניתן ציון מנורמל לכל קריטריון (בדרך כלל 0–1), והציון הכולל הוא הסכום המשוקלל — אותה צורה מתמטית כמו כרטיס ניקוד לבחירת ספק תוכנה.

## למה זה חשוב

MCDA משמש במסגרות כמו EVIDEM, ועל ידי גופי HTA מסוימים בהערכות של מחלות יתומות/נדירות שבהן גישת סף עלות-ל-QALY קפדנית נחשבת צרה מדי כדי לתפוס את כל מה שחשוב בהחלטה. כוח המשימה ISPOR MCDA Emerging Good Practices ביסס הנחיות פרקטיקה טובה לשליפת משקלות וציונים באופן הניתן להגנה, דווקא משום שהחלטה משוקללת באופן לא פורמלי קלה לבנייה וקלה למשחק. כשלטכנולוגיית בריאות יש באמת ממדי ערך ש[סף נכונות לשלם](../ספי-נכונות-לשלם/) יחיד אינו יכול לייצג — חומרה, חדשנות, שוויון — MCDA נותן למקבלי החלטות מבנה מפורש וניתן לביקורת לשילובם, במקום שיקול דעת לא מוצהר.

## המתמטיקה

```
MCDA score = Σ_i (weight_i × score_i)

weights should sum to 1 (elicited via stakeholder methods such as swing
weighting or the Analytic Hierarchy Process)
```

## דוגמה מחושבת

ועדת HTA מנקדת טיפול דיגיטלי בארבעה קריטריונים:

```
Criterion                          Weight   Score   Weight × Score
Clinical benefit                   0.4      0.8     0.32
Cost impact                        0.3      0.5     0.15
Disease severity / unmet need      0.2      0.9     0.18
Innovation                         0.1      0.6     0.06
                                    ─────                ─────
                                    1.0                  0.71
```

המשקלות מסתכמים ל-1.0 (0.4 + 0.3 + 0.2 + 0.1), וציון ה-MCDA הוא 0.71 (0.32 + 0.15 + 0.18 + 0.06). הוועדה משווה 0.71 לסף שהוסכם מראש, או מדרגת אותו מול טכנולוגיות מתחרות שנוקדו באותו אופן.

## הקשר להנדסת תוכנה

זו בדיוק אותה מתמטיקה כמו כרטיס ניקוד משוקלל לבחירת ספק, מטריצת הערכת RFP או מודל ניקוד לתעדוף פיצ'רים — ראו [לבנות או לקנות](../לבנות-או-לקנות/), מקרה שימוש קלאסי של כרטיס ניקוד משוקלל ברכש תוכנה. כדאי גם לעמת עם [WSJF ו-CD3](../wsjf-ו-cd3/): WSJF/CD3 היא שיטת תעדוף מבוססת *יחס* (עלות עיכוב מחולקת בגודל עבודה או משך), בעוד MCDA היא *סכום* משוקלל. MCDA ו-WSJF/CD3 הן שתי תשובות שונות מבנית ל"איך מדרגים אפשרויות מתחרות", והידיעה איזו מהן החלטה נתונה באמת דורשת — ערך מצטבר על פני קריטריונים בלתי תלויים, לעומת צפיפות ערך ליחידת קיבולת נדירה — חשובה יותר מאיזו נוסחה נראית קפדנית יותר.

## מלכודות נפוצות

- **הטיית שליפת משקלות**: מי שקובע את המשקלות קובע למעשה מראש את הדירוג, כך ש"נוסחה" יכולה להלבין החלטה פוליטית או מסחרית כחישוב אובייקטיבי. תעדו מי קבע את המשקלות וכיצד.
- **ספירה כפולה של קריטריון שכבר נלכד במקום אחר**: ניקוד "עלות-אפקטיביות" כקריטריון אחד *וגם* ניקוד נפרד של "השפעת עלות" מעניק יותר מדי משקל לכסף ביחס לקריטריונים האחרים בלי שאיש התכוון לכך.
- **דיוק כוזב**: ציון משוקלל בשתי ספרות עשרוניות (0.71) מרמז על קפדנות רבה יותר ממה שדירוגי בעלי העניין 0–10 שבבסיסו תומכים בה, ושונות בין מדרגים בדירוגים אלה לרוב אינה מדווחת כלל.
