# הערכת בינה מלאכותית קלינית

הסטטיסטיקה המרכזית להערכת מודל בינה מלאכותית קלינית או אבחוני: רגישות, סגוליות, AUROC, ערכים חזויים ומספר הנדרש לסקירה. הלקח הכלכלי המרכזי: **AUROC מצוין אינו הופך פריסה לעלות-אפקטיבית** — הערך תלוי בנקודת הפעולה, בשכיחות, ובמה שקורה במורד הזרם של כל תוצאה חיובית.

## למה זה חשוב

רגולטורים (FDA, MHRA) מאשרים בינה מלאכותית קלינית ב**נקודת פעולה נעולה** — זוג רגישות/סגוליות מסוים (למשל מערכת הרטינופתיה הסוכרתית האוטונומית הראשונה שאושרה על ידי FDA: רגישות 87.2%, סגוליות 90.7% בניסוי המכריע שלה). כלכלני בריאות שואלים אז את השאלה שמדדי דיוק אינם יכולים לענות עליה: בשכיחות של אוכלוסיית הפריסה שלכם, כמה *עולה* כל זיהוי, והאם הפעולה בעקבותיו שווה את זה? הערכה כלכלית של בינה מלאכותית לסקירת רטינופתיה (npj Digital Medicine 2024) הראתה שדיוק גבוה יותר לבדו לא הבטיח עלות-אפקטיביות לאחר שנספרו עלויות ההפניה.

## המתמטיקה

```
Sensitivity = TP / (TP + FN)        — of the truly positive, share caught
Specificity = TN / (TN + FP)        — of the truly negative, share cleared
AUROC       = P(model ranks a random positive above a random negative)
              0.5 chance … 1.0 perfect; threshold-independent — and therefore
              deployment-decision-insufficient

PPV = TP / (TP + FP)   ← prevalence-dependent (Bayes); collapses when rare
NPV = TN / (TN + FN)

NNS  ≈ 1 / (prevalence × sensitivity)       — screened per true case found
Cost per true case = programme cost / TP      — the economic bottom line
```

## דוגמה מחושבת

אותו מודל, שתי סביבות — רגישות 90%, סגוליות 93%:

```
Specialist clinic (prevalence 20%):
  PPV = (0.9×0.2)/(0.9×0.2 + 0.07×0.8) = 0.18/0.236 ≈ 76%  → 3 in 4 alerts real

Primary care (prevalence 1%):
  PPV = (0.9×0.01)/(0.9×0.01 + 0.07×0.99) = 0.009/0.0783 ≈ 11.5%
  → 8 in 9 alerts false; workup at £350 each:
  cost per true case = (0.009 + 0.0693) × 350 / 0.009 ≈ £3,045 per case found
```

אותו מודל, כלכלה שונה לחלוטין — ולכן הערכה ספציפית לאתר היא נושא רגולטורי, ולכן "למודל שלנו יש AUROC של 0.95" הוא תחילת התיק הכלכלי, לא סופו. ראו [כלכלת סקירה](../כלכלת-סקירה/) למתמטיקה המלאה של התוכנית.

## הקשר להנדסת תוכנה

למהנדסים שבונים או קונים בינה מלאכותית קלינית: **שלחו את מטריצת הבלבול בשכיחות הפריסה**, לא רק את עקומת ה-ROC; **תנו לסף להיות החלטה כלכלית** — פשרת הרגישות/סגוליות צריכה למזער עלות צפויה (מקרים שהוחמצו × עלות החמצה מול אזעקות שווא × עלות בירור), לא למקסם סטטיסטיקת ייחוס; והכירו את אותה מתמטיקה בכלים שלכם — מערכות התראה, גלאי חריגות וסורקי אבטחה הם בדיקות אבחון על זרמי אירועים בשכיחות נמוכה, כשעייפות התראות היא ה-[NNH](../המספר-הנדרש-לטיפול/). עדכוני מודל שמזיזים את נקודת הפעולה פותחים מחדש את הכלכלה (ואת האישור הרגולטורי — ראו [הערכה רגולטורית של בינה מלאכותית](../הערכה-רגולטורית-של-בינה-מלאכותית/)).

## מלכודות נפוצות

- **קניות AUROC**: השוואת מודלים לפי AUROC כשהם ירוצו בסף אחד — השוו בנקודת הפעולה.
- **PPV בשכיחות הניסוי המצוטט לפריסה בעולם האמיתי** — הקלאסיקה; תמיד חשבו מחדש בשכיחות המקומית.
- **הטיית ספקטרום**: מודלים שאומתו על מקרים ברורים מול בקרות בריאות מציגים ביצועי יתר באמצע העמום ששולט בפרקטיקה.
- **היעדר תמחור המסלול במורד הזרם**: כל תוצאה חיובית מפעילה בירור; מודל הוא התערבות ב*כלכלת כל המסלול*.
