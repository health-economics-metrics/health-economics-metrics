# ຜະລິດຕະພາບຂອງນັກພັດທະນາດ້ວຍ AI

ຕົວຊີ້ວັດວ່າຜູ້ຊ່ວຍຂຽນໂຄດດ້ວຍ AI ເຮັດຫຍັງກັບຜົນຜະລິດຂອງວິສະວະກຳແທ້ໆ: ອັດຕາການຍອມຮັບຄຳແນະນຳ, ການເລັ່ງຄວາມໄວຈາກການສຶກສາແບບຄວບຄຸມ, ປະລິມານ PR, ແລະ ການຄົງຢູ່ຂອງໂຄດ. ຖານຫຼັກຖານຂັດແຍ້ງກັນຈິງໆ — ເຊິ່ງເຮັດໃຫ້ມັນເປັນກໍລະນີສຶກສາທີ່ສົມບູນແບບຂອງຄວາມແຕກຕ່າງລະຫວ່າງ efficacy ກັບ effectiveness ທີ່ເສດຖະສາດສຸຂະພາບຖືກສ້າງຂຶ້ນມາຮັບມື.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ສອງການສຶກສາແບບຄວບຄຸມທີ່ຖືກອ້າງເຖິງຫຼາຍທີ່ສຸດຊີ້ໄປຄົນລະທິດ:

- **Peng et al. 2023 (GitHub Copilot RCT)**: ນັກພັດທະນາເຮັດໜ້າທີ່ເຊີບເວີ HTTP ແບບເລີ່ມໃໝ່ສຳເລັດ**ໄວຂຶ້ນ 55.8%** ເມື່ອໃຊ້ Copilot (1 ຊມ 11 ນທ ທຽບກັບ 2 ຊມ 41 ນທ, n=95).
- **METR 2025 RCT**: ນັກພັດທະນາໂອເພນຊອດທີ່ມີປະສົບການ ເຮັດວຽກຢູ່ໃນ*ຄັງໂຄດທີ່ເປັນຜູ້ໃຫຍ່ຂອງຕົນເອງ* **ຊ້າລົງ 19%** ເມື່ອໃຊ້ເຄື່ອງມື AI ຕົ້ນປີ 2025 (ນັກພັດທະນາ 16 ຄົນ, 246 ໜ້າວຽກ) — ໃນຂະນະທີ່ *ເຊື່ອ*ວ່າຕົນໄວຂຶ້ນ 20%.

ທັງສອງເປັນການສຶກສາທີ່ດີ. ຄວາມຂັດແຍ້ງນັ້ນຄືຜົນການຄົ້ນພົບ: efficacy ໃນໜ້າວຽກເລີ່ມໃໝ່ບໍ່ຖ່າຍທອດໄປເປັນ effectiveness ໃນຄັງໂຄດທີ່ເປັນຜູ້ໃຫຍ່, ແລະ ຜົນປະໂຫຍດທີ່*ຮັບຮູ້*ບໍ່ສາມາດແທນຜົນປະໂຫຍດທີ່ວັດໄດ້. ການແພດມີຊື່ເອີ້ນທັງສອງປະກົດການ (ການທົດລອງແບບອະທິບາຍ ທຽບກັບແບບປະຕິບັດຈິງ; ບັນຫາ placebo) ແລະ ມີກົນໄກຮັບມື.

## ຄະນິດສາດ

```
Acceptance rate  = accepted suggestions / shown suggestions
                   (GitHub telemetry ~30% avg; varies: SQL 45%, Python 35%, JS 28%)
Retention rate   = AI code surviving to merge / accepted AI code (~88% reported)
Speedup          = (t_control − t_AI) / t_control  (from controlled comparison ONLY)
Throughput delta = Δ merged PRs/dev/week (GitHub/Accenture field data: +8.7%)

Value model     = devs × time saved × loaded rate × utilization factor
                  — every term needs local measurement; see the tornado in
                  sensitivity-analysis.md, where time-saved dominates all
                  other parameters combined
```

## ຕົວຢ່າງການຄິດໄລ່

ອົງກອນທີ່ມີນັກພັດທະນາ 500 ຄົນທົດລອງຜູ້ຊ່ວຍດ້ວຍກຸ່ມຄວບຄຸມທີ່ຖືກຕ້ອງ (ທີມທີ່ຈັບຄູ່ກັນ, 3 ເດືອນ, ຕົວຊີ້ວັດທີ່ລົງທະບຽນລ່ວງໜ້າ):

```
Pilot result: PR cycle time −18%; merged PRs +6%; CFR unchanged;
              self-reported time saved 45 min/day; measured task-level ≈ 15 min/day

Value the MEASURED number: 500 × 0.25h × 220d × £60 × 0.6 utilization
                          ≈ £990,000/year capacity (non-cash-releasing)
Cost: 500 × £39/mo × 12 ≈ £234,000/year
Net capacity ratio ≈ 4:1 — fundable, at one-third the self-reported claim.
```

ຊ່ອງຫວ່າງ 3 ເທົ່າລະຫວ່າງສິ່ງທີ່ຮັບຮູ້ກັບສິ່ງທີ່ວັດໄດ້ ແມ່ນຜົນການຄົ້ນພົບຂອງ METR ທີ່ເກີດຂຶ້ນຈິງ; ຖ້າຈັດງົບປະມານຕາມການລາຍງານດ້ວຍຕົນເອງ ແຖວຜົນປະໂຫຍດຈະສູງເກີນຈິງສາມເທົ່າ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ສິ່ງທີ່ນຳເຂົ້າຈາກເສດຖະສາດສຸຂະພາບສຳລັບທຸກຄົນທີ່ປະເມີນເຄື່ອງມື AI: ດຳເນີນ**ການທົດລອງແບບປະຕິບັດຈິງ (pragmatic trials)** (ຄັງໂຄດຂອງທ່ານ, ວິສະວະກອນຂອງທ່ານ, ຕັ໋ວຈິງ — ບໍ່ແມ່ນໜ້າວຽກສາທິດຂອງຜູ້ຂາຍ); ຖື**ອັດຕາການຍອມຮັບເປັນຕົວແທນ ບໍ່ແມ່ນຜົນລັບ** (ມັນຄື [PPV](../ການປະເມີນ-ai-ທາງຄລີນິກ/) ຂອງຄຳແນະນຳໃນມຸມມອງຂອງນັກພັດທະນາ — ການຍອມຮັບສູງແຕ່ການຄົງຢູ່ຕ່ຳຄືການວິນິດໄສເກີນຈິງ); ຈັບຄູ່ທຸກການເພີ່ມຂຶ້ນຂອງປະລິມານງານກັບ**ການກວດສອບຄວາມໝັ້ນຄົງ** (DORA 2025: AI ເພີ່ມປະລິມານງານ ແຕ່ເຮັດໃຫ້ຄວາມໝັ້ນຄົງຕົກ — ການແຊກແຊງທີ່ມີຜົນຂ້າງຄຽງຕ້ອງການການວິເຄາະຜົນປະໂຫຍດສຸດທິ ຕາມ[ຕົວຊີ້ວັດ DORA](../ຕົວຊີ້ວັດ-dora/)); ແລະ ຈັດປະເພດຜົນປະໂຫຍດຢ່າງຊື່ສັດວ່າເປັນຄວາມສາມາດ ([ການປະຢັດທີ່ປົດປ່ອຍເງິນສົດ ທຽບກັບທີ່ບໍ່ປົດປ່ອຍເງິນສົດ](../ການປະຢັດທີ່ປົດປ່ອຍເງິນສົດ-ທຽບກັບ-ທີ່ບໍ່ປົດປ່ອຍເງິນສົດ/)).

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ການຍ້າຍການສຶກສາຂອງຜູ້ຂາຍມາໃຊ້ຜິດບ່ອນ**: ເອົາຕົວເລກ RCT ໜ້າວຽກເລີ່ມໃໝ່ໄປໃຊ້ກັບງານຄັງໂຄດເກົ່າ — ຂໍ້ຜິດພາດທີ່ການສຶກສາ METR ເປີດໂປງ.
- **ການລາຍງານດ້ວຍຕົນເອງເປັນການວັດ**: ຊ່ອງຫວ່າງການຮັບຮູ້ 20 ຈຸດເປີເຊັນແມ່ນຄວາມລຳອຽງທີ່ໃຫຍ່ທີ່ສຸດທີ່ຮູ້ຈັກໃນວັນນະຄະດີນີ້.
- **ການຂະຫຍາຍກິດຈະກຳ**: PR ແລະ ໂຄດທີ່ຫຼາຍຂຶ້ນແມ່ນ Activity ບໍ່ແມ່ນຜົນລັບ ([SPACE](../space-ແລະ-devex/)); ໃຫ້ຈັບຄູ່ກັບການແກ້ໄຂຊ້ຳ ແລະ CFR.
- **ການລະເລີຍເສັ້ນໂຄ້ງການຮຽນຮູ້**: ການວັດໃນອາທິດທີ 2 ຈັບຜົນຂອງຄວາມໃໝ່ໃນທິດທາງໃດກໍໄດ້; ໃຫ້ວັດເມື່ອເຂົ້າສູ່ສະພາບຄົງທີ່ ([ຂອບເຂດເວລາ](../ຂອບເຂດເວລາ/)).
