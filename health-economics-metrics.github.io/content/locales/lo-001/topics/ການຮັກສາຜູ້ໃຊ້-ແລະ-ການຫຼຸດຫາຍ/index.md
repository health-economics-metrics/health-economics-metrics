# ການຮັກສາຜູ້ໃຊ້ ແລະ ການຫຼຸດຫາຍ

ການຮັກສາຜູ້ໃຊ້ວັດວ່າສ່ວນໃດຂອງກຸ່ມຜູ້ໃຊ້ຍັງໃຊ້ງານຢູ່ N ວັນຫຼັງເລີ່ມ (ເສັ້ນໂຄ້ງ D1/D7/D30); ການຫຼຸດຫາຍແມ່ນສ່ວນເສີມຂອງມັນ. ເສັ້ນຖານສຸຂະພາບດິຈິຕອນທີ່ໂຫດຮ້າຍ: **ປະມານ 90% ຂອງຜູ້ໃຊ້ແອັບສຸຂະພາບເລີກໃຊ້ພາຍໃນ 30 ວັນ** — ການຮັກສາຜູ້ໃຊ້ D30 ຂອງສຸຂະພາບດິຈິຕອນຢູ່ ~3–4% ທຽບກັບຄ່າສະເລ່ຍທຸກແອັບ ~6%.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

Eysenbach ຕັ້ງຊື່ໃນປີ 2005: **ກົດແຫ່ງການຫຼຸດຫາຍ (law of attrition)** — ການສູນເສຍຜູ້ໃຊ້ໃນອັດຕາສູງແມ່ນຄຸນສົມບັດທີ່ແນ່ນອນ ແລະ ເປັນໂຄງສ້າງຂອງການແຊກແຊງ eHealth, ບໍ່ແມ່ນຂໍ້ບົກພ່ອງຂອງການນຳໃຊ້, ດ້ວຍການຫຼຸດຫາຍໃນການທົດລອງ eHealth ປົກກະຕິເກີນ 50%. ຜົນສະທ້ອນດ້ານເສດຖະກິດຄືທັງໝົດ: ການຮັກສາຜູ້ໃຊ້ກຳນົດ *ປ່ອງຢ້ຽມການຮັກສາ* ທີ່ປະໂຫຍດໃດໆສາມາດສົ່ງມອບໄດ້, ແລະ [ເສດຖະສາດຫົວໜ່ວຍ](../ເສດຖະສາດຫົວໜ່ວຍຂອງແອັບສຸຂະພາບ/) — CAC ທີ່ຈ່າຍຕໍ່ຜູ້ໃຊ້ທີ່ຢູ່ 12 ວັນບໍ່ສົ່ງມອບທັງ LTV ແລະ QALY. ແບບຈຳລອງເສດຖະກິດໃດສຳລັບຜະລິດຕະພັນສຸຂະພາບຜູ້ບໍລິໂພກທີ່ບໍ່ຖ່ວງນ້ຳໜັກປະໂຫຍດດ້ວຍເສັ້ນໂຄ້ງການຮັກສາຜູ້ໃຊ້ກຳລັງອະທິບາຍຜະລິດຕະພັນທີ່ບໍ່ມີຢູ່.

## ຄະນິດສາດ

```
Retention_Dn = users active on day n / cohort size × 100
Churn rate   = users lost in period / users at period start × 100

Benefit weighting (the health-economics move):
  expected benefit per acquired user = Σ_t retention(t) × benefit rate(t)
  ≈ area under the retention curve × per-time benefit
  — NOT trial benefit × 100% of acquired users

Cost per retained-at-D30 user = CAC / D30 retention
  (at 4% D30, a £5 CAC is really £125 per retained user)
```

## ຕົວຢ່າງການຄິດໄລ່

ແອັບສຸຂະພາບຈິດ: ການທົດລອງສະແດງ 0.02 QALY ຕໍ່ຜູ້ໃຊ້ທີ່ເຮັດສຳເລັດ 8 ອາທິດ. ກຸ່ມການນຳໃຊ້ 100,000 ດາວໂຫຼດ, ການຮັກສາຜູ້ໃຊ້ D7 25%, D30 8%, ອາທິດທີ 8 4%:

```
Completers          = 100,000 × 0.04 = 4,000
QALYs delivered     = 4,000 × 0.02 = 80  (not 100,000 × 0.02 = 2,000)
At £20,000/QALY     = £1.6M of health value (not £40M)

Per-download health value = £16 — the number that should set what a
payer will pay per download, and it is 4% of the naive claim.
Retention improvement case: moving week-8 completion 4% → 6% adds
40 QALYs/year ≈ £800k — retention engineering IS health production.
```

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ການຮັກສາຜູ້ໃຊ້ແມ່ນຕົວຊີ້ວັດທີ່ວິສະວະກຳຜະລິດຕະພັນສ້າງມູນຄ່າສຸຂະພາບໂດຍກົງທີ່ສຸດ, ຕາມເລກຂ້າງເທິງ. ການປະຕິບັດທີ່ເຄື່ອນມັນແມ່ນທຳມະດາ: ເວລາຈົນເຖິງມູນຄ່າທຳອິດຂອງການຕ້ອນຮັບ, ການອອກແບບການດຶງກັບມາມີສ່ວນຮ່ວມ, ປະສິດທິພາບ, ແລະ ສຳຄັນທີ່ສຸດ **ການສຳເລັດປະລິມານຕາມແຜນ** — ໂຄງການທີ່ມີຈຸດຈົບກຳນົດ (8 ອາທິດ, ແລ້ວຮຽນຈົບ) ຄວນວັດ *ການສຳເລັດ*, ບໍ່ແມ່ນ DAU ຕະຫຼອດໄປ, ປັບຕົວຊີ້ວັດໃຫ້ສອດຄ່ອງກັບແບບຈຳລອງຄລີນິກແທນແບບຈຳລອງຄວາມສົນໃຈທີ່ອີງໂຄສະນາ. ການວິເຄາະການລອດຊີວິດແມ່ນຊຸດເຄື່ອງມືທີ່ຖືກຕ້ອງ (ເລກ Kaplan-Meier ດຽວກັນກັບ [ປີຊີວິດທີ່ໄດ້ເພີ່ມ](../ປີຊີວິດທີ່ໄດ້ເພີ່ມ/)); ແບ່ງເສັ້ນໂຄ້ງຕາມຊ່ອງທາງການຫາຜູ້ໃຊ້, ເພາະສ່ວນປະສົມຊ່ອງທາງປ່ຽນການຮັກສາຜູ້ໃຊ້ຫຼາຍກວ່າຄຸນສົມບັດສ່ວນໃຫຍ່.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ການຟອກ intention-to-treat ແບບກົງກັນຂ້າມ**: ການທົດລອງລາຍງານຜູ້ເຮັດສຳເລັດ; ເສດຖະສາດການນຳໃຊ້ຕ້ອງນັບທຸກຄົນທີ່ຫາມາ (ຄຳເຕືອນຫຼັກຂອງ Eysenbach).
- **ລະຄອນການຮັກສາຜູ້ໃຊ້**: ຜູ້ໃຊ້ "ທີ່ໃຊ້ງານຢູ່" ທີ່ຖືກຂັບໂດຍການແຈ້ງເຕືອນແຕ່ບໍ່ເຄີຍເຮັດການກະທຳການຮັກສາ (ເບິ່ງ [ຕົວຊີ້ວັດການມີສ່ວນຮ່ວມ](../ຕົວຊີ້ວັດການມີສ່ວນຮ່ວມ/)).
- **ປຽບທຽບເສັ້ນໂຄ້ງຂ້າມນິຍາມ**: "ໃຊ້ງານຢູ່" ທີ່ນິຍາມເປັນການເປີດ ທຽບກັບການກະທຳທີ່ມີຄວາມໝາຍປ່ຽນ D30 ຫຼາຍເທົ່າ.
- **ເມີນເສີຍໃຜທີ່ຫຼຸດຫາຍ**: ຖ້າຄົນເຈັບປ່ວຍທີ່ສຸດຫຼຸດຫາຍໄວທີ່ສຸດ, ປະໂຫຍດຕໍ່ຜູ້ໃຊ້ຫຼຸດລົງເມື່ອການຮັກສາຜູ້ໃຊ້ປັບປຸງໃນກຸ່ມຄົນສຸຂະພາບດີ — ຈັບຄູ່ເສັ້ນໂຄ້ງກັບ case-mix (ເບິ່ງ [ການເຂົ້າເຖິງ ແລະ ຄວາມເທົ່າທຽມ](../ການເຂົ້າເຖິງ-ແລະ-ຄວາມເທົ່າທຽມ/)).
