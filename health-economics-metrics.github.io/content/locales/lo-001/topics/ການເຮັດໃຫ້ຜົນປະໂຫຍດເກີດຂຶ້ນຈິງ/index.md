# ການເຮັດໃຫ້ຜົນປະໂຫຍດເກີດຂຶ້ນຈິງ

ການຈັດການການເຮັດໃຫ້ຜົນປະໂຫຍດເກີດຂຶ້ນຈິງ (BRM) ແມ່ນລະບຽບວິໄນຂອງການກຳນົດ, ວາງພື້ນຖານ, ຕິດຕາມ ແລະ*ສະແດງຫຼັກຖານ*ວ່າຜົນປະໂຫຍດທີ່ສັນຍາໄວ້ໃນກໍລະນີທຸລະກິດເກີດຂຶ້ນຈິງຫຼັງການສົ່ງມອບ. ໃນການລົງທຶນສາທາລະນະຂອງອັງກິດ ມັນຢູ່ພາຍໃນ **Five Case Model** ຂອງ Green Book ຂອງ HM Treasury; ໃນການແພດ ຍາດພີ່ນ້ອງຂອງມັນຄືການເຝົ້າລະວັງຫຼັງອອກສູ່ຕະຫຼາດ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ກໍລະນີທຸລະກິດຄືຄຳສັນຍາ; ການເຮັດໃຫ້ຜົນປະໂຫຍດເກີດຂຶ້ນຈິງຄືການກວດສອບ. ການປະເມີນໂຄງການດິຈິຕອນຂະໜາດໃຫຍ່ຂອງ NHS ພົບຊ້ຳແລ້ວຊ້ຳອີກວ່າຜົນປະໂຫຍດທີ່ຄາດການບໍ່ເຄີຍເກີດຂຶ້ນ — ແລະ ເມື່ອຜົນປະໂຫຍດບໍ່ປົດປ່ອຍເງິນສົດ ມັນບໍ່ໄດ້ເຮັດຫຍັງໃຫ້ບັນຊີຂອງ trust. ຄຳຕອບຂອງ Green Book: ທຸກກໍລະນີການໃຊ້ຈ່າຍຕ້ອງຜ່ານ**ຫ້າກໍລະນີ** (ຍຸດທະສາດ, ເສດຖະກິດ, ການຄ້າ, ການເງິນ, ການຄຸ້ມຄອງ) ໂດຍວາງແຜນການເຮັດໃຫ້ຜົນປະໂຫຍດເກີດຂຶ້ນຈິງໃນກໍລະນີການຄຸ້ມຄອງ*ກ່ອນອະນຸມັດ* — ມີການລະບຸເຈົ້າຂອງ, ເກັບພື້ນຖານ, ກຳນົດວັນວັດ. ຖ້າບໍ່ມີສິ່ງນີ້ "ຊອບແວປະຢັດ 30 ນາທີຕໍ່ພະຍາບານ" ຈະເປັນນິຍາຍຂອງຜູ້ຂາຍຕະຫຼອດໄປ.

## ຄະນິດສາດ

```
Realization rate = benefits realized / benefits forecast   (per benefit, per period)

Mechanics that make it computable:
  baseline captured BEFORE go-live (else the delta is unmeasurable)
  each benefit: owner, metric, data source, measurement schedule
  forecast adjusted for optimism bias at appraisal (Green Book mandate)
  benefits classed cash / non-cash / qualitative and tracked separately
  (see cash-releasing-vs-non-cash-releasing.md)
```

## ຕົວຢ່າງການຄິດໄລ່

ກໍລະນີທຸລະກິດການຈັດຕາຕະລາງເວນດ້ວຍລະບົບອີເລັກໂທຣນິກສັນຍາໄວ້ຕໍ່ປີ: ຫຼຸດລາຍຈ່າຍບຸກຄະລາກອນຈ້າງຊົ່ວຄາວ £450k (ເງິນສົດ), 8,000 ຊົ່ວໂມງຂອງຜູ້ຈັດການຫວອດ (ຄວາມສາມາດ), ການປະຕິບັດຕາມອັດຕາເຕີມເວນທີ່ດີຂຶ້ນ (ດ້ານຄຸນນະພາບ). 12 ເດືອນຫຼັງເປີດໃຊ້:

```
Benefit           Forecast    Realized    Rate   Evidence
Agency spend      £450,000    £287,000    64%    ledger vs baseline year
Manager hours     8,000       5,100       64%    time-motion sample
Fill compliance   +10pp       +12pp       120%   rostering system data

Actions from the review (the point of BRM):
agency shortfall traced to two wards never onboarded → onboard them;
forecast model's 30%-optimism error logged → applied to the next case.
```

ການບັນລຸ 64% ບໍ່ແມ່ນຄວາມລົ້ມເຫຼວ — ມັນແມ່ນ*ຄວາມຮູ້*. ກໍລະນີທີ່ບໍ່ໄດ້ວັດອ້າງ 100% ຕະຫຼອດໄປ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ອົງກອນວິສະວະກຳອະນຸມັດການລົງທຶນແພລດຟອມຈາກຜົນປະໂຫຍດທີ່ຄາດການ ແລະ ເກືອບບໍ່ເຄີຍກວດສອບ — ພະຍາດທີ່ BRM ແກ້ໄຂ. ການນຳມາໃຊ້ແບບເບົາ: ທຸກຂໍ້ສະເໜີເໜືອເກນຕ້ອງລະບຸເຈົ້າຂອງຜົນປະໂຫຍດ, ຕົວຊີ້ວັດພື້ນຖານ, ແລະ ວັນທົບທວນ T+6 ເດືອນ; ອັດຕາການບັນລຸສົ່ງຄືນເຂົ້າໄປໃນວ່າອົງກອນຫຼຸດທອນການຄາດການຄັ້ງຕໍ່ໄປຂອງທີມ (ຫຼື ຜູ້ຂາຍ) ນັ້ນເທົ່າໃດ. ນີ້ຍັງເປັນຄຳຕອບຕໍ່ຄວາມສົງໄສເລື່ອງເຄື່ອງມື AI: [ຜົນຄົ້ນພົບຂອງ MIT ທີ່ວ່າ ~95% ຂອງໂຄງການທົດລອງ GenAI ບໍ່ສະແດງຜົນຕອບແທນ P&L ທີ່ວັດໄດ້](../ຜົນຕອບແທນຈາກການລົງທຶນໃນ-ai/)ແມ່ນຜົນຂອງການເຮັດໃຫ້ຜົນປະໂຫຍດເກີດຂຶ້ນຈິງ — ໂຄງການທົດລອງທີ່*ໃຫ້*ຜົນຕອບແທນມີແຖວຜົນປະໂຫຍດທີ່ຕິດຕາມໄດ້ແລະມີເຈົ້າຂອງ. ຄາດການ → ວັດ → ປັບທຽບໃໝ່ ແມ່ນວົງຈອນດຽວກັນກັບການທົດລອງທີ່ຕີລາຄາດ້ວຍ [EVPI](../ມູນຄ່າທີ່ຄາດໄວ້ຂອງຂໍ້ມູນສົມບູນແບບ/) ແຕ່ດຳເນີນໃນລະດັບພອດໂຟລິໂອ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ບໍ່ມີພື້ນຖານກ່ອນເປີດໃຊ້** — ການຂາດຕົກບົກຜ່ອງທີ່ຮ້າຍແຮງແລະແກ້ບໍ່ໄດ້.
- **ຜົນປະໂຫຍດກຳພ້າ**: ບໍ່ມີເຈົ້າຂອງທີ່ມີຊື່ ໝາຍຄວາມວ່າບໍ່ມີໃຜເກັບຂໍ້ມູນ ແລະ ທຸກການທົບທວນເວົ້າວ່າ "ໂດຍລວມເປັນໄປຕາມແຜນ."
- **ຜົນປະໂຫຍດທີ່ນັບຊ້ຳຂ້າມໂຄງການ** ທີ່ອ້າງຄວາມສາມາດທີ່ປົດປ່ອຍອັນດຽວກັນ — ຮັກສາທະບຽນຜົນປະໂຫຍດຂ້າມພອດໂຟລິໂອ.
- **ລະຄອນການບັນລຸ**: ວັດຜົນສຳເລັດດ້ານຄຸນນະພາບທີ່ງ່າຍ ໃນຂະນະທີ່ແຖວເງິນສົດຖືກປະຖິ້ມໂດຍບໍ່ກວດ.
