# ຕົ້ນທຶນສ່ວນເພີ່ມ ທຽບກັບ ຕົ້ນທຶນສະເລ່ຍ

ຕົ້ນທຶນສະເລ່ຍແມ່ນຕົ້ນທຶນລວມຫານດ້ວຍຈຳນວນຫົວໜ່ວຍທີ່ຜະລິດ. ຕົ້ນທຶນສ່ວນເພີ່ມແມ່ນຕົ້ນທຶນຂອງການຜະລິດຫົວໜ່ວຍ *ເພີ່ມອີກໜຶ່ງ*. ການຕັດສິນໃຈຄວນອີງໃສ່ຕົ້ນທຶນສ່ວນເພີ່ມ — ແຕ່ຕົ້ນທຶນຫົວໜ່ວຍທີ່ເຜີຍແຜ່ເກືອບສະເໝີເປັນຄ່າສະເລ່ຍ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ຂໍ້ຜິດພາດທີ່ພົບທົ່ວໄປທີ່ສຸດໃນ business case ສຸຂະພາບດິຈິຕອນ ແມ່ນການປະເມີນຊັບພະຍາກອນທີ່ປະຢັດດ້ວຍຕົ້ນທຶນ **ສະເລ່ຍ** ໃນຂະນະທີ່ການປະຢັດຈິງແມ່ນຕົ້ນທຶນ **ສ່ວນເພີ່ມ**. ວັນນອນໂຮງໝໍມີຕົ້ນທຶນສະເລ່ຍ (ດູດຊຶມເຕັມ) £400+, ແຕ່ການປົດປ່ອຍໜຶ່ງວັນນອນບໍ່ໄດ້ປະຢັດ £400 — ອາຄານ, ຄວາມຮ້ອນ ແລະ ຕົ້ນທຶນບຸກຄະລາກອນສ່ວນໃຫຍ່ຍັງດຳເນີນຕໍ່. ເງິນສົດທີ່ປົດປ່ອຍຈິງອາດເປັນ £50–£150 ເວັ້ນເສຍແຕ່ວ່າຕຽງທີ່ປົດປ່ອຍມີພຽງພໍທີ່ຈະປິດຕຶກຜູ້ປ່ວຍທັງໝົດ.

## ຄະນິດສາດ

```
Average cost:  AC = TC / Q
Marginal cost: MC = dTC/dQ   (cost of one more/one fewer unit)

TC = total cost, Q = quantity
```

ຕົ້ນທຶນຄົງທີ່ເຮັດໃຫ້ MC < AC ສຳລັບການຫຼຸດຄວາມຈຸ, ແລະ MC ອາດເຂົ້າໃກ້ສູນເມື່ອມີຄວາມຈຸເຫຼືອ. ການອ້າງການປະຢັດຄວນໃຊ້:

```
True saving = ΔQ × MC          (small changes)
True saving = step change in TC (large changes that cross a capacity threshold, e.g. closing a ward)
```

## ຕົວຢ່າງການຄິດໄລ່

ຊອບແວຂອງທ່ານຫຼຸດໄລຍະເວລານອນສະເລ່ຍ, ປົດປ່ອຍ 1,000 ວັນນອນ/ປີ ທີ່ທຣັສໜຶ່ງ.

- **ການອ້າງແບບໄຮ້ດຽງສາ**: 1,000 × £400 ຕົ້ນທຶນສະເລ່ຍ = **ປະຢັດ £400,000**. ຜິດ.
- **ການອ້າງແບບສ່ວນເພີ່ມ**: ຕົ້ນທຶນຜັນແປຕໍ່ວັນນອນ (ອາຫານ, ຊັກລີດ, ວັດສະດຸສິ້ນເປືອງ, ພະຍາບານຍືດຫຍຸ່ນບາງສ່ວນ) ≈ £120. ການປະຢັດ = 1,000 × £120 = **£120,000**, *ບວກ* ມູນຄ່າຂອງຄວາມຈຸທີ່ປົດປ່ອຍ ຖ້າຕຽງຖືກເຕີມໃໝ່ດ້ວຍຜູ້ປ່ວຍນັດໝາຍທີ່ລໍຖ້າ (ລາຍໄດ້ພາຍໃຕ້ການຈ່າຍຕາມກິດຈະກຳ, ຫຼື ການຫຼຸດລາຍຊື່ລໍຖ້າ).
- **ການອ້າງແບບປ່ຽນຂັ້ນ**: ຖ້າທຣັສປົດປ່ອຍ 7,300 ວັນນອນ/ປີ (ຕຶກຜູ້ປ່ວຍ 20 ຕຽງ) ມັນສາມາດປິດຕຶກໄດ້ຈິງ: ບຸກຄະລາກອນ + ການດຳເນີນງານ ≈ £1.5 ລ້ານ/ປີເປັນເງິນສົດຈິງ. ຕອນນີ້ເລກຕົ້ນທຶນສະເລ່ຍໃກ້ຄວາມຈິງກວ່າ.

ການແຊກແຊງດຽວກັນ, ສາມຕົວເລກທີ່ປົກປ້ອງໄດ້, ຂຶ້ນກັບວ່າການປ່ຽນແປງຂ້າມຂັ້ນຄວາມຈຸຫຼືບໍ່.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ເສດຖະສາດຄລາວແມ່ນດິນແດນຂອງຕົ້ນທຶນສ່ວນເພີ່ມໂດຍກຳເນີດ:

- ຕົ້ນທຶນສ່ວນເພີ່ມຂອງການຣັນ CI ອີກໜຶ່ງຄັ້ງເທິງຄວາມຈຸທີ່ຈອງໄວ້ແລ້ວ ≈ £0, ໃນຂະນະທີ່ຕົ້ນທຶນສະເລ່ຍຕໍ່ການຣັນ (ລາຍຈ່າຍແພລດຟອມທັງໝົດ ÷ ຈຳນວນຣັນ) ອາດເປັນຫຼາຍປອນ. ລະບົບເກັບເງິນຄືນທີ່ເກັບຕາມຕົ້ນທຶນສະເລ່ຍຂັບໃຫ້ທີມໃຊ້ຄວາມຈຸຮ່ວມກັນຕ່ຳເກີນໄປ ທັງທີ່ມັນຟຣີແທ້ທີ່ຂອບ.
- ໃນທາງກົງກັນຂ້າມ, "ເຮົາປະຢັດຄອມພິວ 30%" ປົດປ່ອຍເງິນສົດກໍຕໍ່ເມື່ອອິນສະແຕນຖືກຢຸດຈິງ ຫຼື ການຈອງຖືກຫຼຸດ — ຮຸ່ນຊອບແວຂອງກັບດັກວັນນອນ. ເບິ່ງ [ການປະຢັດທີ່ປົດປ່ອຍເງິນສົດ ທຽບກັບ ທີ່ບໍ່ປົດປ່ອຍເງິນສົດ](../ການປະຢັດທີ່ປົດປ່ອຍເງິນສົດ-ທຽບກັບ-ທີ່ບໍ່ປົດປ່ອຍເງິນສົດ/).

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ປະເມີນຄວາມຈຸດ້ວຍຕົ້ນທຶນສະເລ່ຍ** ແລ້ວນຳສະເໜີເປັນເງິນສົດ (ຕົວຢ່າງຄລາສສິກ).
- **ສົມມຸດວ່າຕົ້ນທຶນສ່ວນເພີ່ມຄົງທີ່.** ມັນປ່ຽນເປັນຂັ້ນທີ່ຂອບເຂດຄວາມຈຸ (ການປິດຕຶກ, ລະດັບໃບອະນຸຍາດ, ພັນທະອິນສະແຕນທີ່ຈອງໄວ້).
- **ໃຊ້ຕົ້ນທຶນສ່ວນເພີ່ມສຳລັບການຕັດສິນໃຈຂະຫຍາຍແຕ່ໃຊ້ສະເລ່ຍສຳລັບການຫຼຸດ** ໃນກໍລະນີດຽວກັນ — ເລືອກຕາມການຕັດສິນໃຈຈິງ.
