# WSJF و CD3

CD3 (هزینه تأخیر تقسیم بر مدت) و WSJF (کوتاه‌ترین کار وزنی اول) قواعد اولویت‌بندی‌اند که کار را بر اساس **چگالی ارزش** زمان‌بندی می‌کنند: چه مقدار هزینه تأخیر به ازای هر واحد ظرفیت کمیاب مصرف‌شده حذف می‌شود. تحت ظرفیت مشترک و ثابت، بالاترین-CD3-اول توالی بهینه ریاضی برای کمینه کردن کل هزینه تأخیر است.

## چرا اهمیت دارد

هر بک‌لاگ یک مسئله سهمیه‌بندی است: آیتم‌های شایسته بسیار، یک خط تحویل. اقتصاد سلامت همین مسئله را برای بودجه‌های سلامت با جدول‌های رده‌بندی هزینه-اثربخشی حل کرد — مداخلات را بر اساس سلامت به‌دست‌آمده به ازای هر پوند رتبه دهید، تا اتمام بودجه از بالای فهرست تأمین مالی کنید. CD3 همان منطق برای ظرفیت تحویل است: منفعت به ازای هر واحد *منبع محدود*، به ترتیب رتبه تأمین‌شده. درست کردن توالی پول مفت است — همان کار، همان ظرفیت، کل هزینه تأخیر کمتر.

## ریاضیات

```
CD3  = Cost of Delay (£/week) / Duration (weeks)      — real units (Black Swan Farming)

WSJF = (user-business value + time criticality + risk reduction/opportunity
        enablement) / job size                         — SAFe's relative-scale proxy,
                                                        modified-Fibonacci scores
```

CD3 با واحد پولی واقعی ([هزینه تأخیر](../هزینه-تأخیر/)) اکیداً قوی‌تر از امتیازهای بی‌واحد WSJF است — WSJF برای CD3 همان است که امتیازدهی چندمعیاره برای [تحلیل هزینه-مطلوبیت](../تحلیل-هزینه-مطلوبیت/) کامل: وقتی پولی‌سازی ناعملی است قابل‌استفاده، وقتی امتیازها لنگری ندارند دستکاری‌پذیر.

## مثال حل‌شده

سه قابلیت، یک تیم:

```
Feature   CoD (£/wk)   Duration   CD3
A         30,000       10 wks     3,000
B         12,000       2 wks      6,000
C         5,000        1 wk       5,000
```

ترتیب CD3: B، C، A. کل هزینه تأخیر را با «بزرگ‌ترین CoD اول» (A، B، C) مقایسه کنید:

```
CD3 order  (B,C,A): A waits 3 wks, C waits 2 → 30k×3 + 5k×2  = £100k delay cost
CoD order  (A,B,C): B waits 10, C waits 12   → 12k×10 + 5k×12 = £180k
```

همان قابلیت‌ها، همان تیم — توالی به‌تنهایی £80,000 صرفه‌جویی می‌کند. شهود: آیتم‌های کوچک و فوری ابتدا می‌روند چون هزینه تأخیرشان را ارزان آزاد می‌کنند؛ آیتم بزرگ با انتظار کوتاه چیز کمی از دست می‌دهد.

## ارتباط با مهندسی نرم‌افزار

برای سبدهای نرم‌افزار سلامت، CoD را در واحدهایی بیان کنید که این مخزن می‌آموزد: QALY/هفته × آستانه + £/هفته عملیاتی، و بک‌لاگ مستقیماً با نحوه رتبه‌بندی هر چیز دیگر که نظام سلامت می‌خرد قابل‌قیاس می‌شود. دو نکته عملی: (1) مدت یعنی *زمان تقویمی اشغال محدودیت*، نه تلاش — آیتم 2 هفته سپری‌شده که 2 روز تیم گلوگاه را می‌خواهد ارزان‌تر از ظاهرش است (به [بهینه‌سازی منابع پایین‌دست](../بهینه-سازی-منابع-پایین-دست/) نگاه کنید)؛ (2) بیمارستان‌ها همین قاعده را ضمنی اجرا می‌کنند وقتی فهرست‌های اتاق عمل را بر اساس توان عملیاتی وزن‌دهی‌شده با فوریت مرتب می‌کنند — رده‌های اولویت بالینی CD3 وزن‌دهی‌شده با شدت‌اند (به [کمبود QALY و تعدیل‌کننده‌های شدت](../کمبود-qaly-و-تعدیل-کننده-های-شدت/) نگاه کنید).

## تله‌ها و اشتباهات رایج

- **نمایش امتیاز WSJF**: بحث‌های فیبوناچی بی‌واحد به سمت هر که بلندتر استدلال کند همگرا می‌شوند؛ دست‌کم آیتم‌های بالای بک‌لاگ را در CoD واقعی لنگر بیندازید.
- **دستکاری مدت**: شکستن آیتم‌ها برای باد کردن رتبه CD3 — وقتی شکست‌ها ارزش را مستقل تحویل دهند مشکلی نیست، وقتی ندهند تقلب است.
- **نادیده گرفتن نمایه‌های فوریت**: CoD شکل مهلت (تاریخ‌های مقرراتی) فرض نرخ ثابت را می‌شکند؛ آنها را با امکان‌سنجی تاریخ زمان‌بندی کنید، سپس بقیه را CD3 کنید.
- **ریزش رتبه‌بندی مجدد**: CD3 برای تصمیم‌های توالی در زمان تعهد است، نه جابه‌جایی روزانه کار در جریان (درباره WIP به [معیارهای جریان](../معیارهای-جریان/) نگاه کنید).
