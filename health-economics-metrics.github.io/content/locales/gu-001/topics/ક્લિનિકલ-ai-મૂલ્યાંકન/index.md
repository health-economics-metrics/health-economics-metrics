# ક્લિનિકલ AI મૂલ્યાંકન

ક્લિનિકલ AI કે નિદાન મૉડેલના મૂલ્યાંકન માટેના મુખ્ય આંકડા: સંવેદનશીલતા, વિશિષ્ટતા, AUROC, આગાહી મૂલ્યો અને સ્ક્રીનિંગ માટે જરૂરી સંખ્યા. કેન્દ્રીય આર્થિક પાઠ: **ઉત્તમ AUROC ખર્ચ-અસરકારક ડિપ્લોયમેન્ટ બનાવતું નથી** — મૂલ્ય ઑપરેટિંગ બિંદુ, વ્યાપ અને દરેક હકારાત્મક પછી ડાઉનસ્ટ્રીમમાં શું થાય છે તેના પર આધાર રાખે છે.

## આ શા માટે મહત્ત્વનું છે

નિયામકો (FDA, MHRA) ક્લિનિકલ AI ને **લૉક કરેલા ઑપરેટિંગ બિંદુ** પર અધિકૃત કરે છે — ચોક્કસ સંવેદનશીલતા/વિશિષ્ટતા જોડ (દા.ત., પ્રથમ FDA-ક્લિયર સ્વાયત્ત ડાયાબિટીક-રેટિનોપેથી સિસ્ટમ: તેના મુખ્ય ટ્રાયલમાં સંવેદનશીલતા 87.2%, વિશિષ્ટતા 90.7%). આરોગ્ય અર્થશાસ્ત્રીઓ પછી એ પ્રશ્ન પૂછે છે જેનો ચોકસાઈ મેટ્રિક્સ જવાબ આપી શકતા નથી: તમારી ડિપ્લોયમેન્ટ વસ્તીના વ્યાપ પર, દરેક શોધનો *ખર્ચ* કેટલો છે, અને તેના પર પગલાં લેવા યોગ્ય છે? રેટિનોપેથી-સ્ક્રીનિંગ AI ના આર્થિક મૂલ્યાંકન (npj Digital Medicine 2024) એ દર્શાવ્યું કે રેફરલ ખર્ચ ગણતાં ફક્ત ઊંચી ચોકસાઈ ખર્ચ-અસરકારકતાની ખાતરી આપતી નથી.

## ગણિત

```
Sensitivity = TP / (TP + FN)        — of the truly positive, share caught
Specificity = TN / (TN + FP)        — of the truly negative, share cleared
AUROC       = P(model ranks a random positive above a random negative)
              0.5 chance … 1.0 perfect; threshold-independent — and therefore
              deployment-decision-insufficient

PPV = TP / (TP + FP)   ← prevalence-dependent (Bayes); collapses when rare
NPV = TN / (TN + FN)

NNS  ≈ 1 / (prevalence × sensitivity)       — screened per true case found
Cost per true case = programme cost / TP      — the economic bottom line
```

## ઉકેલેલું ઉદાહરણ

એ જ મૉડેલ, બે સેટિંગ — સંવેદનશીલતા 90%, વિશિષ્ટતા 93%:

```
Specialist clinic (prevalence 20%):
  PPV = (0.9×0.2)/(0.9×0.2 + 0.07×0.8) = 0.18/0.236 ≈ 76%  → 3 in 4 alerts real

Primary care (prevalence 1%):
  PPV = (0.9×0.01)/(0.9×0.01 + 0.07×0.99) = 0.009/0.0783 ≈ 11.5%
  → 8 in 9 alerts false; workup at £350 each:
  cost per true case = (0.009 + 0.0693) × 350 / 0.009 ≈ £3,045 per case found
```

સમાન મૉડેલ, મૂળભૂત રીતે અલગ અર્થશાસ્ત્ર — એટલે જ સાઇટ-વિશિષ્ટ મૂલ્યાંકન નિયામક વિષય છે અને "અમારા મૉડેલનો AUROC 0.95 છે" આર્થિક કેસની શરૂઆત છે, અંત નહીં. સંપૂર્ણ કાર્યક્રમ ગણિત માટે [સ્ક્રીનિંગ અર્થશાસ્ત્ર](../સ્ક્રીનિંગ-અર્થશાસ્ત્ર/) જુઓ.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

ક્લિનિકલ AI બનાવતા કે ખરીદતા એન્જિનિયરો માટે: ફક્ત ROC વક્ર નહીં, **ડિપ્લોયમેન્ટ વ્યાપ પર કન્ફ્યુઝન મૅટ્રિક્સ મોકલો**; **સીમાને આર્થિક નિર્ણય બનવા દો** — sens/spec સમાધાન અપેક્ષિત ખર્ચ ઘટાડે (ચૂકેલા કેસ × ચૂકનો ખર્ચ વિરુદ્ધ ખોટા એલાર્મ × વર્કઅપ ખર્ચ), બેન્ચમાર્ક આંકડો મહત્તમ ન કરે; અને તમારા પોતાના ટૂલિંગમાં એ જ ગણિત ઓળખો — ચેતવણી સિસ્ટમ્સ, વિસંગતતા શોધકો અને સુરક્ષા સ્કૅનર્સ નીચા-વ્યાપ ઘટના પ્રવાહો પરના નિદાન પરીક્ષણો છે, જેમાં ચેતવણી થાક [NNH](../સારવાર-માટે-જરૂરી-સંખ્યા/) છે. ઑપરેટિંગ બિંદુ ખસેડતા મૉડેલ અપડેટ્સ અર્થશાસ્ત્ર (અને નિયામક ક્લિયરન્સ — જુઓ [AI નિયામક મૂલ્યાંકન](../ai-નિયામક-મૂલ્યાંકન/)) ફરી ખોલે છે.

## સામાન્ય ભૂલો

- **AUROC ખરીદી**: જે મૉડેલ એક સીમા પર ચાલશે તેમની AUROC પર સરખામણી — ઑપરેટિંગ બિંદુ પર સરખાવો.
- **વાસ્તવિક-વિશ્વ ડિપ્લોયમેન્ટ માટે ટ્રાયલ-વ્યાપ PPV ટાંકવો** — ક્લાસિક; હંમેશા સ્થાનિક વ્યાપ પર ફરી ગણો.
- **સ્પેક્ટ્રમ પૂર્વગ્રહ**: સ્પષ્ટ કેસ વિરુદ્ધ સ્વસ્થ નિયંત્રણો પર માન્ય થયેલા મૉડેલ તે અસ્પષ્ટ મધ્યમાં નબળાં પડે છે જે વ્યવહારમાં પ્રભુત્વ ધરાવે છે.
- **ડાઉનસ્ટ્રીમ માર્ગ ખર્ચ નહીં**: દરેક હકારાત્મક વર્કઅપ ઊભો કરે છે; મૉડેલ *સમગ્ર માર્ગના* અર્થશાસ્ત્ર પર હસ્તક્ષેપ છે.
