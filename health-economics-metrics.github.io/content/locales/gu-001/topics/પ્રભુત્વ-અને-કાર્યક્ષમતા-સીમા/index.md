# પ્રભુત્વ અને કાર્યક્ષમતા સીમા

જો બીજો વિકલ્પ ઓછો ખર્ચ કરે *અને* વધુ આપે, તો વિકલ્પ **પ્રભાવિત** (dominated) છે. **કાર્યક્ષમતા સીમા** એ છે જે પ્રભાવિત વિકલ્પો દૂર કર્યા પછી બાકી રહે: પસંદગીઓનો સમૂહ જ્યાં વધુ મેળવવા માટે વધુ ચૂકવવું પડે.

## આ શા માટે મહત્ત્વનું છે

સીમાઓ કે બજેટ અંગેની કોઈપણ ચર્ચા પહેલાં, આરોગ્ય ટેકનોલોજી મૂલ્યાંકન પહેલાં એવા વિકલ્પો દૂર કરે છે જે કોઈએ ક્યારેય પસંદ ન કરવા જોઈએ. દરેક વિકલ્પને ખર્ચ-વિરુદ્ધ-અસર સમતલ પર આલેખવો અને સીમા દોરવી એ પાંચ-મિનિટની કવાયત છે જે નિયમિતપણે અડધી શૉર્ટલિસ્ટ મારી નાખે છે. વૃદ્ધિશીલ સરખામણીઓ ([ICER](../વૃદ્ધિશીલ-ખર્ચ-અસરકારકતા-ગુણોત્તર/)) પછી ફક્ત *સીમા સાથે* ગણાય છે, દરેક વિકલ્પ આગામી-સૌથી-સસ્તા અપ્રભાવિત વિકલ્પ સામે — જ્યારે વધુ સારા મધ્યવર્તી વિકલ્પો હોય ત્યારે ક્યારેય "કંઈ ન કરવા" સામે નહીં.

## ગણિત

```
Strict dominance:   A dominates B if Cost_A ≤ Cost_B and Effect_A ≥ Effect_B
                    (with at least one strict inequality)

Extended dominance: B is ruled out if a mix of A and C achieves more effect
                    per pound — detected when ICERs decrease as you move up
                    the frontier. Valid frontier ICERs must be increasing.
```

પ્રક્રિયા: વિકલ્પોને અસર દ્વારા ગોઠવો; કડક રીતે પ્રભાવિત દૂર કરો; પડોશીઓ વચ્ચે જોડીવાર ICER ગણો; જેનો ICER આગામી વધુ-અસરકારક વિકલ્પ કરતાં વધે તે કોઈપણ વિકલ્પ દૂર કરો (વિસ્તૃત પ્રભુત્વ); ICER એકસૂત્રી રીતે વધે ત્યાં સુધી પુનરાવર્તન કરો.

## ઉકેલેલું ઉદાહરણ

ચૂકેલી એપૉઇન્ટમેન્ટ ઘટાડવાના ચાર વિકલ્પો (અસર = વર્ષે પાછી મળેલી એપૉઇન્ટમેન્ટ):

```
Option          Cost/yr    Recovered
Do nothing      £0         0
SMS reminders   £20,000    2,000
Phone calls     £120,000   2,200
SMS + AI triage £90,000    3,500
```

ફોન કૉલ્સ SMS + AI ટ્રાયેજ દ્વારા **કડક રીતે પ્રભાવિત** છે (વધુ ખર્ચ, ઓછું પાછું). સીમા: કંઈ નહીં → SMS → SMS + AI.

```
ICER(SMS vs nothing)   = 20,000 / 2,000  = £10 per appointment recovered
ICER(SMS+AI vs SMS)    = (90,000 − 20,000) / (3,500 − 2,000) = £46.67 per appointment
```

વધતા ICER → માન્ય સીમા. પાછી મળેલી હૉસ્પિટલ એપૉઇન્ટમેન્ટ દીઠ ~£160 બચત પર ([હાજર ન રહેવાનો દર](../હાજર-ન-રહેવાનો-dna-દર/) જુઓ), સીમાનાં બંને પગલાં લેવા યોગ્ય છે; ફોન-બૅંક દરખાસ્ત ક્યારેય સમિતિ સુધી પહોંચવી ન જોઈએ.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

કોઈપણ ટૂલિંગ નિર્ણય માટે એ જ ચાર્ટ બનાવો: એક અક્ષ પર વર્ષ દીઠ ખર્ચ, બીજા પર માપેલું પરિણામ (બચેલા કલાકો, ટાળેલી ઘટનાઓ, સક્ષમ ડિપ્લોય). સીમાની ઉપર-ડાબેના બિંદુઓ કોઈ બજેટ પર દલીલ કરે તે પહેલાં દૂર થાય છે. આ વેન્ડર પસંદગીને સુવિધા-ચેકલિસ્ટ ચર્ચાઓમાંથી "તમે પ્રભાવિત છો; મીટિંગ પૂરી" તરફ ફરી ઘડે છે. તે સીમાંત લાભ માટે સૌથી મોંઘો વિકલ્પ ખરીદવાની સામાન્ય એન્ટરપ્રાઇઝ પેટર્નને પણ ખુલ્લી પાડે છે — ફક્ત ત્યારે જ યોગ્ય જો વૃદ્ધિશીલ એકમ દીઠ વૃદ્ધિશીલ ભાવ એવો હોય જે સંસ્થા જાણી-જોઈને ચૂકવે.

## સામાન્ય ભૂલો

- **દરેક વસ્તુની આધારરેખા સાથે સરખામણી** સીમા પરના આગામી વિકલ્પને બદલે — તે સસ્તા લગભગ-સમકક્ષ વિકલ્પો છુપાવીને મોંઘા વિકલ્પોની ખુશામત કરે છે.
- **એક-પરિમાણીય અસર ગુણાંક** જે મહત્ત્વનું છે તે છુપાવે છે; જો બે પરિણામો ગણાય, તો કાં તેમને બચાવી શકાય તેવી રીતે જોડો ([ખર્ચ-ઉપયોગિતા વિશ્લેષણ](../ખર્ચ-ઉપયોગિતા-વિશ્લેષણ/) જુઓ) અથવા બે સીમાઓ બતાવો.
- **અનિશ્ચિતતા ભૂલવી**: સીમા નજીકના વિકલ્પો [સંવેદનશીલતા વિશ્લેષણ](../સંવેદનશીલતા-વિશ્લેષણ/) હેઠળ સ્થાન બદલી શકે છે.
