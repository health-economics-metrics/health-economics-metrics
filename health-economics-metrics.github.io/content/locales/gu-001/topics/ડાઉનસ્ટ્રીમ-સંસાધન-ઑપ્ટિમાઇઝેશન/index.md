# ડાઉનસ્ટ્રીમ સંસાધન ઑપ્ટિમાઇઝેશન

વરિષ્ઠ પ્રૅક્ટિશનર — GP, વરિષ્ઠ રજિસ્ટ્રાર, કન્સલ્ટન્ટ — માટે એક કલાક બચાવવાથી ઘણી વાર ક્લિનિકલ સહીઓની રાહ જોતા નર્સો, વહીવટી કારકુનો અને થેરાપિસ્ટ્સની સમગ્ર બહુ-શાખા ટીમ (MDT) માટે અવરોધ વિલંબ અટકે છે. અવરોધ ખોલવાનું મૂલ્ય તેની પાછળના દરેકનો થ્રુપુટ છે.

## આ શા માટે મહત્ત્વનું છે

આરોગ્ય સંભાળ અધિકૃતિ સાંકળો પર ચાલે છે: રજાઓ કન્સલ્ટન્ટ સહીની રાહ જુએ છે, સારવાર યોજનાઓ MDT સમીક્ષાની રાહ જુએ છે, રેફરલ ટ્રાયેજની રાહ જુએ છે. જ્યારે દ્વારપાળ ભૂમિકા વિલંબિત થાય, ત્યારે ખર્ચ એક વ્યક્તિનો કલાક નથી — તે દરેક આશ્રિત ભૂમિકામાં નિષ્ક્રિય કે અવરોધિત સમય છે, ઉપરાંત અધવચ્ચે લટકતા દર્દીનો સમય (વધારાના [પથારી-દિવસો](../બચાવેલા-પથારી-દિવસો/), લાંબી [RTT પ્રતીક્ષા](../રેફરલથી-સારવાર/)). આ ક્લિનિકલ માર્ગો પર લાગુ અવરોધોનો સિદ્ધાંત છે: *અવરોધ પર* બચાવેલો કલાક આખી પ્રણાલીના સીમાંત થ્રુપુટ જેટલો મૂલ્યવાન છે; બીજે બચાવેલો કલાક ઘણો ઓછો.

## ગણિત

```
Value of unblocking = Σ over downstream roles (blocked hours released × unit cost)
                    + pathway throughput gain × value per pathway completion

Contrast: value of the same hour saved at a non-gating role ≈ that role's
capacity value alone (see practitioner-time.md).
```

પ્રયોગમૂલક રીતે અવરોધ ઓળખો: કામ ક્યાં સૌથી લાંબું કતારમાં રહે છે? વિલંબ કોના ઇનબૉક્સ સુધી પાછા જાય છે?

## ઉકેલેલું ઉદાહરણ

વૉર્ડની રજાઓને દરરોજ સવારે કન્સલ્ટન્ટ સમીક્ષા જોઈએ. કન્સલ્ટન્ટ દરરોજ 90 મિનિટ પ્રણાલીઓમાં વેરાયેલી માહિતી ભેગી કરવામાં ગાળે છે; સમીક્ષા 14:00 સુધીમાં પૂરી થાય છે, અને દરરોજ 6 રજાઓ તે દિવસ માટે મોડી પૂરી થાય છે — દરેક એક ટાળી શકાય તેવો પથારી-દિવસ ખર્ચે છે.

રજા-સારાંશ ડૅશબોર્ડ (લેબ્સ, દવાઓ, ફ્લૅગ્સ એક દૃશ્યમાં) ભેગું કરવાનું 20 મિનિટ કરે છે; સમીક્ષા 11:30 સુધીમાં પૂરી થાય છે:

```
Bed days avoided     = 4 of the 6 late discharges × 365 ≈ 1,460 bed days/year
Downstream unblocking: 2 discharge coordinators + pharmacy + transport
                       previously idle-then-crunched each afternoon —
                       ~3 staff-hours/day of blocked time released ≈ 1,100 hrs/yr
```

કન્સલ્ટન્ટની પોતાની 70 મિનિટ મૂલ્યનો *સૌથી નાનો* ભાગ છે — આ મેટ્રિકનો મુદ્દો. પથારી-દિવસોનું મૂલ્ય પદ્ધતિ મુજબ આંકો ([બચાવેલા પથારી-દિવસો](../બચાવેલા-પથારી-દિવસો/) જુઓ) અને સ્ટાફ કલાકોને ક્ષમતા તરીકે.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

આ કોડ રિવ્યૂ, આર્કિટેક્ચર સાઇન-ઑફ અને સ્ટાફ એન્જિનિયરનું ઇનબૉક્સ છે. જ્યારે ડિઝાઇન મંજૂર કરી શકે તેવા એક વ્યક્તિ માટે પાંચ એન્જિનિયરો એક દિવસ રાહ જુએ, ત્યારે ખર્ચ પાંચ એન્જિનિયર-દિવસ ઉપરાંત કામ પર જ એક દિવસની [વિલંબની કિંમત](../વિલંબની-કિંમત/) છે — એક રિવ્યૂઅર-કલાક નહીં. દ્વારપાળ ભૂમિકાનું કાર્ય સંકોચતું ટૂલિંગ (સારો રિવ્યૂ સંદર્ભ, સ્વચાલિત પૂર્વ-તપાસ, મંજૂર કરનારને જે જોઈએ તે ભેગું કરતા ડૅશબોર્ડ) વ્યક્તિગત સગવડ નહીં, પ્રણાલી થ્રુપુટ ખરીદે છે. અવરોધ પર ઉપાડ/પ્રતીક્ષા સમય માપો ([ફ્લો મેટ્રિક્સ](../ફ્લો-મેટ્રિક્સ/) જુઓ) — તે 14:00 રજા-કરાડનું સૉફ્ટવેર સમકક્ષ છે.

## સામાન્ય ભૂલો

- **બિન-અવરોધને ઑપ્ટિમાઇઝ કરવો**: જેની પાછળ કંઈ કતારમાં નથી તેવી ભૂમિકા માટે સુંદર ટૂલિંગ લગભગ-શૂન્ય પ્રણાલી મૂલ્ય પેદા કરે છે.
- **અવરોધ સ્થળાંતર**: કન્સલ્ટન્ટને ખોલો અને અવરોધ ખસે છે (ફાર્મસી, પરિવહન તરફ) — પૂર્ણ થ્રુપુટ લાભનો દાવો કરતાં પહેલાં *આગામી* અવરોધનું મૉડેલ કરો.
- **ડાઉનસ્ટ્રીમ કલાકોને રોકડ ગણવા**: અવરોધિત-સમય મુક્તિ ક્ષમતા છે, સામાન્ય [પુનઃનિયુક્તિ કસોટી](../રોકડ-મુક્તિકારક-વિરુદ્ધ-બિન-રોકડ-મુક્તિકારક-બચત/) ને આધીન.
