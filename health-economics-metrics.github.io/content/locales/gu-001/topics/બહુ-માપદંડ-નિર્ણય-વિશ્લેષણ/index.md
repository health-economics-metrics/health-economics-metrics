# બહુ-માપદંડ નિર્ણય વિશ્લેષણ (MCDA)

બહુ-માપદંડ નિર્ણય વિશ્લેષણ (MCDA) એ આરોગ્ય ટેકનોલોજી મૂલ્યાંકનમાં વપરાતું ભારિત-સરવાળા ગુણાંકન મૉડેલ છે, જ્યારે એક જ ICER/ચૂકવવાની-તૈયારી સીમા નિર્ણયકર્તાને જે મહત્ત્વનું છે તે બધું પકડતી નથી: સમાનતા, અપૂર્ણ જરૂરિયાત, નવીનતા, બજેટ અસર, રોગ ગંભીરતા. દરેક માપદંડને તેનું મહત્ત્વ દર્શાવતો ભાર મળે છે (હિતધારકો પાસેથી મેળવાયેલ, ભારનો સરવાળો 1), દરેક વિકલ્પને પ્રતિ-માપદંડ સામાન્યીકૃત ગુણાંક મળે છે (સામાન્ય રીતે 0–1), અને એકંદર ગુણાંક ભારિત સરવાળો છે — સૉફ્ટવેર વેન્ડર-પસંદગી સ્કોરકાર્ડ જેવો જ ગાણિતિક આકાર.

## આ શા માટે મહત્ત્વનું છે

MCDA EVIDEM જેવા માળખાંમાં, અને અનાથ/દુર્લભ-રોગ મૂલ્યાંકનો માટે કેટલીક HTA સંસ્થાઓ દ્વારા વપરાય છે જ્યાં કડક QALY-દીઠ-ખર્ચ સીમા અભિગમ નિર્ણય વિશે મહત્ત્વનું બધું પકડવા માટે બહુ સાંકડો ગણાય છે. ISPOR MCDA Emerging Good Practices Task Force એ ભાર અને ગુણાંક બચાવી શકાય તેવી રીતે મેળવવા માટે શ્રેષ્ઠ-પ્રથા માર્ગદર્શન ઔપચારિક બનાવ્યું, ચોક્કસ એટલા માટે કે અનૌપચારિક રીતે ભારિત નિર્ણય બનાવવો સરળ અને રમત કરવી સરળ છે. જ્યારે આરોગ્ય ટેકનોલોજીમાં ખરેખર મૂલ્ય પરિમાણો હોય જે એક [ચૂકવવાની તૈયારીની સીમા](../ચૂકવવાની-તૈયારીની-સીમાઓ/) રજૂ કરી શકતી નથી — ગંભીરતા, નવીનતા, સમાનતા — ત્યારે MCDA નિર્ણયકર્તાઓને અકથિત વિવેચનાત્મક નિર્ણયને બદલે તેમને ભેગા કરવા સ્પષ્ટ, ઑડિટ કરી શકાય તેવી રચના આપે છે.

## ગણિત

```
MCDA score = Σ_i (weight_i × score_i)

weights should sum to 1 (elicited via stakeholder methods such as swing
weighting or the Analytic Hierarchy Process)
```

## ઉકેલેલું ઉદાહરણ

HTA સમિતિ ડિજિટલ થેરાપ્યુટિકને ચાર માપદંડો પર ગુણાંક આપે છે:

```
Criterion                          Weight   Score   Weight × Score
Clinical benefit                   0.4      0.8     0.32
Cost impact                        0.3      0.5     0.15
Disease severity / unmet need      0.2      0.9     0.18
Innovation                         0.1      0.6     0.06
                                    ─────                ─────
                                    1.0                  0.71
```

ભારનો સરવાળો 1.0 છે (0.4 + 0.3 + 0.2 + 0.1), અને MCDA ગુણાંક 0.71 છે (0.32 + 0.15 + 0.18 + 0.06). સમિતિ 0.71 ની પૂર્વ-સંમત સીમા સાથે સરખામણી કરે છે, અથવા એ જ રીતે ગુણાંકિત સ્પર્ધક ટેકનોલોજી સામે ક્રમ આપે છે.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

આ ભારિત વેન્ડર-પસંદગી સ્કોરકાર્ડ, RFP મૂલ્યાંકન મૅટ્રિક્સ, કે સુવિધા-પ્રાથમિકતા ગુણાંકન મૉડેલ જેવું જ ગણિત છે — સૉફ્ટવેર પ્રાપ્તિમાં ક્લાસિક ભારિત-સ્કોરકાર્ડ ઉપયોગ કેસ માટે [બનાવો વિરુદ્ધ ખરીદો](../બનાવો-વિરુદ્ધ-ખરીદો/) જુઓ. [WSJF અને CD3](../wsjf-અને-cd3/) સાથે વિરોધાભાસ કરવો પણ યોગ્ય: WSJF/CD3 *ગુણોત્તર*-આધારિત પ્રાથમિકતા પદ્ધતિ છે (વિલંબની કિંમત ભાગ્યા કાર્ય કદ કે સમયગાળો), જ્યારે MCDA ભારિત *સરવાળો* છે. MCDA અને WSJF/CD3 "સ્પર્ધક વિકલ્પોને કેવી રીતે ક્રમ આપવો" ના બે રચનાત્મક રીતે અલગ જવાબો છે, અને આપેલા નિર્ણયને ખરેખર કયો જોઈએ તે જાણવું — સ્વતંત્ર માપદંડો પર ઍડિટિવ મૂલ્ય, વિરુદ્ધ દુર્લભ ક્ષમતાના એકમ દીઠ મૂલ્ય ઘનતા — કયું સૂત્ર વધુ કડક દેખાય છે તેના કરતાં વધુ મહત્ત્વનું છે.

## સામાન્ય ભૂલો

- **ભાર મેળવવામાં પૂર્વગ્રહ**: જે ભાર નક્કી કરે તે અસરકારક રીતે ક્રમ પૂર્વનિર્ધારિત કરે છે, તેથી "સૂત્ર" રાજકીય કે વાણિજ્યિક નિર્ણયને ઉદ્દેશ્ય ગણતરી તરીકે ધોઈ શકે. ભાર કોણે અને કેવી રીતે નક્કી કર્યા તે દસ્તાવેજીકૃત કરો.
- **બીજે પહેલેથી પકડાયેલા માપદંડની બેવડી ગણતરી**: "ખર્ચ-અસરકારકતા" ને એક માપદંડ તરીકે ગુણાંક આપવું જ્યારે *સાથે* "ખર્ચ અસર" ને અલગથી ગુણાંક આપવું, કોઈના ઇરાદા વિના અન્ય માપદંડોની સાપેક્ષ નાણાંને વધુ ભાર આપે છે.
- **ખોટી ચોકસાઈ**: બે-દશાંશ ભારિત ગુણાંક (0.71) અંતર્ગત 0–10 હિતધારક રેટિંગ્સ ખરેખર આધાર આપે તેના કરતાં વધુ કડકાઈ સૂચવે છે, અને તે રેટિંગ્સમાં આંતર-રેટર ચલતા ઘણી વાર અહેવાલ જ થતી નથી.
