# રિયલ ઑપ્શન્સ મૂલ્યાંકન

રિયલ ઑપ્શન્સ મૂલ્યાંકન નાણાકીય ઑપ્શન-પ્રાઇસિંગ તર્કને વાસ્તવિક (બિન-નાણાકીય-બજાર) રોકાણ નિર્ણયો પર લાગુ કરે છે — ખાસ કરીને પ્રોજેક્ટ સફળ થાય તો તેને પછીથી *વિસ્તારવાનો વિકલ્પ*, તેમ કરવા બંધાયા વિના. સરળ એક-સમયગાળા બાયનોમિયલ મૉડેલ (Cox, Ross, Rubinstein, 1979) આ લવચીકતાનું સીધું મૂલ્ય આંકે છે, "ચાલો નાનું મોકલીને જોઈએ" ને અંતઃપ્રેરણામાંથી કિંમત-આંકેલી સંખ્યામાં ફેરવે છે.

## આ શા માટે મહત્ત્વનું છે

સ્થિર NPV ગણતરી પ્રોજેક્ટની કિંમત બધું-અથવા-કંઈ નહીં દાવ તરીકે આંકે છે: આજના સ્કેલે, કાયમ માટે, ભંડોળ આપો અથવા ન આપો. વાસ્તવિક પ્રોજેક્ટ્સ — ખાસ કરીને તબક્કાવાર ડિજિટલ આરોગ્ય રોલઆઉટ — ભાગ્યે જ આ રીતે દાવ લાગે છે: આરોગ્ય પ્રણાલી નાના પાયલટને ભંડોળ આપી શકે, શું થાય છે તે જોઈ શકે, અને તે કામ કરે તો જ વધુ નાણાં પ્રતિબદ્ધ કરી શકે. તે લવચીકતાનું વાસ્તવિક મૂલ્ય છે, અને તેની અવગણના તબક્કાવાર રોકાણોને એક-વારના રોકાણો સાપેક્ષ વ્યવસ્થિત રીતે ઓછા આંકે છે, જે સુરક્ષિત-દેખાતી તબક્કાવાર દરખાસ્તને પુરસ્કાર આપતી પ્રાપ્તિ પ્રક્રિયાઓ માટે બરાબર ઊલટું છે. રિયલ ઑપ્શન્સ મૂલ્યાંકન લવચીકતાની જ કિંમત આંકે છે, જેથી તબક્કાવાર દરખાસ્તની સરખામણી સંપૂર્ણ-પ્રતિબદ્ધતા વિકલ્પ સાથે યોગ્ય રીતે થઈ શકે, ભોળી NPV પંક્તિ પર નાની દેખાવા બદલ દંડ વિના.

## ગણિત

```
Risk-neutral probability of the "up" state:
  p = ((1 + risk_free_rate) − down_factor) / (up_factor − down_factor)

Expansion payoff in each state (floored at zero — expanding is optional):
  payoff_up   = max(project_value × up_factor   − expansion_cost, 0)
  payoff_down = max(project_value × down_factor − expansion_cost, 0)

Option value (discounted expected payoff):
  option_value = (p × payoff_up + (1 − p) × payoff_down) / (1 + risk_free_rate)

Expanded NPV = static_npv + option_value
```

પ્રોજેક્ટનું મૂલ્ય આગામી નિર્ણય બિંદુ સુધીમાં કાં વધે (`up_factor`) કે ઘટે (`down_factor`). વિસ્તરણ ફક્ત તે અવસ્થામાં નફાકારક હોય તો જ વાપરવામાં આવે છે — શૂન્ય પરનો ચુકવણી ફ્લોર જ આને ફરજિયાતતાને બદલે સાચો *વિકલ્પ* બનાવે છે. પહેલાં માહિતી એકત્ર કરવાના વિકલ્પને બદલે પછીથી વિસ્તારવાના વિકલ્પની કિંમત માટે, [સંપૂર્ણ માહિતીનું અપેક્ષિત મૂલ્ય](../સંપૂર્ણ-માહિતીનું-અપેક્ષિત-મૂલ્ય/) જુઓ. તે નિર્ણય લેવા માટે રાહ જોવાના ખર્ચ માટે, [વિલંબની કિંમત](../વિલંબની-કિંમત/) જુઓ.

## ઉકેલેલું ઉદાહરણ

ડિજિટલ સેવા પાયલટ `project_value = £1,000,000` સાથે, આગામી નિર્ણય બિંદુ સુધીમાં 1.5× વધવાની કે 0.5× ઘટવાની શક્યતા, 8% જોખમ-મુક્ત દર, અને £600,000 વિસ્તરણ ખર્ચ:

```
p = (1.08 − 0.5) / (1.5 − 0.5) = 0.58

payoff_up   = max(1,000,000 × 1.5 − 600,000, 0) =  900,000
payoff_down = max(1,000,000 × 0.5 − 600,000, 0) = max(−100,000, 0) = 0

The floor matters: the option would NOT be exercised if the market
disappoints — the £600,000 expansion cost exceeds the £500,000 the
project would be worth in the down state.

option_value = (0.58 × 900,000 + 0.42 × 0) / 1.08
             = 522,000 / 1.08
             ≈ £483,333.33
```

£200,000 ના સ્થિર-NPV આધારરેખામાં વિકલ્પનું મૂલ્ય ઉમેરતાં: વિસ્તૃત NPV = 200,000 + 483,333.33 ≈ **£683,333.33**. આ વિકલ્પ મૂલ્ય વિના ફક્ત £200,000 સ્થિર NPV અહેવાલ કરવું તબક્કાવાર પ્રોજેક્ટના સાચા મૂલ્યને બે ગણા કરતાં વધુ ઓછું આંકત.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

આ "હમણાં ન્યૂનતમ સંસ્કરણ મોકલો, તે ઉપડે તો વધુ રોકાણ કરવાનો વિકલ્પ રાખો" નું ઔપચારિક સ્વરૂપ છે — તબક્કાવાર ડિજિટલ આરોગ્ય ઉત્પાદન રોલઆઉટ સાથે સીધું સુસંગત, [વિલંબની કિંમત](../વિલંબની-કિંમત/) અને [WSJF/CD3](../wsjf-અને-cd3/) ના અનિશ્ચિતતા હેઠળ ક્રમાંકન ફ્રેમિંગ સાથે રચનાત્મક રીતે સમાંતર, અને [સંપૂર્ણ માહિતીનું અપેક્ષિત મૂલ્ય](../સંપૂર્ણ-માહિતીનું-અપેક્ષિત-મૂલ્ય/) અને [નમૂના માહિતીનું અપેક્ષિત મૂલ્ય](../નમૂના-માહિતીનું-અપેક્ષિત-મૂલ્ય/) નું પૂરક — ત્રણેય અનિશ્ચિતતા હેઠળ લવચીકતા કે માહિતીની કિંમત આંકે છે, અલગ ખૂણાઓથી.

## સામાન્ય ભૂલો

- **જેના પર તે આધાર રાખે છે તે વેપાર થતી-સંપત્તિ ધારણા વિના જોખમ-તટસ્થ ભાવ ઉછીના લેવા**: રિયલ ઑપ્શન્સ મૉડેલ નાણાકીય ઑપ્શન પ્રાઇસિંગમાંથી જોખમ-તટસ્થ સંભાવના ઉછીની લે છે, જે માને છે કે અંતર્ગત મૂલ્ય *વેપાર થતી* સંપત્તિ છે — ખરેખર બિન-વેપાર થતા વાસ્તવિક પ્રોજેક્ટ માટે આ મૉડેલિંગ સગવડ છે, શાબ્દિક બજાર હકીકત નથી.
- **`up_factor`/`down_factor` ને મુક્ત પરિમાણો ગણવા**: બાયનોમિયલ up/down ઇનપુટ પોતે ધારણાઓ છે જેને ન્યાયીકરણ જોઈએ, ઇચ્છિત જવાબ પેદા કરવા પસંદ કરેલા મુક્ત પરિમાણો નહીં.
- **ફક્ત વિકલ્પ મૂલ્ય અહેવાલ કરવું**: રિયલ ઑપ્શન્સ મૂલ્ય સ્વતંત્ર પ્રોજેક્ટના સ્થિર NPV ઉપરાંત *ઉમેરાય* છે — સામાન્ય ભૂલ એ છે કે ફક્ત વિકલ્પ મૂલ્ય અહેવાલ કરવું અને આધાર કેસ છોડવો, જે સ્થિર NPV ઋણ હોય ત્યારે કેસ વધુ આંકે છે અને સ્થિર NPV સંપૂર્ણપણે છોડી દેવાય ત્યારે (ઉપરના ઉકેલેલા ઉદાહરણની જેમ) ઓછો આંકે છે.
