# જાળવણી અને છોડી જવું

જાળવણી માપે છે કે શરૂઆતના N દિવસ પછી વપરાશકર્તા સમૂહનો કેટલો હિસ્સો હજી સક્રિય છે (D1/D7/D30 વક્રો); છોડી જવું તેનું પૂરક છે. ડિજિટલ-આરોગ્યનો કડવો આધારરેખા: **લગભગ 90% આરોગ્ય-ઍપ વપરાશકર્તાઓ 30 દિવસમાં છોડી દે છે** — ડિજિટલ આરોગ્ય D30 જાળવણી ~3–4% છે, જ્યારે બધી ઍપની સરેરાશ ~6% છે.

## આ શા માટે મહત્ત્વનું છે

Eysenbach એ 2005માં તેને નામ આપ્યું: **ક્ષયનો નિયમ (law of attrition)** — ઊંચા દરે વપરાશકર્તાઓ ગુમાવવા એ eHealth હસ્તક્ષેપોનો આંતરિક, માળખાકીય ગુણધર્મ છે, અમલીકરણની ભૂલ નથી; eHealth ટ્રાયલમાં ક્ષય નિયમિત રીતે 50% થી વધુ હોય છે. આર્થિક પરિણામ સંપૂર્ણ છે: જાળવણી *સારવાર-બારી* નક્કી કરે છે જેની અંદર કોઈ પણ લાભ પહોંચાડી શકાય, અને [યુનિટ ઇકોનોમિક્સ](../આરોગ્ય-ઍપ-યુનિટ-ઇકોનોમિક્સ/) — 12 દિવસ ટકતા વપરાશકર્તા માટે ચૂકવેલ CAC ન તો LTV આપે છે, ન QALY. ગ્રાહક આરોગ્ય ઉત્પાદન માટેનું કોઈ પણ આર્થિક મૉડેલ જે લાભને જાળવણી વક્રથી ભારિત ન કરે તે એવા ઉત્પાદનનું વર્ણન કરે છે જે અસ્તિત્વમાં નથી.

## ગણિત

```
Retention_Dn = users active on day n / cohort size × 100
Churn rate   = users lost in period / users at period start × 100

Benefit weighting (the health-economics move):
  expected benefit per acquired user = Σ_t retention(t) × benefit rate(t)
  ≈ area under the retention curve × per-time benefit
  — NOT trial benefit × 100% of acquired users

Cost per retained-at-D30 user = CAC / D30 retention
  (at 4% D30, a £5 CAC is really £125 per retained user)
```

## ઉકેલેલું ઉદાહરણ

એક માનસિક-આરોગ્ય ઍપ: ટ્રાયલમાં 8 અઠવાડિયા પૂરા કરનાર દરેક વપરાશકર્તા દીઠ 0.02 QALY મળ્યા. 100,000 ડાઉનલોડનો ડિપ્લોયમેન્ટ સમૂહ, જાળવણી D7 25%, D30 8%, અઠવાડિયું-8 4%:

```
Completers          = 100,000 × 0.04 = 4,000
QALYs delivered     = 4,000 × 0.02 = 80  (not 100,000 × 0.02 = 2,000)
At £20,000/QALY     = £1.6M of health value (not £40M)

Per-download health value = £16 — the number that should set what a
payer will pay per download, and it is 4% of the naive claim.
Retention improvement case: moving week-8 completion 4% → 6% adds
40 QALYs/year ≈ £800k — retention engineering IS health production.
```

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

ઉપરના ગણિત મુજબ, જાળવણી એ મેટ્રિક છે જ્યાં પ્રોડક્ટ એન્જિનિયરિંગ સૌથી સીધું આરોગ્ય મૂલ્ય ઉત્પન્ન કરે છે. તેને હલાવતી પદ્ધતિઓ સામાન્ય છે: ઑનબોર્ડિંગ સમય-થી-પ્રથમ-મૂલ્ય, ફરી-જોડાણ ડિઝાઇન, પ્રદર્શન, અને ખાસ કરીને **આયોજિત માત્રા-પૂર્ણતા** — નિશ્ચિત અંતવાળો કાર્યક્રમ (8 અઠવાડિયા, પછી સ્નાતક) *પૂર્ણતા* માપે, કાયમી DAU નહીં; જેથી મેટ્રિક જાહેરાત-આધારિત ધ્યાન મૉડેલને બદલે ક્લિનિકલ મૉડેલ સાથે સુસંગત રહે. સર્વાઇવલ વિશ્લેષણ યોગ્ય સાધનસમૂહ છે ([જીવન-વર્ષ મેળવ્યા](../પ્રાપ્ત-જીવન-વર્ષો/) જેવું જ Kaplan-Meier ગણિત); વક્રોને પ્રાપ્તિ ચૅનલ પ્રમાણે વિભાજિત કરો, કારણ કે ચૅનલ મિશ્રણ મોટાભાગની સુવિધાઓ કરતાં જાળવણીને વધુ બદલે છે.

## સામાન્ય ભૂલો

- **ઊલટું ઇન્ટેન્શન-ટુ-ટ્રીટ ધોવાણ**: ટ્રાયલ પૂર્ણ કરનારાઓ જણાવે છે; ડિપ્લોયમેન્ટ અર્થશાસ્ત્રે પ્રાપ્ત થયેલા બધાને ગણવા જોઈએ (Eysenbach ની મુખ્ય ચેતવણી).
- **જાળવણી નાટક**: સૂચના-ચાલિત "સક્રિય" વપરાશકર્તાઓ જે ક્યારેય ઉપચારાત્મક ક્રિયા કરતા નથી ([જોડાણ મેટ્રિક્સ](../જોડાણ-મેટ્રિક્સ/) જુઓ).
- **વ્યાખ્યાઓ વચ્ચે વક્રોની સરખામણી**: "સક્રિય" એટલે ખોલવું કે અર્થપૂર્ણ ક્રિયા — D30 ને ઘણા ગણું બદલે છે.
- **કોણ છોડે છે તે અવગણવું**: જો સૌથી બીમાર સૌથી ઝડપથી છોડે, તો સ્વસ્થ લોકોમાં જાળવણી સુધરતાં વપરાશકર્તા-દીઠ લાભ ઘટે છે — વક્રોને કેસ-મિશ્રણ સાથે જોડો ([પહોંચ અને સમાનતા](../પહોંચ-અને-સમાનતા/) જુઓ).
