# ຜະລິດຕະພາບການເຮັດວຽກ ແລະ ຄວາມບົກພ່ອງຂອງກິດຈະກຳ (WPAI)

WPAI ແມ່ນແບບສອບຖາມລາຍງານຕົນເອງທີ່ຢືນຢັນແລ້ວ (Reilly, Zbrozek, Dasbach, 1993) ທີ່ວັດວ່າບັນຫາສຸຂະພາບມີຜົນຕໍ່ວຽກທີ່ມີຄ່າຈ້າງ ແລະ ກິດຈະກຳປະຈຳວັນຫຼາຍປານໃດ, ປົກກະຕິໃນ 7 ວັນທີ່ຜ່ານມາ. ມັນແຍກການສູນເສຍເປັນ *ການຂາດງານ* — ເວລາເຮັດວຽກທີ່ພາດຈິງ — ແລະ *ການມາເຮັດວຽກແຕ່ບໍ່ມີຜະລິດຕະພາບ (presenteeism)* — ຜະລິດຕະພາບຫຼຸດໃນຂະນະທີ່ຢູ່ບ່ອນເຮັດວຽກທາງກາຍ — ແລະ ອັນທີສອງປົກກະຕິເປັນສ່ວນຕົ້ນທຶນທີ່ໃຫຍ່ກວ່າ ແລະ ເຊື່ອງຢູ່ຫຼາຍກວ່າ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ການນັບວັນເຈັບປ່ວຍງ່າຍໆເຫັນສະເພາະການຂາດງານ. ແພດ ຫຼື ພະນັກງານຄວາມຮູ້ທີ່ບໍ່ເຄີຍລາຢຸດແຕ່ເຮັດວຽກທີ່ 60% ຂອງຄວາມຈຸຜ່ານສະພາບຊຳເຮື້ອສົ່ງຜົນສູນຕໍ່ທະບຽນການຂາດງານ ໃນຂະນະທີ່ຍັງສ້າງການສູນເສຍຜະລິດຕະພາບທີ່ໃຫຍ່ ແລະ ເປັນຈິງ — WPAI ຖືກອອກແບບສະເພາະເພື່ອເປີດເຜີຍຕົ້ນທຶນທີ່ເບິ່ງບໍ່ເຫັນນັ້ນ. ເພາະມັນເປັນເຄື່ອງມືທີ່ຢືນຢັນແລ້ວແທນການສຳຫຼວດສະເພາະກິດ, ຄະແນນຂອງມັນໃຊ້ໄດ້ໃນຊຸດຫຼັກຖານ [ຜົນລັບທີ່ຜູ້ປ່ວຍລາຍງານ](../ຜົນລັບທີ່ຜູ້ປ່ວຍລາຍງານ/) ແລະ ການສຶກສາຕົ້ນທຶນຂອງພະຍາດໂດຍຜູ້ທົບທວນບໍ່ຕ້ອງຢືນຢັນມາດຕະການຄືນໃໝ່. ໃນຖານະເຄື່ອງມືລາຍງານຕົນເອງ, ມັນເອງເປັນຮູບແບບໜຶ່ງຂອງ PROM, ແຕກຕ່າງຫຼັກໆໂດຍການເນັ້ນວຽກ ແລະ ກິດຈະກຳແທນອາການ ຫຼື ຄຸນນະພາບຊີວິດ.

## ຄະນິດສາດ

```
Absenteeism % = hours_missed_due_to_health / (hours_missed_due_to_health + hours_worked) × 100

Presenteeism %  = self-rated 0–10 impairment while working, × 10
                  (elicited directly via questionnaire, not derived here)

Overall Work Impairment % =
    Absenteeism% + (1 − Absenteeism%/100) × Presenteeism%
    (combines the two so the total can never exceed 100%)

Productivity cost = Overall Work Impairment% / 100 × period_earnings
```

ສູດຄວາມບົກພ່ອງລວມບໍ່ແມ່ນຜົນບວກງ່າຍໆໂດຍເຈດຕະນາ: ການບວກສອງເປີເຊັນໂດຍກົງອາດເກີນ 100%, ດັ່ງນັ້ນ presenteeism ຖືກນຳໃຊ້ກັບສ່ວນ *ທີ່ເຫຼືອ* (ບໍ່ຂາດງານ) ຂອງເວລາເຮັດວຽກເທົ່ານັ້ນ.

## ຕົວຢ່າງການຄິດໄລ່

ພະນັກງານທີ່ເປັນໄມເກຣນລາຍງານວ່າຖືກກຳນົດໃຫ້ເຮັດວຽກອາທິດ 40 ຊົ່ວໂມງແຕ່ພາດ 4 ຊົ່ວໂມງ:

```
hours_missed = 4, hours_worked = 36
Absenteeism% = 4 / (4 + 36) × 100 = 10%
```

ເຂົາປະເມີນຜົນກະທົບຕໍ່ຜະລິດຕະພາບຂອງຕົນເອງແຍກຕ່າງຫາກໃນຂະນະເຮັດວຽກເປັນ 3 ໃນ 10 ໃນແບບສອບຖາມ WPAI, ເຊັ່ນ `Presenteeism% = 30%` (ຂັ້ນຕອນນີ້ແມ່ນຄຳຕອບແບບສອບຖາມດິບ, ບໍ່ແມ່ນສິ່ງທີ່ຄິດໄລ່ຈາກຕົວເລກອື່ນ):

```
Overall Work Impairment% = 10 + (1 − 10/100) × 30
                          = 10 + 0.9 × 30
                          = 10 + 27
                          = 37%
```

ໃນອາທິດ 5 ວັນທີ່ມີລາຍໄດ້ £800 (£160/ວັນ):

```
Productivity cost = 37/100 × 800 = £296
```

ສັງເກດວ່າການນັບວັນເຈັບປ່ວຍແບບໄຮ້ດຽງສາຈະບັນທຶກພຽງ 4 ຊົ່ວໂມງ (10%) ທີ່ພາດ — ສ່ວນ presenteeism ເກືອບເພີ່ມຄວາມບົກພ່ອງແທ້ເປັນສາມເທົ່າເມື່ອນັບ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ນີ້ແຜ່ກັບຕົວຊີ້ວັດສຸຂະພາບທີມວິສະວະກຳໂດຍກົງ:

- **ການຂາດງານ** ແມ່ນການລາເຈັບ ແລະ PTO — ເຫັນໄດ້, ຕິດຕາມແລ້ວ, ແລະ ເປັນສ່ວນງ່າຍ.
- **Presenteeism** ແມ່ນວິສະວະກອນທີ່ໝົດໄຟ ຫຼື ຖືກບັງຄັບປ່ຽນບໍລິບົດຫຼາຍເກີນທີ່ຢູ່ໃນທຸກ stand-up ແຕ່ເຮັດວຽກດ້ວຍຄວາມຈຸຫຼຸດ — ປົກກະຕິເປັນຕົ້ນທຶນທີ່ໃຫຍ່ກວ່າ ແລະ ເຊື່ອງຢູ່ຫຼາຍກວ່າ, ແລະ ເບິ່ງບໍ່ເຫັນຕໍ່ຂໍ້ມູນຈຳນວນພະນັກງານ ຫຼື ການເຂົ້າວຽກ. ມັນປາກົດແທນເປັນ throughput ທີ່ຫຼຸດໃນ [DORA](../ຕົວຊີ້ວັດ-dora/) ແລະ [ຕົວຊີ້ວັດການໄຫຼ](../ຕົວຊີ້ວັດການໄຫຼ/), ຫຼື ການແກ້ [ໜີ້ສິນດ້ານເຕັກນິກ](../ໜີ້ສິນດ້ານເຕັກນິກ/) ທີ່ຊ້າລົງ ເຊິ່ງ "ດອກເບ້ຍ" ຂອງມັນທະວີຄວາມບົກພ່ອງຕໍ່ໄປອີກ.
- ບົດຮຽນວິສະວະກຳຄືກັບທາງຄລີນິກ: ການວັດສະເພາະການຂາດງານແລ້ວເອີ້ນມັນວ່າ "ການສູນເສຍຜະລິດຕະພາບ" ປະເມີນຕົ້ນທຶນແທ້ຕ່ຳເກີນຢ່າງເປັນລະບົບ, ເພາະພາດທຸກຄົນທີ່ຢູ່ແຕ່ບົກພ່ອງ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ອະຄະຕິການລະນຶກຂອງການລາຍງານຕົນເອງ.** ປ່ອງຢ້ຽມລະນຶກ 7 ວັນຢູ່ພາຍໃຕ້ການບິດເບືອນການລາຍງານດຽວກັບການລາຍງານຕົນເອງຍ້ອນຫຼັງໃດໆ.
- **ຖືສະເກວ presenteeism 0–10 ເປັນການວັດທາງກາຍຈິງ.** ມັນເປັນລຳດັບ, ດຶງດ້ວຍການປະເມີນຕົນເອງ, ບໍ່ແມ່ນປະລິມານກາຍທີ່ຢືນຢັນແລ້ວ — ການຖືຄວາມແຕກຕ່າງຂອງມັນເປັນເສັ້ນຊື່ ຫຼື ຊ່ວງຢ່າງເຄັ່ງແມ່ນຄວາມສະດວກຂອງການສ້າງແບບຈຳລອງ, ບໍ່ແມ່ນຂໍ້ເທັດຈິງທາງກາຍທີ່ຢືນຢັນແລ້ວ.
- **ລວມຄະແນນຂ້າມຮຸ່ນ WPAI.** WPAI ມີຫຼາຍຮຸ່ນສະເພາະສະພາບ — WPAI:GH (ສຸຂະພາບທົ່ວໄປ), WPAI:SHP (ບັນຫາສຸຂະພາບສະເພາະ), ແລະ ຮຸ່ນສະເພາະພະຍາດ — ແລະ ຄະແນນຈາກຮຸ່ນຕ່າງກັນບໍ່ຄວນລວມ ຫຼື ປຽບທຽບໂດຍບໍ່ກວດກ່ອນວ່າເປັນເວີຊັນເຄື່ອງມືດຽວກັນ.
