# ການວິເຄາະຄວາມອ່ອນໄຫວ

ການວິເຄາະຄວາມອ່ອນໄຫວແບບກຳນົດ (DSA) ປ່ຽນສົມມຸດຖານເທື່ອລະອັນຕະຫຼອດຊ່ວງທີ່ເປັນໄປໄດ້ເພື່ອເບິ່ງວ່າບົດສະຫຼຸບຢູ່ລອດຫຼືບໍ່. ການສະແດງພາບມາດຕະຖານແມ່ນແຜນຜັງ tornado: ພາຣາມິເຕີທີ່ຈັດອັນດັບຕາມຂະໜາດທີ່ມັນເຮັດໃຫ້ຜົນແກວ່ງ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ທຸກແບບຈຳລອງເສດຖະກິດສ້າງຢູ່ເທິງການຄາດຄະເນ — ເວລາທີ່ປະຢັດ, ການຮັບເອົາ, ຕົ້ນທຶນຫົວໜ່ວຍ. ການປະເມີນເຕັກໂນໂລຢີສຸຂະພາບປະຕິເສດຍອມຮັບຄ່າຈຸດດຽວ ("ROI ແມ່ນ 340%") ໂດຍບໍ່ມີຫຼັກຖານວ່າບົດສະຫຼຸບທົນຕໍ່ຄວາມບໍ່ເຫັນດີທີ່ສົມເຫດສົມຜົນກ່ຽວກັບຂໍ້ມູນເຂົ້າ. ແຜນຜັງ tornado ບອກຜູ້ຕັດສິນໃຈວ່າ *ຄວນສອບຖາມສົມມຸດຖານໃດ*: ຖ້າກໍລະນີໃຊ້ໄດ້ກໍຕໍ່ເມື່ອພາຣາມິເຕີທີ່ຖົກຖຽງຫຼາຍທີ່ສຸດຢູ່ປາຍທີ່ມອງໃນແງ່ດີ, ທຸກຄົນເຫັນທັນທີ.

ນີ້ແມ່ນນິໄສດຽວທີ່ໂອນຈາກເສດຖະສາດສຸຂະພາບໄປຫາ business case ຊອບແວໄດ້ຫຼາຍທີ່ສຸດ.

## ຄະນິດສາດ

ສຳລັບແຕ່ລະພາຣາມິເຕີ p ທີ່ມີຊ່ວງເປັນໄປໄດ້ [p_low, p_high]:

```
Result_low  = model(p = p_low,  all others at base case)
Result_high = model(p = p_high, all others at base case)
Swing(p)    = |Result_high − Result_low|
```

ຈັດອັນດັບພາຣາມິເຕີຕາມການແກວ່ງ; ພລັອດແຖບແນວນອນອ້ອມຜົນກໍລະນີພື້ນຖານ. ຮຸ່ນຢ່າງ: DSA ສອງທາງ (ປ່ຽນສອງພາຣາມິເຕີເທິງຕາຕະລາງ), ການວິເຄາະເກນ (ຊອກຫາຄ່າພາຣາມິເຕີທີ່ການຕັດສິນໃຈພິກ).

## ຕົວຢ່າງການຄິດໄລ່

ຜູ້ຊ່ວຍຂຽນໂຄ້ດ AI ສຳລັບນັກພັດທະນາ 200 ຄົນ. ກໍລະນີພື້ນຖານ: ໃບອະນຸຍາດ £39/ນັກພັດທະນາ/ເດືອນ; ປະຢັດ 30 ນາທີ/ນັກພັດທະນາ/ວັນ; ຕົ້ນທຶນເຕັມ £60/ຊົ່ວໂມງ; 220 ວັນເຮັດວຽກ.

```
Base-case annual benefit = 200 × 0.5h × 220 × £60 = £1,320,000
Annual cost              = 200 × £39 × 12         = £93,600
Base-case net            = £1,226,400
```

Tornado (ເທື່ອລະພາຣາມິເຕີ):

```
Time saved 0.1–1.0 h/day: net = £170,400 … £2,546,400   (swing £2.38M) ← dominates
Loaded cost £40–£80/h:    net = £786,400 … £1,666,400   (swing £0.88M)
Working days 200–240:     net = £1,106,400 … £1,346,400 (swing £0.24M)
Licence £30–£50/mo:       net = £1,248,000 … £1,200,000 (swing £48k)
```

ການວິເຄາະເກນ: ຜົນປະໂຫຍດສຸດທິເຖິງສູນທີ່ປະມານ **2.1 ນາທີ/ວັນ** ທີ່ປະຢັດ. ການຕັດສິນໃຈບໍ່ອ່ອນໄຫວຕໍ່ລາຄາໃບອະນຸຍາດ ແລະ ຂຶ້ນກັບການຄາດຄະເນເວລາທີ່ປະຢັດທັງໝົດ — ດັ່ງນັ້ນວັດສິ່ງນັ້ນ, ບໍ່ແມ່ນສ່ວນທີ່ເຫຼືອ. (ແລະ ຈື່ວ່າຜົນແມ່ນຄວາມຈຸ, ບໍ່ແມ່ນເງິນສົດ — ເບິ່ງ [ການປະຢັດທີ່ປົດປ່ອຍເງິນສົດ ທຽບກັບ ທີ່ບໍ່ປົດປ່ອຍເງິນສົດ](../ການປະຢັດທີ່ປົດປ່ອຍເງິນສົດ-ທຽບກັບ-ທີ່ບໍ່ປົດປ່ອຍເງິນສົດ/).)

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ວິສະວະກອນເຮັດສະຕິນີ້ແລ້ວເປັນ "ຈະເປັນແນວໃດຖ້າເຮົາຜິດກ່ຽວກັບ X?" — DSA ພຽງແຕ່ເຮັດໃຫ້ມັນເປັນລະບົບ ແລະ ເຫັນໄດ້. ໃສ່ແຜນຜັງ tornado ໃນທຸກຂໍ້ສະເໜີເຄື່ອງມື, ແຜນຄວາມຈຸ ແລະ ການວິເຄາະສ້າງເອງທຽບກັບຊື້. ມັນແປງການໂຕ້ຖຽງວ່າໃຜຄວາມຮູ້ສຶກຖືກເປັນຂໍ້ຕົກລົງວ່າຈະໄປວັດພາຣາມິເຕີໃດ — ມັກຜ່ານໂຄງການນຳຮ່ອງ, ເຊິ່ງມູນຄ່າຂອງມັນເອງຕັ້ງລາຄາໄດ້ (ເບິ່ງ [ມູນຄ່າທີ່ຄາດໄວ້ຂອງຂໍ້ມູນສົມບູນແບບ](../ມູນຄ່າທີ່ຄາດໄວ້ຂອງຂໍ້ມູນສົມບູນແບບ/)).

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ຊ່ວງທີ່ເລືອກເພື່ອຍົກຍ້ອງ**: ±10% ອ້ອມທຸກຂໍ້ມູນເຂົ້າໂດຍບໍ່ສົນໃຈຄວາມບໍ່ແນ່ນອນຈິງ. ການຄາດຄະເນເວລາທີ່ປະຢັດຄວນ ±80%; ລາຄາໃບອະນຸຍາດ ±10%.
- **ເທື່ອລະອັນພາດປະຕິສຳພັນ** — ພາຣາມິເຕີທີ່ສຳພັນກັນ (ການຮັບເອົາ ແລະ ເວລາທີ່ປະຢັດ) ຕ້ອງການການວິເຄາະສອງທາງ ຫຼື [ການວິເຄາະຄວາມອ່ອນໄຫວແບບຄວາມນ່າຈະເປັນ](../ການວິເຄາະຄວາມອ່ອນໄຫວແບບຄວາມນ່າຈະເປັນ/) ເຕັມຮູບແບບ.
- **ເຮັດການວິເຄາະແລ້ວເມີນເສີຍມັນ**: ຖ້າ tornado ບອກວ່າກໍລະນີຂຶ້ນກັບຕົວເລກອ່ອນໜຶ່ງຕົວ, ຂັ້ນຕອນຕໍ່ໄປແມ່ນການວັດ, ບໍ່ແມ່ນການເຊັນອະນຸມັດ.
