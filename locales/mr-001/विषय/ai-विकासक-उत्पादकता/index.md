# AI विकासक उत्पादकता

AI कोडिंग साहाय्य अभियांत्रिकी उत्पादनावर प्रत्यक्षात काय परिणाम करते याचे मेट्रिक्स: सूचना स्वीकार दर, नियंत्रित अभ्यासांतील वेगवाढ, PR थ्रुपुट आणि कोड टिकवणूक. पुराव्याचा आधार खऱ्या अर्थाने परस्परविरोधी आहे — म्हणूनच तो आरोग्य अर्थशास्त्र ज्यासाठी उभारले गेले त्या परिणामकारकता-विरुद्ध-वास्तविक परिणामकारकता (efficacy vs effectiveness) भेदाचा उत्तम केस स्टडी आहे.

## हे का महत्त्वाचे आहे

सर्वाधिक उद्धृत केलेले दोन नियंत्रित अभ्यास विरुद्ध दिशांना निर्देश करतात:

- **Peng et al. 2023 (GitHub Copilot RCT)**: Copilot वापरून विकासकांनी नवीन (greenfield) HTTP-सर्व्हर काम **55.8% वेगाने** पूर्ण केले (1h11m विरुद्ध 2h41m, n=95).
- **METR 2025 RCT**: *स्वतःच्या प्रगल्भ रेपॉझिटरीवर* काम करणारे अनुभवी ओपन-सोर्स विकासक 2025 च्या सुरुवातीच्या AI साधनांसह **19% हळू** होते (16 विकासक, 246 कामे) — तरीही त्यांचा *विश्वास* होता की ते 20% वेगवान आहेत.

दोन्ही चांगले अभ्यास आहेत. विरोधाभास हाच निष्कर्ष आहे: greenfield कामातील परिणामकारकता प्रगल्भ कोडबेसमधील वास्तविक परिणामकारकतेत हस्तांतरित होत नाही, आणि *जाणवलेला* लाभ मोजलेल्या लाभाची जागा घेऊ शकत नाही. वैद्यकशास्त्रात या दोन्ही घटितांना नावे आहेत (स्पष्टीकरणात्मक विरुद्ध व्यावहारिक चाचण्या; प्लासिबो समस्या) आणि त्या हाताळण्याची यंत्रणा आहे.

## गणित

```
Acceptance rate  = accepted suggestions / shown suggestions
                   (GitHub telemetry ~30% avg; varies: SQL 45%, Python 35%, JS 28%)
Retention rate   = AI code surviving to merge / accepted AI code (~88% reported)
Speedup          = (t_control − t_AI) / t_control  (from controlled comparison ONLY)
Throughput delta = Δ merged PRs/dev/week (GitHub/Accenture field data: +8.7%)

Value model     = devs × time saved × loaded rate × utilization factor
                  — every term needs local measurement; see the tornado in
                  sensitivity-analysis.md, where time-saved dominates all
                  other parameters combined
```

## सोडवलेले उदाहरण

500 विकासकांची संस्था योग्य नियंत्रणासह (जुळवलेले संघ, 3 महिने, पूर्व-नोंदणीकृत मेट्रिक्स) एका साहाय्यकाचा पायलट राबवते:

```
Pilot result: PR cycle time −18%; merged PRs +6%; CFR unchanged;
              self-reported time saved 45 min/day; measured task-level ≈ 15 min/day

Value the MEASURED number: 500 × 0.25h × 220d × £60 × 0.6 utilization
                          ≈ £990,000/year capacity (non-cash-releasing)
Cost: 500 × £39/mo × 12 ≈ £234,000/year
Net capacity ratio ≈ 4:1 — fundable, at one-third the self-reported claim.
```

जाणवलेल्या आणि मोजलेल्या वेळेतील 3 पट अंतर म्हणजे METR चा निष्कर्ष प्रत्यक्ष जगात घडताना दिसणे; स्वतः-नोंदवलेल्या आकड्यावर अंदाजपत्रक केले असते तर लाभाची ओळ तिप्पट झाली असती.

## सॉफ्टवेअर अभियांत्रिकीशी संबंध

AI साधनांचे मूल्यमापन करणाऱ्या कोणालाही आरोग्य अर्थशास्त्राकडून मिळणाऱ्या गोष्टी: **व्यावहारिक चाचण्या** करा (तुमचा कोडबेस, तुमचे अभियंते, खरी तिकिटे — विक्रेत्याची डेमो कामे नव्हे); **स्वीकार दर हा प्रॉक्सी माना, परिणाम नव्हे** (विकासकाच्या दृष्टीने तो सूचनांचा [PPV](../क्लिनिकल-ai-मूल्यमापन/) आहे — उच्च स्वीकार आणि कमी टिकवणूक म्हणजे अतिनिदान); प्रत्येक थ्रुपुट वाढीला **स्थिरता तपासणी** जोडा (DORA 2025: AI थ्रुपुट वाढवते, स्थिरता बिघडवते — दुष्परिणाम असलेल्या हस्तक्षेपाला [DORA मेट्रिक्स](../dora-मेट्रिक्स/) नुसार निव्वळ-लाभ विश्लेषण लागते); आणि लाभाचे वर्गीकरण क्षमता म्हणून प्रामाणिकपणे करा ([रोख-मुक्त करणारी विरुद्ध रोख-मुक्त न करणारी बचत](../रोख-मुक्त-करणारी-विरुद्ध-रोख-मुक्त-न-करणारी-बचत/)).

## सामान्य चुका

- **विक्रेत्याच्या अभ्यासाचे प्रत्यारोपण**: greenfield RCT चे आकडे जुन्या कोडबेसच्या कामावर लावणे — METR अभ्यासाने उघड केलेली नेमकी चूक.
- **स्वतः-नोंदवलेली माहिती म्हणजे मोजमाप असे मानणे**: 20 टक्के-बिंदूंचे धारणा-अंतर हा या साहित्यातील सर्वात मोठा ज्ञात पूर्वग्रह आहे.
- **क्रियाकलापांचा फुगवटा**: जास्त PR आणि जास्त कोड म्हणजे क्रियाकलाप, परिणाम नव्हे ([SPACE](../space-आणि-devex/)); पुनर्काम आणि CFR सोबत जोडा.
- **शिकण्याच्या वक्राकडे दुर्लक्ष**: दुसऱ्या आठवड्यातील मोजमाप नावीन्याचा परिणाम कोणत्याही दिशेने पकडते; स्थिर अवस्थेत मोजा ([कालावधी क्षितिज](../कालावधी-क्षितिज/)).
