# तांत्रिक कर्ज

तांत्रिक कर्ज म्हणजे कोडबेसमधील भूतकाळातील सोयीस्कर निर्णयांचा गर्भित भावी खर्च: देय असलेले उपाययोजना काम (**मुद्दल**) आणि वितरणावर ते लावत असलेला सततचा ओढा (**व्याज**). SQALE सारख्या परिमाणीकरण पद्धती त्याला रूपकातून खर्चित देयतेत बदलतात.

## हे का महत्त्वाचे आहे

परिमाण न दिलेले तांत्रिक कर्ज म्हणजे तक्रार; परिमाणित केलेले ते व्यवसाय प्रकरण. उद्योग मूलरेषा (CAST Appmarq, 1,400 अ‍ॅप्स / 550M LOC): ऐतिहासिकदृष्ट्या प्रति कोड ओळ ≈ **$3.61 तांत्रिक-कर्ज मुद्दल**, ठराविक कोडबेसमध्ये पुनर्बांधणी खर्चाच्या 15–20% कर्ज गुणोत्तर, तर सामान्यतः वापरली जाणारी निरोगी पट्टी ≤5% (SonarQube चा "A" ग्रेड). आरोग्य-आर्थिक चौकट अचूक बसते: कर्ज हा *दीर्घकालीन आजार* आहे — उपचार न केल्यास तो पुढे सरकतो, त्याचे "व्याज" मंद वितरण आणि जास्त दोष दर म्हणून चक्रवाढ होते, आणि उपाययोजना वैशिष्ट्य कामाशी क्षमतेसाठी स्पर्धा करते अगदी जसे प्रतिबंध उपचाराशी स्पर्धा करतो.

## गणित

```
SQALE principal   = Σ over violations (remediation time) × developer cost rate
Technical debt ratio (TDR) = remediation cost / redevelopment cost × 100
                    (SonarQube grades: A ≤ 5%, B ≤ 10%, C ≤ 20%, D ≤ 50%)

Interest (the number that justifies paydown):
  interest/year = Δ delivery velocity × value per unit velocity
                + Δ defect rate × cost per defect
Paydown case  = PV(interest avoided over horizon) − remediation cost
                (discounted — see discounting-and-time-preference.md)
```

मुद्दल देयता नमूद करते; **व्याज** गुंतवणूक प्रकरण बनवते. £40k/वर्ष व्याज टाळण्यासाठी £500k मुद्दल फेडणे वाईट व्यवहार आहे; £400k/वर्ष टाळण्यासाठी, उत्कृष्ट.

## सोडवलेले उदाहरण

400k-LOC क्लिनिकल-नोंदी एकत्रीकरण स्तर: SQALE मुद्दल 3,800 तास × £75 = **£285k**; TDR ≈ 12% (ग्रेड C). मोजलेले व्याज: या स्तराला स्पर्श करणाऱ्या संघांमध्ये संपत्ती मूलरेषेच्या तुलनेत 40% जास्त सायकल टाइम आणि 2× बदल-अपयश दर दिसतात. स्तर दरवर्षी 6,000 डेव्ह-तास शोषून घेतो:

```
Interest ≈ 6,000 × 0.40 × £75      = £180,000/year (velocity drag)
         + 12 extra failures × £8,000 = £96,000/year (rework/incidents)
         ≈ £276,000/year

Remediate the worst 30% of principal (£85k) targeting hotspots → modelled
interest reduction 60%: saves ~£166k/year. Payback ≈ 6 months.
```

हॉटस्पॉट लक्ष्यीकरण महत्त्वाचे आहे: कर्जाचे व्याज तिथे केंद्रित होते जिथे बदल वारंवारता × कर्ज घनता शिखरावर असते — क्वचित स्पर्श होणाऱ्या कर्जाची उपाययोजना काहीच विकत घेत नाही, जसे कधीच पुढे न सरकणाऱ्या स्थितीवर उपचार करणे ([प्रतिबंध अर्थशास्त्र](../प्रतिबंध-अर्थशास्त्र/)).

## सॉफ्टवेअर अभियांत्रिकीशी संबंध

तांत्रिक-कर्ज युक्तिवाद सुधारणारी आरोग्य-अर्थशास्त्रीय आयात: संपदेला **भार यादी** म्हणून मांडा ([DALY](../अपंगत्व-समायोजित-आयुर्वर्ष/)-शैली — गमावलेली निरोगी अभियांत्रिकी-वर्षे कुठे आहेत?); फेडीचे समर्थन प्रामाणिकपणे प्रगती गणिताने करा (सहसा खर्च-परिणामकारक, खर्च-बचत करणारे नाही); सर्वात वाईट प्रणालींच्या उपाययोजनेला [तीव्रता तुटीने](../qaly-तूट-आणि-तीव्रता-सुधारक/) भारित करा; आणि मोठे उपाययोजना प्रस्ताव [टाळलेले डाउनस्ट्रीम खर्च](../टाळलेले-डाउनस्ट्रीम-खर्च/) नियमांना टिकणाऱ्या प्रतिसंतुलन विश्लेषणासह सादर करा — संभाव्यता-भारित, सवलत दिलेले, एकदाच मोजलेले.

## सामान्य चुका

- **फक्त मुद्दल नोंदवणे**: व्याज अंदाजाशिवायचा मोठा भीतीदायक आकडा काहीच समर्थन करत नाही.
- **टूल-निर्मित कर्ज आकडे शब्दशः घेणे**: SQALE नियम उल्लंघने मोजते; ते आर्किटेक्चरल कर्ज (महाग प्रकार) चुकवते आणि क्षुल्लक गोष्टी मोजते.
- **कर्ज-शून्य आदर्शवाद**: इष्टतम कर्ज पातळी शून्य नाही — कर्ज म्हणजे लीव्हरेज; प्रश्न व्याज दराचा आहे.
- **"पुनर्लेखन हे सर्व टाळते"**: पुनर्लेखन प्रस्तावांनी तेच प्रतिसंतुलन नियम पार केले पाहिजेत — प्रतितथ्य खर्च, संभाव्यता, सवलत.
