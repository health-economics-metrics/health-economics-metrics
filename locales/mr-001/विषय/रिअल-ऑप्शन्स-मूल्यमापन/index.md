# रिअल ऑप्शन्स मूल्यमापन

रिअल ऑप्शन्स मूल्यमापन आर्थिक-ऑप्शन किंमत तर्क खऱ्या (वित्तीय-बाजार नसलेल्या) गुंतवणूक निर्णयांना लावते — विशेषतः प्रकल्प यशस्वी झाला तर तो नंतर *विस्तारण्याचा पर्याय*, बंधन न घेता. सरलीकृत एक-कालावधी द्विपद मॉडेल (Cox, Ross, Rubinstein, 1979) ही लवचिकता थेट मोजते, "छोटे पाठवू आणि पाहू" ला अंतःप्रेरणेतून किंमत ठरवलेल्या संख्येत बदलते.

## हे का महत्त्वाचे आहे

स्थिर NPV गणना प्रकल्पाची किंमत सर्व-किंवा-काहीच-नाही पैज म्हणून ठरवते: आजच्या प्रमाणावर, कायमचा, निधी द्या किंवा देऊ नका. खरे प्रकल्प — विशेषतः टप्प्याटप्प्याचे डिजिटल आरोग्य रोलआउट — क्वचितच अशी पैज असतात: आरोग्य प्रणाली छोटा पायलट निधीकृत करू शकते, काय घडते ते पाहू शकते, आणि तो चालला तरच पुढील पैसे वचनबद्ध करू शकते. त्या लवचिकतेला खरे मूल्य असते, आणि तिकडे दुर्लक्ष केल्याने टप्प्याटप्प्याच्या गुंतवणुकींचे एकदम-वचनबद्धतेच्या तुलनेत पद्धतशीरपणे कमी मूल्यमापन होते, जे सुरक्षित दिसणाऱ्या टप्प्याटप्प्याच्या प्रस्तावाला बक्षीस देणाऱ्या खरेदी प्रक्रियांसाठी अगदी उलटे आहे. रिअल ऑप्शन्स मूल्यमापन लवचिकतेचीच किंमत ठरवते, म्हणून टप्प्याटप्प्याच्या प्रस्तावाची पूर्ण-वचनबद्धता पर्यायाशी निष्पक्ष तुलना करता येते, भोळ्या NPV ओळीवर लहान दिसल्याबद्दल दंड न देता.

## गणित

```
Risk-neutral probability of the "up" state:
  p = ((1 + risk_free_rate) − down_factor) / (up_factor − down_factor)

Expansion payoff in each state (floored at zero — expanding is optional):
  payoff_up   = max(project_value × up_factor   − expansion_cost, 0)
  payoff_down = max(project_value × down_factor − expansion_cost, 0)

Option value (discounted expected payoff):
  option_value = (p × payoff_up + (1 − p) × payoff_down) / (1 + risk_free_rate)

Expanded NPV = static_npv + option_value
```

पुढील निर्णय बिंदूपर्यंत प्रकल्पाचे मूल्य एकतर वाढते (`up_factor`) किंवा घटते (`down_factor`). विस्तार केवळ त्या अवस्थेत फायदेशीर असेल तरच वापरला जातो — शून्यावरील मोबदला किमान मर्यादा हेच यास बंधन नव्हे तर खरा *पर्याय* बनवते. आधी माहिती गोळा करण्याच्या पर्यायाऐवजी, नंतर विस्तारण्याच्या पर्यायाची किंमत ठरवण्यासाठी [परिपूर्ण माहितीचे अपेक्षित मूल्य](../परिपूर्ण-माहितीचे-अपेक्षित-मूल्य/) पहा. तो निर्णय घेण्यासाठी थांबण्याच्या खर्चासाठी [विलंबाचा खर्च](../विलंबाचा-खर्च/) पहा.

## सोडवलेले उदाहरण

डिजिटल सेवा पायलट ज्यात `project_value = £1,000,000`, पुढील निर्णय बिंदूपर्यंत 1.5× पर्यंत वाढ किंवा 0.5× पर्यंत घट शक्य, 8% जोखीम-मुक्त दर, आणि £600,000 विस्तार खर्च:

```
p = (1.08 − 0.5) / (1.5 − 0.5) = 0.58

payoff_up   = max(1,000,000 × 1.5 − 600,000, 0) =  900,000
payoff_down = max(1,000,000 × 0.5 − 600,000, 0) = max(−100,000, 0) = 0

The floor matters: the option would NOT be exercised if the market
disappoints — the £600,000 expansion cost exceeds the £500,000 the
project would be worth in the down state.

option_value = (0.58 × 900,000 + 0.42 × 0) / 1.08
             = 522,000 / 1.08
             ≈ £483,333.33
```

£200,000 च्या स्थिर-NPV मूलरेषेत पर्यायाचे मूल्य जोडा: विस्तारित NPV = 200,000 + 483,333.33 ≈ **£683,333.33**. या पर्याय मूल्याशिवाय फक्त £200,000 स्थिर NPV नोंदवणे टप्प्याटप्प्याच्या प्रकल्पाचे खरे मूल्य दुपटीपेक्षा जास्त कमी दाखवले असते.

## सॉफ्टवेअर अभियांत्रिकीशी संबंध

"आता किमान आवृत्ती पाठवा, तो चालला तर पुढे गुंतवणुकीचा पर्याय राखा" याची ही औपचारिक आवृत्ती आहे — टप्प्याटप्प्याच्या डिजिटल आरोग्य उत्पादन रोलआउटशी थेट संबंधित, [विलंबाचा खर्च](../विलंबाचा-खर्च/) आणि [WSJF/CD3](../wsjf-आणि-cd3/) च्या अनिश्चिततेखालील क्रमवारी मांडणीशी रचनात्मकदृष्ट्या समांतर, आणि [परिपूर्ण माहितीचे अपेक्षित मूल्य](../परिपूर्ण-माहितीचे-अपेक्षित-मूल्य/) व [नमुना माहितीचे अपेक्षित मूल्य](../नमुना-माहितीचे-अपेक्षित-मूल्य/) यांना पूरक — तिन्ही अनिश्चिततेखाली लवचिकता किंवा माहितीची किंमत वेगवेगळ्या कोनांतून ठरवतात.

## सामान्य चुका

- **ज्यावर ते अवलंबून आहे ते व्यापार-मालमत्ता गृहीतक न मानता जोखीम-तटस्थ किंमत उसनी घेणे**: रिअल ऑप्शन्स मॉडेल्स आर्थिक ऑप्शन किंमतीतून जोखीम-तटस्थ संभाव्यता उसनी घेतात, जी गृहीत धरते की अंतर्निहित मूल्य *व्यापार केलेली* मालमत्ता आहे — खरोखर व्यापार न होणाऱ्या खऱ्या प्रकल्पासाठी हे मॉडेलिंग सोय आहे, शब्दशः बाजार तथ्य नाही.
- **`up_factor`/`down_factor` ला मुक्त पॅरामीटर मानणे**: द्विपद वर/खाली इनपुट स्वतः समर्थन आवश्यक असलेली गृहीतके आहेत, हवा तो उत्तर देण्यासाठी निवडलेले मुक्त पॅरामीटर नाहीत.
- **फक्त पर्यायाचे मूल्य नोंदवणे**: रिअल ऑप्शन्स मूल्य स्वतंत्र प्रकल्पाच्या स्थिर NPV मध्ये *जोडले* जाते — सामान्य चूक म्हणजे फक्त पर्याय मूल्य नोंदवून मूळ प्रकरण वगळणे, जे स्थिर NPV ऋण असल्यास प्रकरण अतिरंजित करते आणि स्थिर NPV पूर्णपणे वगळल्यास (वरील सोडवलेल्या उदाहरणाप्रमाणे) कमी दाखवते.
