# वर्चस्व आणि कार्यक्षमता सीमा

एखादा पर्याय **वर्चस्वित** असतो जर दुसरा पर्याय कमी खर्चात *आणि* जास्त परिणाम देतो. **कार्यक्षमता सीमा** म्हणजे वर्चस्वित पर्याय काढून टाकल्यानंतर उरते ते: निवडींचा संच जिथे जास्त मिळवण्यासाठी जास्त पैसे द्यावे लागतात.

## हे का महत्त्वाचे आहे

थ्रेशोल्ड किंवा अंदाजपत्रकांवरील कोणत्याही वादापूर्वी, आरोग्य तंत्रज्ञान मूल्यमापन आधी असे पर्याय काढून टाकते जे कोणीही कधीही निवडू नयेत. प्रत्येक पर्याय खर्च-विरुद्ध-परिणाम पटलावर मांडून सीमा काढणे हा पाच मिनिटांचा सराव आहे जो नियमितपणे निम्मी निवड यादी संपवतो. वाढीव तुलना ([ICER](../वाढीव-खर्च-परिणामकारकता-गुणोत्तर/)) नंतर फक्त *सीमेवर* काढल्या जातात, प्रत्येक पर्याय पुढच्या सर्वात स्वस्त अ-वर्चस्वित पर्यायाविरुद्ध — चांगले मधले पर्याय असताना कधीही "काही न करणे" विरुद्ध नाही.

## गणित

```
Strict dominance:   A dominates B if Cost_A ≤ Cost_B and Effect_A ≥ Effect_B
                    (with at least one strict inequality)

Extended dominance: B is ruled out if a mix of A and C achieves more effect
                    per pound — detected when ICERs decrease as you move up
                    the frontier. Valid frontier ICERs must be increasing.
```

प्रक्रिया: पर्याय परिणामानुसार क्रमवारी लावा; काटेकोरपणे वर्चस्वित पर्याय काढा; शेजारी पर्यायांमधील जोडी ICER काढा; ज्या पर्यायाचा ICER पुढच्या अधिक-परिणामकारक पर्यायाच्या ICER पेक्षा जास्त आहे तो काढा (विस्तारित वर्चस्व); ICER एकसुरीपणे वाढेपर्यंत पुन्हा करा.

## सोडवलेले उदाहरण

चुकलेल्या भेटी कमी करण्याचे चार पर्याय (परिणाम = दरवर्षी वसूल झालेल्या भेटी):

```
Option          Cost/yr    Recovered
Do nothing      £0         0
SMS reminders   £20,000    2,000
Phone calls     £120,000   2,200
SMS + AI triage £90,000    3,500
```

फोन कॉल्स SMS + AI ट्रायाज द्वारे **काटेकोरपणे वर्चस्वित** आहेत (जास्त खर्च, कमी वसुली). सीमा: काही नाही → SMS → SMS + AI.

```
ICER(SMS vs nothing)   = 20,000 / 2,000  = £10 per appointment recovered
ICER(SMS+AI vs SMS)    = (90,000 − 20,000) / (3,500 − 2,000) = £46.67 per appointment
```

वाढते ICER → वैध सीमा. वसूल झालेल्या प्रत्येक रुग्णालय भेटीमागे ~£160 बचतीवर ([उपस्थित न राहण्याचा दर](../उपस्थित-न-राहण्याचा-dna-दर/) पहा), सीमेवरील दोन्ही पायऱ्या घेण्यासारख्या आहेत; फोन-बँक प्रस्ताव समितीपर्यंत पोहोचूच नये.

## सॉफ्टवेअर अभियांत्रिकीशी संबंध

कोणत्याही टूलिंग निर्णयासाठी तोच तक्ता बनवा: एका अक्षावर प्रति वर्ष खर्च, दुसऱ्यावर मोजलेला परिणाम (वाचलेले तास, टाळलेल्या घटना, सक्षम झालेल्या तैनाती). सीमेच्या वर-डावीकडील बिंदू अंदाजपत्रकावर कोणी वाद घालण्यापूर्वीच बाद होतात. हे विक्रेता निवडीला वैशिष्ट्य-यादी वादांपासून "तुम्ही वर्चस्वित आहात; बैठक संपली" पर्यंत नेते. तसेच किरकोळ फायद्यासाठी सर्वात महाग पर्याय खरेदी करण्याचा सामान्य एंटरप्राइझ नमुना उघड करते — वाढीव एककामागील वाढीव किंमत संस्था जाणूनबुजून द्यायला तयार असेल तरच ते वैध.

## सामान्य चुका

- **सर्वकाही मूलरेषेशी तुलना** सीमेवरील पुढच्या पर्यायाऐवजी — हे स्वस्त जवळपास-समतुल्य पर्याय लपवून महागड्या पर्यायांची खुशामत करते.
- **एक-परिमाणी परिणाम गुण** जे महत्त्वाचे लपवतात; दोन परिणाम महत्त्वाचे असतील तर त्यांना समर्थनीयरीत्या एकत्र करा ([खर्च-उपयुक्तता विश्लेषण](../खर्च-उपयुक्तता-विश्लेषण/) पहा) किंवा दोन सीमा दाखवा.
- **अनिश्चितता विसरणे**: सीमेजवळील पर्याय [संवेदनशीलता विश्लेषण](../संवेदनशीलता-विश्लेषण/) अंतर्गत जागा बदलू शकतात.
