# غلبه و مرز کارایی

یک گزینه **مغلوب** است اگر گزینه دیگری هم کم‌هزینه‌تر *و* هم بیشتر ارائه دهد. **مرز کارایی** آنچه پس از حذف گزینه‌های مغلوب می‌ماند: مجموعه انتخاب‌هایی که در آنها بیشتر گرفتن مستلزم بیشتر پرداختن است.

## چرا اهمیت دارد

پیش از هرگونه بحث درباره آستانه‌ها یا بودجه‌ها، ارزیابی فناوری سلامت ابتدا گزینه‌هایی را که هیچ‌کس نباید هرگز انتخاب کند حذف می‌کند. رسم هر گزینه روی صفحه هزینه-در-برابر-اثر و کشیدن مرز تمرینی پنج‌دقیقه‌ای است که به‌طور معمول نیمی از فهرست کوتاه را می‌کشد. مقایسه‌های افزایشی ([ICERها](../نسبت-هزینه-اثربخشی-افزایشی/)) سپس فقط *در امتداد مرز* محاسبه می‌شوند، هر گزینه در برابر ارزان‌ترین گزینه بعدی غیرمغلوب — هرگز در برابر «هیچ‌کاری نکردن» وقتی گزینه‌های میانی بهتر وجود دارند.

## ریاضیات

```
Strict dominance:   A dominates B if Cost_A ≤ Cost_B and Effect_A ≥ Effect_B
                    (with at least one strict inequality)

Extended dominance: B is ruled out if a mix of A and C achieves more effect
                    per pound — detected when ICERs decrease as you move up
                    the frontier. Valid frontier ICERs must be increasing.
```

رویه: گزینه‌ها را بر اساس اثر مرتب کنید؛ گزینه‌های اکیداً مغلوب را حذف کنید؛ ICERهای زوجی بین همسایه‌ها را محاسبه کنید؛ هر گزینه‌ای را که ICER آن از ICER گزینه مؤثرتر بعدی بیشتر است حذف کنید (غلبه گسترده)؛ تا زمانی که ICERها یکنوا افزایش یابند تکرار کنید.

## مثال حل‌شده

چهار گزینه برای کاهش نوبت‌های ازدست‌رفته (اثر = نوبت‌های بازیابی‌شده در سال):

```
Option          Cost/yr    Recovered
Do nothing      £0         0
SMS reminders   £20,000    2,000
Phone calls     £120,000   2,200
SMS + AI triage £90,000    3,500
```

تماس‌های تلفنی توسط SMS + تریاژ هوش مصنوعی **اکیداً مغلوب** می‌شوند (گران‌تر و کم‌تر بازیابی). مرز: هیچ ← SMS ← SMS + AI.

```
ICER(SMS vs nothing)   = 20,000 / 2,000  = £10 per appointment recovered
ICER(SMS+AI vs SMS)    = (90,000 − 20,000) / (3,500 − 2,000) = £46.67 per appointment
```

ICERهای افزایشی ← مرز معتبر. با حدود £160 صرفه‌جویی به ازای هر نوبت بیمارستانی بازیابی‌شده (به [نرخ عدم حضور](../نرخ-عدم-حضور/) نگاه کنید)، هر دو گام مرز ارزش برداشتن دارند؛ پیشنهاد مرکز تماس هرگز نباید به کمیته برسد.

## ارتباط با مهندسی نرم‌افزار

همین نمودار را برای هر تصمیم ابزار بسازید: هزینه در سال روی یک محور، پیامد اندازه‌گیری‌شده (ساعت صرفه‌جویی‌شده، رخداد اجتناب‌شده، استقرار ممکن‌شده) روی محور دیگر. نقاط بالا-و-چپ مرز پیش از آنکه کسی درباره بودجه بحث کند حذف می‌شوند. این انتخاب فروشنده را از بحث فهرست‌های قابلیت به «شما مغلوب هستید؛ جلسه تمام شد» بازچارچوب می‌کند. همچنین الگوی رایج سازمانی خرید گران‌ترین گزینه برای دستاوردی حاشیه‌ای را آشکار می‌کند — فقط وقتی مشروع است که قیمت افزایشی به ازای هر واحد افزایشی قیمتی باشد که سازمان آگاهانه می‌پردازد.

## تله‌ها و اشتباهات رایج

- **مقایسه همه‌چیز با خط پایه** به‌جای گزینه بعدی روی مرز — با پنهان کردن هم‌ارزهای نزدیک ارزان‌تر، گزینه‌های گران را چاپلوسی می‌کند.
- **امتیازهای اثر تک‌بُعدی** که آنچه مهم است را پنهان می‌کنند؛ اگر دو پیامد اهمیت دارند، یا آنها را به‌طور قابل‌دفاعی ترکیب کنید (به [تحلیل هزینه-مطلوبیت](../تحلیل-هزینه-مطلوبیت/) نگاه کنید) یا دو مرز نشان دهید.
- **فراموش کردن عدم‌قطعیت**: گزینه‌های نزدیک مرز ممکن است زیر [تحلیل حساسیت](../تحلیل-حساسیت/) جایشان را عوض کنند.
