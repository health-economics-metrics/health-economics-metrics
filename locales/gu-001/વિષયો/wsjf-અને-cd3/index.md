# WSJF અને CD3

CD3 (વિલંબનો ખર્ચ ભાગ્યા સમયગાળો) અને WSJF (ભારિત સૌથી ટૂંકું કામ પ્રથમ) એ પ્રાથમિકતા નિયમો છે જે કામને **મૂલ્ય-ઘનતા** પ્રમાણે શેડ્યૂલ કરે છે: વપરાયેલી દુર્લભ ક્ષમતાના એકમ દીઠ કેટલો વિલંબ ખર્ચ દૂર થાય છે. સહિયારી, નિશ્ચિત ક્ષમતા હેઠળ, કુલ વિલંબ ખર્ચ ઓછો કરવા માટે સર્વોચ્ચ-CD3-પ્રથમ ગાણિતિક રીતે શ્રેષ્ઠ ક્રમ છે.

## આ શા માટે મહત્ત્વનું છે

દરેક બૅકલૉગ રેશનિંગ સમસ્યા છે: ઘણી લાયક આઇટમ, એક પાઇપલાઇન. આરોગ્ય અર્થશાસ્ત્રે આરોગ્ય બજેટ માટે એ જ સમસ્યા ખર્ચ-અસરકારકતા લીગ ટેબલથી ઉકેલી: હસ્તક્ષેપોને પ્રતિ પાઉન્ડ મેળવેલા આરોગ્ય પ્રમાણે ક્રમ આપો, બજેટ ખૂટે ત્યાં સુધી યાદી નીચે ભંડોળ આપો. CD3 ડિલિવરી ક્ષમતા માટે એ જ તર્ક છે: *અવરોધક સંસાધન*ના એકમ દીઠ લાભ, ક્રમ પ્રમાણે ભંડોળિત. ક્રમ સાચો મેળવવો મફત પૈસા છે — એ જ કામ, એ જ ક્ષમતા, ઓછો કુલ વિલંબ ખર્ચ.

## ગણિત

```
CD3  = Cost of Delay (£/week) / Duration (weeks)      — real units (Black Swan Farming)

WSJF = (user-business value + time criticality + risk reduction/opportunity
        enablement) / job size                         — SAFe's relative-scale proxy,
                                                        modified-Fibonacci scores
```

સાચા ચલણ સાથેનું CD3 ([વિલંબની કિંમત](../વિલંબની-કિંમત/)) WSJF ના એકમ-વિહીન પૉઇન્ટ કરતાં કડક રીતે વધુ મજબૂત છે — WSJF એ CD3 માટે તે છે જે બહુ-માપદંડ સ્કોરિંગ સંપૂર્ણ [ખર્ચ-ઉપયોગિતા વિશ્લેષણ](../ખર્ચ-ઉપયોગિતા-વિશ્લેષણ/) માટે છે: નાણાંમાં ફેરવવું અવ્યવહારુ હોય ત્યારે ઉપયોગી, સ્કોરનો કોઈ ઍન્કર ન હોય ત્યારે ગેમ થઈ શકે એવું.

## ઉકેલેલું ઉદાહરણ

ત્રણ ફીચર, એક ટીમ:

```
Feature   CoD (£/wk)   Duration   CD3
A         30,000       10 wks     3,000
B         12,000       2 wks      6,000
C         5,000        1 wk       5,000
```

CD3 ક્રમ: B, C, A. "સૌથી મોટું CoD પ્રથમ" (A, B, C) સામે કુલ વિલંબ ખર્ચ સરખાવો:

```
CD3 order  (B,C,A): A waits 3 wks, C waits 2 → 30k×3 + 5k×2  = £100k delay cost
CoD order  (A,B,C): B waits 10, C waits 12   → 12k×10 + 5k×12 = £180k
```

એ જ ફીચર, એ જ ટીમ — ફક્ત ક્રમથી £80,000 બચે છે. અંતઃપ્રેરણા: નાની, તાકીદની આઇટમ પ્રથમ જાય છે કારણ કે તે પોતાનો વિલંબ ખર્ચ સસ્તામાં મુક્ત કરે છે; મોટી આઇટમ થોડું રાહ જોતાં ઓછું ગુમાવે છે.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

આરોગ્યસંભાળ સૉફ્ટવેર પોર્ટફોલિયો માટે, CoD ને આ રિપોઝિટરી શીખવતી એકમોમાં દર્શાવો: QALY/અઠવાડિયું × સીમા + ઑપરેશનલ £/અઠવાડિયું, અને બૅકલૉગ સીધો તે રીત સાથે તુલનીય બને છે જેમાં આરોગ્ય તંત્ર બાકી બધું ખરીદતાં ક્રમ આપે છે. બે પ્રૅક્ટિસ નોંધ: (1) સમયગાળો એટલે અવરોધને રોકતો *કૅલેન્ડર સમય*, પ્રયત્ન નહીં — બાધક ટીમના 2 દિવસ જોઈતી 2-અઠવાડિયાની વીતેલી આઇટમ દેખાય છે તેના કરતાં સસ્તી છે ([ડાઉનસ્ટ્રીમ સંસાધન ઑપ્ટિમાઇઝેશન](../ડાઉનસ્ટ્રીમ-સંસાધન-ઑપ્ટિમાઇઝેશન/) જુઓ); (2) હૉસ્પિટલો થિયેટર લિસ્ટને તાકીદ-ભારિત થ્રૂપુટ પ્રમાણે ગોઠવતાં એ જ નિયમ ગર્ભિત રીતે ચલાવે છે — ક્લિનિકલ પ્રાથમિકતા શ્રેણીઓ ગંભીરતા-ભારિત CD3 છે ([QALY કમી અને ગંભીરતા સંશોધકો](../qaly-ઘટ-અને-ગંભીરતા-સંશોધકો/) જુઓ).

## સામાન્ય ભૂલો

- **WSJF સ્કોર નાટક**: એકમ-વિહીન Fibonacci ચર્ચાઓ જે સૌથી મોટેથી દલીલ કરે તેના પર ભેગી થાય છે; ઓછામાં ઓછી બૅકલૉગની ટોચની આઇટમ વાસ્તવિક CoD માં ઍન્કર કરો.
- **સમયગાળા સાથે રમત**: CD3 ક્રમ ફુલાવવા આઇટમ વિભાજિત કરવી — વિભાગો સ્વતંત્ર રીતે મૂલ્ય આપે ત્યારે ઠીક, ન આપે ત્યારે છેતરપિંડી.
- **તાકીદ પ્રોફાઇલ અવગણવી**: સમયમર્યાદા-આકારનું CoD (નિયમનકારી તારીખો) સ્થિર-દર ધારણા તોડે છે; તેમને તારીખ શક્યતા પ્રમાણે શેડ્યૂલ કરો, પછી બાકીના પર CD3.
- **પુનઃ-ક્રમ ઊથલપાથલ**: CD3 પ્રતિબદ્ધતા સમયે ક્રમ નિર્ણયો માટે છે, ચાલુ કાર્યના દૈનિક પુનઃ-ગોઠવણ માટે નહીં (WIP પર [ફ્લો મેટ્રિક્સ](../ફ્લો-મેટ્રિક્સ/) જુઓ).
