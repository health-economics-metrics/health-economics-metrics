# ટેકનિકલ ડેટ

ટેકનિકલ ડેટ એટલે કોડબેઝમાં ભૂતકાળના ઉતાવળિયા નિર્ણયોનો ગર્ભિત ભાવિ ખર્ચ: બાકી સુધારણા કાર્ય (**મૂળ રકમ**) અને ડિલિવરી પર તે જે સતત ખેંચાણ મૂકે છે (**વ્યાજ**). SQALE જેવી માત્રાત્મક પદ્ધતિઓ તેને રૂપકમાંથી ખર્ચ-આંકેલી જવાબદારીમાં ફેરવે છે.

## આ શા માટે મહત્ત્વનું છે

માપ્યા વગર, ટેક ડેટ ફરિયાદ છે; માપ્યા પછી, તે બિઝનેસ કેસ છે. ઉદ્યોગ આધારરેખા (CAST Appmarq, 1,400 ઍપ / 550M LOC): ઐતિહાસિક રીતે ≈ **કોડની પ્રતિ લાઇન $3.61 ટેકનિકલ-ડેટ મૂળ રકમ**, સામાન્ય કોડબેઝ પુનઃનિર્માણ ખર્ચના 15–20% ડેટ ગુણોત્તર ધરાવે છે, જ્યારે સામાન્ય રીતે વપરાતું આરોગ્ય ધોરણ ≤5% છે (SonarQube નો "A" ગ્રેડ). આરોગ્ય-અર્થશાસ્ત્રનું માળખું બરાબર બંધ બેસે છે: ડેટ *દીર્ઘકાલીન સ્થિતિ* છે — સારવાર વગર તે પ્રગતિ કરે છે, તેનું "વ્યાજ" ધીમી ડિલિવરી અને ઊંચા ખામી દર તરીકે ચક્રવૃદ્ધિ પામે છે, અને સુધારણા ક્ષમતા માટે ફીચર કાર્ય સામે સ્પર્ધા કરે છે, જેમ નિવારણ સારવાર સામે કરે છે.

## ગણિત

```
SQALE principal   = Σ over violations (remediation time) × developer cost rate
Technical debt ratio (TDR) = remediation cost / redevelopment cost × 100
                    (SonarQube grades: A ≤ 5%, B ≤ 10%, C ≤ 20%, D ≤ 50%)

Interest (the number that justifies paydown):
  interest/year = Δ delivery velocity × value per unit velocity
                + Δ defect rate × cost per defect
Paydown case  = PV(interest avoided over horizon) − remediation cost
                (discounted — see discounting-and-time-preference.md)
```

મૂળ રકમ જવાબદારી દર્શાવે છે; **વ્યાજ** રોકાણનો કેસ બનાવે છે. £40k/વર્ષ વ્યાજ ટાળવા £500k મૂળ રકમ ચૂકવવી ખરાબ સોદો છે; £400k/વર્ષ ટાળવા, ઉત્તમ.

## ઉકેલેલું ઉદાહરણ

400k-LOC ક્લિનિકલ-રેકોર્ડ ઇન્ટિગ્રેશન લેયર: SQALE મૂળ રકમ 3,800 કલાક × £75 = **£285k**; TDR ≈ 12% (ગ્રેડ C). માપેલ વ્યાજ: આ લેયરને સ્પર્શતી ટીમોના સાયકલ સમય 40% લાંબા અને ચેન્જ-ફેલ્યોર દર સમગ્ર એસ્ટેટ આધારરેખા કરતાં 2× છે. લેયર 6,000 ડેવ-કલાક/વર્ષ શોષે છે:

```
Interest ≈ 6,000 × 0.40 × £75      = £180,000/year (velocity drag)
         + 12 extra failures × £8,000 = £96,000/year (rework/incidents)
         ≈ £276,000/year

Remediate the worst 30% of principal (£85k) targeting hotspots → modelled
interest reduction 60%: saves ~£166k/year. Payback ≈ 6 months.
```

હૉટસ્પૉટ લક્ષ્યીકરણ મહત્ત્વનું છે: ડેટ વ્યાજ ત્યાં કેન્દ્રિત થાય છે જ્યાં ફેરફાર આવૃત્તિ × ડેટ ઘનતા શિખરે હોય — ભાગ્યે જ સ્પર્શાતી ડેટ સુધારવાથી કંઈ મળતું નથી, જાણે એવી સ્થિતિની સારવાર જે ક્યારેય આગળ વધત નહીં ([નિવારણ અર્થશાસ્ત્ર](../નિવારણ-અર્થશાસ્ત્ર/)).

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

ટેક-ડેટ દલીલોને ઉન્નત કરતી આરોગ્ય-અર્થશાસ્ત્રની આયાતો: એસ્ટેટને **બોજ યાદી** તરીકે વ્યક્ત કરો ([DALY](../અપંગતા-સમાયોજિત-જીવન-વર્ષ/)-શૈલી — ગુમાવેલાં સ્વસ્થ એન્જિનિયરિંગ-વર્ષ ક્યાં છે?); પ્રગતિ ગણિતથી, પ્રામાણિકપણે, ચુકવણી વાજબી ઠેરવો (સામાન્ય રીતે ખર્ચ-અસરકારક, ખર્ચ-બચત નહીં); સૌથી ખરાબ સિસ્ટમોના સુધારણાને [ગંભીરતા કમી](../qaly-ઘટ-અને-ગંભીરતા-સંશોધકો/) થી ભારિત કરો; અને મોટા સુધારણા પ્રસ્તાવોને [ટાળેલા ડાઉનસ્ટ્રીમ ખર્ચ](../ટાળેલા-ડાઉનસ્ટ્રીમ-ખર્ચ/) ના નિયમો ટકાવતા સરભર વિશ્લેષણ સાથે રજૂ કરો — સંભાવના-ભારિત, ડિસ્કાઉન્ટેડ, એક જ વાર ગણાયેલું.

## સામાન્ય ભૂલો

- **ફક્ત-મૂળ-રકમ અહેવાલ**: વ્યાજ અંદાજ વગરનો મોટો ભયાનક આંકડો કંઈ વાજબી ઠેરવતો નથી.
- **ટૂલ-જનિત ડેટ આંકડા શબ્દશઃ લેવા**: SQALE નિયમ ઉલ્લંઘન ગણે છે; તે આર્કિટેક્ચરલ ડેટ (મોંઘી પ્રકારની) ચૂકે છે અને નજીવી બાબતો ગણે છે.
- **ડેટ-શૂન્ય યુટોપિયાવાદ**: શ્રેષ્ઠ ડેટ સ્તર શૂન્ય નથી — ડેટ લિવરેજ છે; પ્રશ્ન વ્યાજ દરનો છે.
- **"રીરાઇટ બધું ટાળે છે"**: રીરાઇટ પ્રસ્તાવોએ એ જ સરભર નિયમો પાસ કરવા જોઈએ — પ્રતિતથ્ય ખર્ચ, સંભાવના, ડિસ્કાઉન્ટિંગ.
