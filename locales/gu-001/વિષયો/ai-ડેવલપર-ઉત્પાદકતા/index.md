# AI ડેવલપર ઉત્પાદકતા

AI કોડિંગ સહાય એન્જિનિયરિંગ આઉટપુટ પર ખરેખર શું અસર કરે છે તેના મેટ્રિક્સ: સૂચન સ્વીકાર દર, નિયંત્રિત-અભ્યાસ ઝડપ-વધારો, PR થ્રુપુટ અને કોડ જાળવણી. પુરાવા-આધાર સાચા અર્થમાં વિરોધાભાસી છે — જે તેને અસરકારકતા-વિરુદ્ધ-કાર્યક્ષમતાના ભેદ માટે ઉત્તમ કેસ સ્ટડી બનાવે છે, જેને સંભાળવા માટે જ આરોગ્ય અર્થશાસ્ત્ર ઘડાયું છે.

## આ શા માટે મહત્ત્વનું છે

સૌથી વધુ ટાંકવામાં આવતા બે નિયંત્રિત અભ્યાસો વિરુદ્ધ દિશામાં ઇશારો કરે છે:

- **Peng et al. 2023 (GitHub Copilot RCT)**: ડેવલપર્સે Copilot સાથે નવા HTTP-સર્વર કાર્યને **55.8% ઝડપથી** પૂરું કર્યું (1h11m વિરુદ્ધ 2h41m, n=95).
- **METR 2025 RCT**: *પોતાના પરિપક્વ રિપોઝિટરીઓ* પર કામ કરતા અનુભવી ઓપન-સોર્સ ડેવલપર્સ 2025ની શરૂઆતના AI સાધનો સાથે **19% ધીમા** હતા (16 ડેવલપર્સ, 246 કાર્યો) — જ્યારે તેઓ *માનતા* હતા કે તેઓ 20% ઝડપી છે.

બંને સારા અભ્યાસો છે. વિરોધાભાસ જ તારણ છે: નવા-કાર્યની અસરકારકતા (efficacy) પરિપક્વ-કોડબેઝની કાર્યક્ષમતા (effectiveness)માં ટ્રાન્સફર થતી નથી, અને *અનુભવાયેલો* લાભ માપેલા લાભનું સ્થાન લઈ શકતો નથી. દવા પાસે બંને ઘટનાઓ માટે નામો છે (સમજૂતીરૂપ વિરુદ્ધ વ્યવહારુ ટ્રાયલ; પ્લેસિબો સમસ્યા) અને તેમને સંભાળવાની પદ્ધતિ છે.

## ગણિત

```
Acceptance rate  = accepted suggestions / shown suggestions
                   (GitHub telemetry ~30% avg; varies: SQL 45%, Python 35%, JS 28%)
Retention rate   = AI code surviving to merge / accepted AI code (~88% reported)
Speedup          = (t_control − t_AI) / t_control  (from controlled comparison ONLY)
Throughput delta = Δ merged PRs/dev/week (GitHub/Accenture field data: +8.7%)

Value model     = devs × time saved × loaded rate × utilization factor
                  — every term needs local measurement; see the tornado in
                  sensitivity-analysis.md, where time-saved dominates all
                  other parameters combined
```

## ઉકેલેલું ઉદાહરણ

500 ડેવલપર્સની એક સંસ્થા યોગ્ય નિયંત્રણ સાથે (મેળ ખાતી ટીમો, 3 મહિના, પૂર્વ-નોંધાયેલા મેટ્રિક્સ) સહાયકનું પાયલટ કરે છે:

```
Pilot result: PR cycle time −18%; merged PRs +6%; CFR unchanged;
              self-reported time saved 45 min/day; measured task-level ≈ 15 min/day

Value the MEASURED number: 500 × 0.25h × 220d × £60 × 0.6 utilization
                          ≈ £990,000/year capacity (non-cash-releasing)
Cost: 500 × £39/mo × 12 ≈ £234,000/year
Net capacity ratio ≈ 4:1 — fundable, at one-third the self-reported claim.
```

અનુભવાયેલા અને માપેલા વચ્ચેનું 3× અંતર એ METR તારણ છે જે વાસ્તવિક દુનિયામાં કામ કરી રહ્યું છે; સ્વ-અહેવાલ પર બજેટ બનાવ્યું હોત તો લાભ પંક્તિ ત્રણ ગણી થઈ ગઈ હોત.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

AI ટૂલિંગનું મૂલ્યાંકન કરનાર કોઈપણ માટે આરોગ્ય-અર્થશાસ્ત્રની આયાતો: **વ્યવહારુ ટ્રાયલ** ચલાવો (તમારો કોડબેઝ, તમારા એન્જિનિયરો, વાસ્તવિક ટિકિટો — વેન્ડર ડેમો કાર્યો નહીં); **સ્વીકાર દરને પરિણામ નહીં, પ્રોક્સી ગણો** (ડેવલપરના દૃષ્ટિકોણથી તે સૂચનોનો [PPV](../ક્લિનિકલ-ai-મૂલ્યાંકન/) છે — ઊંચો સ્વીકાર અને નીચી જાળવણી એટલે અતિનિદાન); દરેક થ્રુપુટ લાભ સાથે **સ્થિરતા તપાસ** જોડો (DORA 2025: AI થ્રુપુટ વધારે છે, સ્થિરતાને નુકસાન કરે છે — આડઅસરોવાળા હસ્તક્ષેપને ચોખ્ખા-લાભ વિશ્લેષણની જરૂર છે, [DORA મેટ્રિક્સ](../dora-મેટ્રિક્સ/) મુજબ); અને લાભને પ્રામાણિકપણે ક્ષમતા તરીકે વર્ગીકૃત કરો ([રોકડ-મુક્તિકારક વિરુદ્ધ બિન-રોકડ-મુક્તિકારક](../રોકડ-મુક્તિકારક-વિરુદ્ધ-બિન-રોકડ-મુક્તિકારક-બચત/)).

## સામાન્ય ભૂલો

- **વેન્ડર-અભ્યાસનું પ્રત્યારોપણ**: નવા-કાર્યના RCT આંકડા લેગસી-કોડબેઝના કામ પર લાગુ કરવા — METR અભ્યાસે જે ભૂલ ખુલ્લી પાડી તે જ.
- **માપન તરીકે સ્વ-અહેવાલ**: 20-ટકા-બિંદુનું ધારણા અંતર આ સાહિત્યમાં જાણીતો સૌથી મોટો પૂર્વગ્રહ છે.
- **પ્રવૃત્તિ ફુગાવો**: વધુ PR અને વધુ કોડ એ પ્રવૃત્તિ છે, પરિણામ નહીં ([SPACE](../space-અને-devex/)); રીવર્ક અને CFR સાથે જોડો.
- **શીખવાના વક્રની અવગણના**: બીજા સપ્તાહના માપ કોઈપણ દિશામાં નવીનતાની અસરો પકડે છે; સ્થિર અવસ્થામાં માપો ([સમય-ક્ષિતિજ](../સમય-ક્ષિતિજ/)).
