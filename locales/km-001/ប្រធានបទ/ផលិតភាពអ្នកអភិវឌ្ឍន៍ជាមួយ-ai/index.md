# ផលិតភាពអ្នកអភិវឌ្ឍន៍ជាមួយ AI

រង្វាស់នៃអ្វីដែលជំនួយកូដ AI ធ្វើចំពោះលទ្ធផលវិស្វកម្មពិតប្រាកដ៖ អត្រាទទួលយកសំណើ ល្បឿនកើនឡើងក្នុងការសិក្សាមានការគ្រប់គ្រង ទិន្នផល PR និងការរក្សាកូដ។ មូលដ្ឋានភស្តុតាងពិតជាផ្ទុយគ្នា — ដែលធ្វើឱ្យវាក្លាយជាករណីសិក្សាល្អឥតខ្ចោះនៃភាពខុសគ្នារវាងប្រសិទ្ធភាពក្នុងលក្ខខណ្ឌល្អ (efficacy) និងប្រសិទ្ធភាពក្នុងការអនុវត្តជាក់ស្តែង (effectiveness) ដែលសេដ្ឋកិច្ចសុខាភិបាលត្រូវបានបង្កើតឡើងដើម្បីដោះស្រាយ។

## ហេតុអ្វីបានជាសំខាន់

ការសិក្សាមានការគ្រប់គ្រងពីរដែលត្រូវបានដកស្រង់ច្រើនបំផុត ចង្អុលទៅទិសដៅផ្ទុយគ្នា៖

- **Peng et al. 2023 (RCT របស់ GitHub Copilot)**៖ អ្នកអភិវឌ្ឍន៍បំពេញកិច្ចការម៉ាស៊ីនបម្រើ HTTP ថ្មីស្រឡាង **លឿនជាង 55.8%** ជាមួយ Copilot (1h11m ធៀបនឹង 2h41m, n=95)។
- **METR 2025 RCT**៖ អ្នកអភិវឌ្ឍន៍កូដបើកចំហដែលមានបទពិសោធន៍ ធ្វើការលើ *ឃ្លាំងកូដចាស់ទុំរបស់ខ្លួនឯង* **យឺតជាង 19%** ជាមួយឧបករណ៍ AI ដើមឆ្នាំ 2025 (អ្នកអភិវឌ្ឍន៍ 16 នាក់ កិច្ចការ 246) — ខណៈដែល *ជឿថា* ខ្លួនលឿនជាង 20%។

ការសិក្សាទាំងពីរល្អ។ ភាពផ្ទុយគ្នាគឺជាការរកឃើញ៖ ប្រសិទ្ធភាពក្នុងកិច្ចការថ្មីស្រឡាងមិនផ្ទេរទៅប្រសិទ្ធភាពក្នុងកូដចាស់ទុំទេ ហើយអត្ថប្រយោជន៍ដែល *យល់ឃើញ* មិនអាចជំនួសអត្ថប្រយោជន៍ដែលបានវាស់បានទេ។ វេជ្ជសាស្ត្រមានឈ្មោះសម្រាប់ទាំងពីរបាតុភូត (ការសាកល្បងពន្យល់ធៀបនឹងអនុវត្តជាក់ស្តែង; បញ្ហាប្លាស៊ីបូ) និងមានយន្តការដោះស្រាយ។

## គណិតវិទ្យា

```
Acceptance rate  = accepted suggestions / shown suggestions
                   (GitHub telemetry ~30% avg; varies: SQL 45%, Python 35%, JS 28%)
Retention rate   = AI code surviving to merge / accepted AI code (~88% reported)
Speedup          = (t_control − t_AI) / t_control  (from controlled comparison ONLY)
Throughput delta = Δ merged PRs/dev/week (GitHub/Accenture field data: +8.7%)

Value model     = devs × time saved × loaded rate × utilization factor
                  — every term needs local measurement; see the tornado in
                  sensitivity-analysis.md, where time-saved dominates all
                  other parameters combined
```

## ឧទាហរណ៍ដែលបានគណនា

អង្គការមានអ្នកអភិវឌ្ឍន៍ 500 នាក់ សាកល្បងជំនួយកូដជាមួយក្រុមត្រួតពិនិត្យត្រឹមត្រូវ (ក្រុមផ្គូផ្គង 3 ខែ រង្វាស់ចុះឈ្មោះជាមុន)៖

```
Pilot result: PR cycle time −18%; merged PRs +6%; CFR unchanged;
              self-reported time saved 45 min/day; measured task-level ≈ 15 min/day

Value the MEASURED number: 500 × 0.25h × 220d × £60 × 0.6 utilization
                          ≈ £990,000/year capacity (non-cash-releasing)
Cost: 500 × £39/mo × 12 ≈ £234,000/year
Net capacity ratio ≈ 4:1 — fundable, at one-third the self-reported claim.
```

គម្លាត 3 ដងរវាងអ្វីដែលយល់ឃើញ និងអ្វីដែលបានវាស់ គឺជាការរកឃើញរបស់ METR ដែលកើតឡើងក្នុងពិភពពិត; ការធ្វើថវិកាតាមការរាយការណ៍ខ្លួនឯងនឹងធ្វើឱ្យបន្ទាត់អត្ថប្រយោជន៍កើនឡើងបីដង។

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

អ្វីដែលអ្នកវាយតម្លៃឧបករណ៍ AI គួរយកពីសេដ្ឋកិច្ចសុខាភិបាល៖ ធ្វើ**ការសាកល្បងអនុវត្តជាក់ស្តែង** (ឃ្លាំងកូដរបស់អ្នក វិស្វករអ្នក សំបុត្រពិតប្រាកដ — មិនមែនកិច្ចការបង្ហាញរបស់អ្នកលក់ទេ); ចាត់ទុក**អត្រាទទួលយកជាប្រូកស៊ី មិនមែនលទ្ធផលទេ** (វាគឺជា[PPV](../ការវាយតម្លៃ-ai-គ្លីនិក/)នៃសំណើពីទស្សនៈរបស់អ្នកអភិវឌ្ឍន៍ — ការទទួលយកខ្ពស់ជាមួយការរក្សាទាបគឺជាការធ្វើរោគវិនិច្ឆ័យហួសហេតុ); ផ្គូផ្គងរាល់ការកើនឡើងទិន្នផលជាមួយ**ការត្រួតពិនិត្យស្ថិរភាព** (DORA 2025៖ AI បង្កើនទិន្នផល ប៉ុន្តែប៉ះពាល់ស្ថិរភាព — អន្តរាគមន៍ដែលមានផលរំខានត្រូវការការវិភាគអត្ថប្រយោជន៍សុទ្ធ តាម[រង្វាស់ DORA](../រង្វាស់-dora/)); ហើយចាត់ថ្នាក់អត្ថប្រយោជន៍ដោយស្មោះត្រង់ថាជាសមត្ថភាព ([ការសន្សំដែលបញ្ចេញសាច់ប្រាក់ ធៀបនឹងមិនបញ្ចេញសាច់ប្រាក់](../ការសន្សំដែលបញ្ចេញសាច់ប្រាក់-ធៀបនឹងមិនបញ្ចេញសាច់ប្រាក់/))។

## កំហុសដែលត្រូវជៀសវាង

- **ការផ្សាំការសិក្សារបស់អ្នកលក់**៖ លេខ RCT កិច្ចការថ្មីស្រឡាងត្រូវបានអនុវត្តលើការងារកូដចាស់ — កំហុសពិតប្រាកដដែលការសិក្សា METR បានបង្ហាញ។
- **ការរាយការណ៍ខ្លួនឯងជាការវាស់វែង**៖ គម្លាតការយល់ឃើញ 20 ភាគរយគឺជាភាពលំអៀងធំបំផុតដែលគេស្គាល់ក្នុងអក្សរសិល្ប៍នេះ។
- **ការបំប៉ោងសកម្មភាព**៖ PR ច្រើនជាង និងកូដច្រើនជាង គឺជាសកម្មភាព មិនមែនលទ្ធផលទេ ([SPACE](../space-និង-devex/)); ផ្គូផ្គងជាមួយការធ្វើឡើងវិញ និង CFR។
- **ការមិនយកចិត្តទុកដាក់ចំពោះខ្សែកោងរៀន**៖ ការវាស់វែងសប្តាហ៍ទី 2 ចាប់យកឥទ្ធិពលភាពថ្មីថ្មោងទាំងទិសដៅណាមួយ; វាស់នៅស្ថានភាពស្ថិរភាព ([ជើងមេឃពេលវេលា](../ព្រំដែនពេលវេលា/))។
