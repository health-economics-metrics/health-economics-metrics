# ການສົ່ງຕໍ່ເຖິງການຮັກສາ (RTT)

ການສົ່ງຕໍ່ເຖິງການຮັກສາແມ່ນເວລາທີ່ຜ່ານໄປຈາກການສົ່ງຕໍ່ຂອງແພດທົ່ວໄປຈົນເລີ່ມການຮັກສາທີ່ນຳໂດຍແພດທີ່ປຶກສາ. ລັດຖະທຳມະນູນ NHS ກຳນົດມາດຕະຖານ: **92% ຂອງຜູ້ປ່ວຍຄວນເລີ່ມການຮັກສາພາຍໃນ 18 ອາທິດ**. RTT ແມ່ນຕົວຊີ້ວັດການດຳເນີນງານທີ່ເຫັນໄດ້ທາງການເມືອງທີ່ສຸດໃນ NHS ອັງກິດ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ທຣັສທີ່ພາດເປົ້າໝາຍ RTT ປະເຊີນການກວດກາຂອງຜູ້ຄວບຄຸມ, ການແຊກແຊງ ແລະ ຄວາມເສຍຫາຍຕໍ່ຊື່ສຽງ; ລາຍຊື່ລໍຖ້າແຫ່ງຊາດແມ່ນຕົວເລກໜ້າໜຶ່ງ. ທຸກອາທິດທີ່ຜູ້ປ່ວຍລໍຖ້າແມ່ນສຸຂະພາບທີ່ສູນເສຍ (ລໍຖ້າໃນສະຖານະສຸຂະພາບທີ່ແຍ່ກວ່າ — ເບິ່ງເລກ QALY ຂ້າງລຸ່ມ) ແລະ ມັກເປັນຕົ້ນທຶນທີ່ເພີ່ມ (ສະພາບຊຸດໂຊມ; ເບິ່ງ [ການແຊກແຊງແຕ່ເນີ່ນໆ](../ການແຊກແຊງແຕ່ເນີ່ນໆ/)). ຊອບແວທີ່ປະຢັດເວລາບ່ອນໃດກໍຕາມໃນເສັ້ນທາງການສົ່ງຕໍ່ເຖິງການຮັກສາ — ການຄັດແຍກ, ເວລາຕອບຜົນວິນິດໄສ, ຄວາມຈຸຄລີນິກ, ການຈັດຕາຕະລາງ — ຜ່ອນຄາຍຜົນຕາມມາດ້ານການດຳເນີນງານ ແລະ ການເງິນຂອງການລົ້ມເຫຼວມາດຕະຖານໂດຍກົງ, ເຊິ່ງເປັນເຫດຜົນທີ່ຜົນກະທົບຕໍ່ RTT ເປັນລາຍການຜົນປະໂຫຍດຊັ້ນໜຶ່ງໃນ business case ດິຈິຕອນຂອງ NHS.

## ຄະນິດສາດ

```
RTT performance = patients treated within 18 weeks / total treated × 100
Waiting-time health cost per patient = wait duration × (utility_treated − utility_waiting)

Pathway view: RTT = Σ stage durations (referral triage → first appointment →
diagnostics → decision → treatment) — improve the longest queue, not the
busiest stage (see flow-metrics.md).
```

## ຕົວຢ່າງການຄິດໄລ່

ສາຂາພິເສດໜຶ່ງຮັກສາຜູ້ປ່ວຍເສັ້ນທາງ 5,000 ຄົນ/ປີ; ການລໍຖ້າສະເລ່ຍ 24 ອາທິດ; ຄ່າປະໂຫຍດລະຫວ່າງລໍຖ້າ 0.68 ທຽບກັບຮັກສາແລ້ວ 0.80.

ການຄັດແຍກດິຈິຕອນບວກໂປຣໂຕຄອນຕົງໄປກວດ ກຳຈັດການຕໍ່ຄິວລ້ວນໆ 5 ອາທິດ:

```
QALY gain = 5,000 × (5/52) × (0.80 − 0.68) = 57.7 QALYs/year
Monetized at £20,000–£30,000/QALY (see willingness-to-pay-thresholds.md):
  ≈ £1.15M–£1.73M/year of health value
```

— ບວກທຣັສຍ້າຍຈາກການລະເມີດໄປສູ່ການບັນລຸມາດຕະຖານ 18 ອາທິດ, ເຊິ່ງມີມູນຄ່າການກຳກັບດູແລທີ່ສະເປຣດຊີດໃດກໍຈັບບໍ່ໄດ້ເຕັມ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

RTT ແມ່ນ **ຕົວຊີ້ວັດເວລານຳຜ່ານຄິວຫຼາຍຂັ້ນຕອນ** — ຮຸ່ນໂຮງໝໍຂອງເວລານຳຈາກ commit ເຖິງການຜະລິດ (ເບິ່ງ [ຕົວຊີ້ວັດ DORA](../ຕົວຊີ້ວັດ-dora/)). ວິທີປັບປຸງຄືກັນທຸກຢ່າງ: ຕິດເຄື່ອງມືທຸກຂັ້ນຕອນ, ຊອກຫາບ່ອນທີ່ເວລາປະຕິທິນສະສົມ (ເກືອບສະເໝີແມ່ນການສົ່ງຕໍ່ ແລະ ຄິວ, ບໍ່ແມ່ນງານຄລີນິກ), ແລະ ກຳຈັດສະຖານະລໍຖ້າ. ໄຊຊະນະຂອງຊອບແວປົກກະຕິ: e-triage ທີ່ກຳນົດເສັ້ນທາງການສົ່ງຕໍ່ເປັນຊົ່ວໂມງແທນກຸ່ມລາຍອາທິດ, ການສົ່ງຜົນວິນິດໄສແທນນັດຕິດຕາມ, ແລະ ເກນຕົງໄປກວດອັດຕະໂນມັດ. ປະເມີນການປັບປຸງດ້ວຍ [ຕົ້ນທຶນຂອງຄວາມລ່າຊ້າ](../ຕົ້ນທຶນຂອງຄວາມລ່າຊ້າ/) ເປັນ QALY/ອາທິດ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ປັບປຸງຂັ້ນຕອນທີ່ບໍ່ແມ່ນຂໍ້ຈຳກັດ** — ຕັດການລໍຖ້ານັດທຳອິດໃນຂະນະທີ່ຄິວວິນິດໄສເພີ່ມພຽງແຕ່ຍ້າຍບໍ່ສະສົມ.
- **ການຫຼິ້ນກົນ**: ການຣີເຊັດເສັ້ນທາງ ແລະ ການຢຸດນາຬິກາສາມາດປັບປຸງ RTT ທີ່ລາຍງານໂດຍບໍ່ໄດ້ຮັກສາໃຜໄວຂຶ້ນ; ກວດສອບການແຈກຢາຍພື້ນຖານ.
- **ອ້າງການປັບປຸງທັງເສັ້ນທາງ** ໃຫ້ເຄື່ອງມືດຽວເມື່ອຫຼາຍການປ່ຽນແປງລົງມາພ້ອມກັນ — ການຖືກຖືວ່າເກີດຈາກຕ້ອງມີຕົວປຽບທຽບ.
