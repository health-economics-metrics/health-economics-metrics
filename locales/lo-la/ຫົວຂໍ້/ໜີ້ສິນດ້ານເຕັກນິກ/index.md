# ໜີ້ສິນດ້ານເຕັກນິກ

ໜີ້ສິນດ້ານເຕັກນິກແມ່ນຕົ້ນທຶນໃນອະນາຄົດທີ່ຖືກບົ່ງບອກຂອງການຕັດສິນໃຈທີ່ສະດວກໃນອະດີດໃນໂຄ້ດເບດ: ງານແກ້ໄຂທີ່ຕິດໜີ້ (**ເງິນຕົ້ນ**) ແລະ ແຮງຖ່ວງຕໍ່ເນື່ອງທີ່ມັນສົ່ງຕໍ່ການສົ່ງມອບ (**ດອກເບ້ຍ**). ວິທີການວັດປະລິມານເຊັ່ນ SQALE ປ່ຽນມັນຈາກການປຽບທຽບເປັນໜີ້ສິນທີ່ມີຕົ້ນທຶນ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ບໍ່ໄດ້ວັດປະລິມານ, ໜີ້ສິນເຕັກນິກແມ່ນການຈົ່ມ; ວັດປະລິມານແລ້ວ, ມັນແມ່ນ business case. ເສັ້ນຖານອຸດສາຫະກຳ (CAST Appmarq, 1,400 ແອັບ / 550M LOC): ໃນອະດີດ ≈ **$3.61 ຂອງເງິນຕົ້ນໜີ້ສິນເຕັກນິກຕໍ່ແຖວໂຄ້ດ**, ດ້ວຍໂຄ້ດເບດປົກກະຕິແບກອັດຕາໜີ້ 15–20% ຂອງຕົ້ນທຶນສ້າງໃໝ່, ທຽບກັບເກນສຸຂະພາບທີ່ໃຊ້ທົ່ວໄປ ≤5% (ເກຣດ "A" ຂອງ SonarQube). ກອບເສດຖະສາດສຸຂະພາບເໝາະສົມຢ່າງແນ່ນອນ: ໜີ້ສິນແມ່ນ *ພະຍາດຊຳເຮື້ອ* — ບໍ່ໄດ້ຮັກສາ, ມັນຄືບໜ້າ, "ດອກເບ້ຍ" ຂອງມັນທະວີເປັນການສົ່ງມອບຊ້າລົງ ແລະ ອັດຕາຂໍ້ບົກພ່ອງສູງຂຶ້ນ, ແລະ ການແກ້ໄຂແຂ່ງຂັນຄວາມຈຸກັບງານຄຸນສົມບັດຄືກັນທີ່ການປ້ອງກັນແຂ່ງຂັນກັບການຮັກສາ.

## ຄະນິດສາດ

```
SQALE principal   = Σ over violations (remediation time) × developer cost rate
Technical debt ratio (TDR) = remediation cost / redevelopment cost × 100
                    (SonarQube grades: A ≤ 5%, B ≤ 10%, C ≤ 20%, D ≤ 50%)

Interest (the number that justifies paydown):
  interest/year = Δ delivery velocity × value per unit velocity
                + Δ defect rate × cost per defect
Paydown case  = PV(interest avoided over horizon) − remediation cost
                (discounted — see discounting-and-time-preference.md)
```

ເງິນຕົ້ນລະບຸໜີ້ສິນ; **ດອກເບ້ຍ** ສ້າງກໍລະນີການລົງທຶນ. ການຈ່າຍເງິນຕົ້ນ £500k ເພື່ອຫຼີກລ່ຽງດອກເບ້ຍ £40k/ປີ ແມ່ນການແລກປ່ຽນທີ່ບໍ່ດີ; ເພື່ອຫຼີກລ່ຽງ £400k/ປີ, ດີເລີດ.

## ຕົວຢ່າງການຄິດໄລ່

ຊັ້ນການເຊື່ອມໂຍງບັນທຶກທາງຄລີນິກ 400k-LOC: ເງິນຕົ້ນ SQALE 3,800 ຊົ່ວໂມງ × £75 = **£285k**; TDR ≈ 12% (ເກຣດ C). ດອກເບ້ຍທີ່ວັດໄດ້: ທີມທີ່ແຕະຊັ້ນນີ້ສະແດງເວລາວົງຈອນຍາວກວ່າ 40% ແລະ ອັດຕາຄວາມລົ້ມເຫຼວຂອງການປ່ຽນແປງ 2× ທຽບກັບເສັ້ນຖານຂອງລະບົບ. ຊັ້ນນີ້ດູດ 6,000 ຊົ່ວໂມງນັກພັດທະນາ/ປີ:

```
Interest ≈ 6,000 × 0.40 × £75      = £180,000/year (velocity drag)
         + 12 extra failures × £8,000 = £96,000/year (rework/incidents)
         ≈ £276,000/year

Remediate the worst 30% of principal (£85k) targeting hotspots → modelled
interest reduction 60%: saves ~£166k/year. Payback ≈ 6 months.
```

ການເປົ້າໝາຍຈຸດຮ້ອນສຳຄັນ: ດອກເບ້ຍໜີ້ສິນສຸມຢູ່ບ່ອນທີ່ຄວາມຖີ່ການປ່ຽນແປງ × ຄວາມໜາແໜ້ນໜີ້ສູງສຸດ — ການແກ້ໄຂໜີ້ທີ່ບໍ່ຄ່ອຍຖືກແຕະບໍ່ໄດ້ຫຍັງ, ຄືກັບການຮັກສາສະພາບທີ່ຈະບໍ່ເຄີຍຄືບໜ້າ ([ເສດຖະສາດການປ້ອງກັນ](../ເສດຖະສາດການປ້ອງກັນ/)).

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ການນຳເຂົ້າຈາກເສດຖະສາດສຸຂະພາບທີ່ຍົກລະດັບຂໍ້ໂຕ້ແຍ້ງໜີ້ສິນເຕັກນິກ: ສະແດງລະບົບເປັນ **ບັນຊີພາລະ** ແບບ [DALY](../ປີຊີວິດທີ່ປັບດ້ວຍຄວາມພິການ/) — ປີວິສະວະກຳທີ່ສຸຂະພາບດີທີ່ສູນເສຍຢູ່ໃສ?; ໃຫ້ເຫດຜົນການຈ່າຍໜີ້ດ້ວຍເລກຄວາມຄືບໜ້າ, ຢ່າງຊື່ສັດ (ປົກກະຕິຄຸ້ມຄ່າດ້ານຕົ້ນທຶນ, ບໍ່ແມ່ນປະຢັດຕົ້ນທຶນ); ຖ່ວງນ້ຳໜັກການແກ້ໄຂຂອງລະບົບທີ່ແຍ່ທີ່ສຸດດ້ວຍ [ຊ່ອງຫວ່າງຄວາມຮຸນແຮງ](../ຊ່ອງຫວ່າງ-qaly-ແລະ-ຕົວປັບຄວາມຮຸນແຮງ/); ແລະ ສົ່ງຂໍ້ສະເໜີແກ້ໄຂໃຫຍ່ພ້ອມການວິເຄາະການຫັກລົບທີ່ຜ່ານກົດ [ຕົ້ນທຶນຕໍ່ເນື່ອງທີ່ຫຼີກລ່ຽງໄດ້](../ຕົ້ນທຶນຕໍ່ເນື່ອງທີ່ຫຼີກລ່ຽງໄດ້/) — ຖ່ວງນ້ຳໜັກຄວາມນ່າຈະເປັນ, ຫຼຸດມູນຄ່າ, ນັບຄັ້ງດຽວ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ລາຍງານສະເພາະເງິນຕົ້ນ**: ຕົວເລກໃຫຍ່ໜ້າຢ້ານທີ່ບໍ່ມີການຄາດຄະເນດອກເບ້ຍບໍ່ໃຫ້ເຫດຜົນຫຍັງ.
- **ຕົວເລກໜີ້ທີ່ເຄື່ອງມືສ້າງ ຖືກຕາມຕົວອັກສອນ**: SQALE ນັບການລະເມີດກົດ; ມັນພາດໜີ້ສະຖາປັດຕະຍະກຳ (ຊະນິດທີ່ແພງ) ແລະ ນັບເລື່ອງຈຸກຈິກ.
- **ອຸດົມຄະຕິໜີ້ສູນ**: ລະດັບໜີ້ທີ່ດີທີ່ສຸດບໍ່ແມ່ນສູນ — ໜີ້ແມ່ນການກູ້ຢືມ; ຄຳຖາມແມ່ນອັດຕາດອກເບ້ຍ.
- **"ການຂຽນໃໝ່ຫຼີກລ່ຽງທັງໝົດ"**: ຂໍ້ສະເໜີຂຽນໃໝ່ຕ້ອງຜ່ານກົດການຫັກລົບດຽວກັນ — ຕົ້ນທຶນກົງກັນຂ້າມ, ຄວາມນ່າຈະເປັນ, ການຫຼຸດມູນຄ່າ.
