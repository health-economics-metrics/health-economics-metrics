# WSJF ແລະ CD3

CD3 (ຕົ້ນທຶນຂອງຄວາມລ່າຊ້າຫານດ້ວຍໄລຍະເວລາ) ແລະ WSJF (ງານສັ້ນທີ່ສຸດທີ່ຖ່ວງນ້ຳໜັກກ່ອນ) ແມ່ນກົດຈັດລຳດັບຄວາມສຳຄັນທີ່ກຳນົດເວລາງານຕາມ **ຄວາມໜາແໜ້ນມູນຄ່າ**: ຕົ້ນທຶນຄວາມລ່າຊ້າຫຼາຍປານໃດທີ່ຖືກກຳຈັດຕໍ່ຫົວໜ່ວຍຄວາມຈຸທີ່ຫາຍາກທີ່ໃຊ້. ພາຍໃຕ້ຄວາມຈຸຮ່ວມກັນທີ່ຄົງທີ່, CD3 ສູງສຸດກ່ອນແມ່ນລຳດັບທີ່ດີທີ່ສຸດທາງຄະນິດສາດໃນການຫຼຸດຕົ້ນທຶນຄວາມລ່າຊ້າທັງໝົດ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ທຸກ backlog ແມ່ນບັນຫາການແບ່ງສັນ: ຫຼາຍລາຍການທີ່ຄຸ້ມຄ່າ, ໜຶ່ງທໍ່. ເສດຖະສາດສຸຂະພາບແກ້ບັນຫາດຽວກັນສຳລັບງົບສຸຂະພາບດ້ວຍຕາຕະລາງລີກຄວາມຄຸ້ມຄ່າດ້ານຕົ້ນທຶນ — ຈັດອັນດັບການແຊກແຊງຕາມສຸຂະພາບທີ່ໄດ້ຕໍ່ປອນ, ໃຫ້ທຶນລົງລາຍການຈົນງົບໝົດ. CD3 ແມ່ນຕັກກະດຽວກັນສຳລັບຄວາມຈຸການສົ່ງມອບ: ຜົນປະໂຫຍດຕໍ່ຫົວໜ່ວຍ *ຊັບພະຍາກອນທີ່ຖືກຈຳກັດ*, ໃຫ້ທຶນຕາມລຳດັບຈັດອັນດັບ. ການຈັດລຳດັບໃຫ້ຖືກແມ່ນເງິນຟຣີ — ງານດຽວກັນ, ຄວາມຈຸດຽວກັນ, ຕົ້ນທຶນຄວາມລ່າຊ້າທັງໝົດໜ້ອຍລົງ.

## ຄະນິດສາດ

```
CD3  = Cost of Delay (£/week) / Duration (weeks)      — real units (Black Swan Farming)

WSJF = (user-business value + time criticality + risk reduction/opportunity
        enablement) / job size                         — SAFe's relative-scale proxy,
                                                        modified-Fibonacci scores
```

CD3 ດ້ວຍສະກຸນເງິນຈິງ ([ຕົ້ນທຶນຂອງຄວາມລ່າຊ້າ](../ຕົ້ນທຶນຂອງຄວາມລ່າຊ້າ/)) ແຂງແຮງກວ່າຄະແນນທີ່ບໍ່ມີຫົວໜ່ວຍຂອງ WSJF ຢ່າງເຄັ່ງຄັດ — WSJF ກັບ CD3 ຄືກັບທີ່ການໃຫ້ຄະແນນຫຼາຍເກນກັບ [ການວິເຄາະຕົ້ນທຶນ-ອຣະຖະປະໂຫຍດ](../ການວິເຄາະຕົ້ນທຶນ-ອຣະຖະປະໂຫຍດ/) ເຕັມຮູບແບບ: ໃຊ້ໄດ້ເມື່ອການແປງເປັນເງິນບໍ່ເປັນໄປໄດ້, ຫຼິ້ນກົນໄດ້ເມື່ອຄະແນນບໍ່ມີຈຸດຍຶດ.

## ຕົວຢ່າງການຄິດໄລ່

ສາມຄຸນສົມບັດ, ໜຶ່ງທີມ:

```
Feature   CoD (£/wk)   Duration   CD3
A         30,000       10 wks     3,000
B         12,000       2 wks      6,000
C         5,000        1 wk       5,000
```

ລຳດັບ CD3: B, C, A. ປຽບທຽບຕົ້ນທຶນຄວາມລ່າຊ້າທັງໝົດກັບ "CoD ໃຫຍ່ທີ່ສຸດກ່ອນ" (A, B, C):

```
CD3 order  (B,C,A): A waits 3 wks, C waits 2 → 30k×3 + 5k×2  = £100k delay cost
CoD order  (A,B,C): B waits 10, C waits 12   → 12k×10 + 5k×12 = £180k
```

ຄຸນສົມບັດດຽວກັນ, ທີມດຽວກັນ — ການຈັດລຳດັບຢ່າງດຽວປະຢັດ £80,000. ຄວາມເຂົ້າໃຈ: ລາຍການນ້ອຍທີ່ຮີບດ່ວນໄປກ່ອນເພາະມັນປົດປ່ອຍຕົ້ນທຶນຄວາມລ່າຊ້າຂອງມັນໃນລາຄາຖືກ; ລາຍການໃຫຍ່ເສຍນ້ອຍເມື່ອລໍຖ້າສັ້ນໆ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ສຳລັບພອດໂຟລິໂອຊອບແວສຸຂະພາບ, ກຳນົດ CoD ໃນຫົວໜ່ວຍທີ່ບ່ອນເກັບນີ້ສອນ: QALY/ອາທິດ × ເກນ + £/ອາທິດດ້ານການດຳເນີນງານ, ແລະ backlog ກາຍເປັນສິ່ງທີ່ປຽບທຽບໄດ້ໂດຍກົງກັບວິທີທີ່ລະບົບສຸຂະພາບຈັດອັນດັບທຸກຢ່າງອື່ນທີ່ມັນຊື້. ສອງຂໍ້ສັງເກດການປະຕິບັດ: (1) ໄລຍະເວລາໝາຍເຖິງ *ເວລາປະຕິທິນທີ່ຄອບຄອງຂໍ້ຈຳກັດ*, ບໍ່ແມ່ນຄວາມພະຍາຍາມ — ລາຍການທີ່ໃຊ້ເວລາຜ່ານໄປ 2 ອາທິດທີ່ຕ້ອງການ 2 ວັນຂອງທີມຄໍຂວດຖືກກວ່າທີ່ເບິ່ງ (ເບິ່ງ [ການເພີ່ມປະສິດທິພາບຊັບພະຍາກອນຕໍ່ເນື່ອງ](../ການເພີ່ມປະສິດທິພາບຊັບພະຍາກອນຕໍ່ເນື່ອງ/)); (2) ໂຮງໝໍໃຊ້ກົດດຽວກັນແບບແອບແຝງເມື່ອຈັດລາຍການຫ້ອງຜ່າຕັດຕາມ throughput ຖ່ວງນ້ຳໜັກຄວາມຮີບດ່ວນ — ໝວດການຈັດລຳດັບຄວາມສຳຄັນທາງຄລີນິກແມ່ນ CD3 ຖ່ວງນ້ຳໜັກຄວາມຮຸນແຮງ (ເບິ່ງ [ຊ່ອງຫວ່າງ QALY ແລະ ຕົວປັບຄວາມຮຸນແຮງ](../ຊ່ອງຫວ່າງ-qaly-ແລະ-ຕົວປັບຄວາມຮຸນແຮງ/)).

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ລະຄອນຄະແນນ WSJF**: ການໂຕ້ຖຽງ Fibonacci ທີ່ບໍ່ມີຫົວໜ່ວຍລົງເອີຍທີ່ຄົນເວົ້າດັງທີ່ສຸດ; ຍຶດຢ່າງໜ້ອຍລາຍການເທິງສຸດຂອງ backlog ໃນ CoD ຈິງ.
- **ການຫຼິ້ນກົນໄລຍະເວລາ**: ແຍກລາຍການເພື່ອພອງອັນດັບ CD3 — ບໍ່ເປັນຫຍັງເມື່ອການແຍກສົ່ງມອບມູນຄ່າເອກະລາດ, ເປັນການສໍ້ໂກງເມື່ອບໍ່.
- **ເມີນເສີຍໂປຣໄຟລ໌ຄວາມຮີບດ່ວນ**: CoD ຮູບກຳນົດເວລາ (ວັນທີຕາມກົດລະບຽບ) ທຳລາຍສົມມຸດຖານອັດຕາຄົງທີ່; ກຳນົດເວລາອັນເຫຼົ່ານັ້ນຕາມຄວາມເປັນໄປໄດ້ຂອງວັນທີ, ແລ້ວ CD3 ສ່ວນທີ່ເຫຼືອ.
- **ການຈັດອັນດັບໃໝ່ຢ່າງບໍ່ຢຸດ**: CD3 ແມ່ນສຳລັບການຕັດສິນໃຈລຳດັບໃນເວລາຜູກມັດ, ບໍ່ແມ່ນການສັບປ່ຽນງານທີ່ກຳລັງດຳເນີນທຸກວັນ (ເບິ່ງ [ຕົວຊີ້ວັດການໄຫຼ](../ຕົວຊີ້ວັດການໄຫຼ/) ກ່ຽວກັບ WIP).
