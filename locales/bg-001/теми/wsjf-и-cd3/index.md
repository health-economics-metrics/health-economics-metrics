# WSJF и CD3

CD3 (разход на забавянето, разделен на продължителността) и WSJF (претеглена най-кратка работа първо) са правила за приоритизиране, които планират работата по **плътност на стойността**: колко разход на забавянето се премахва на единица консумиран оскъден капацитет. При споделен, фиксиран капацитет най-високият CD3 първо е математически оптималната последователност за минимизиране на общия разход на забавянето.

## Защо е важно

Всеки изоставащ работен списък е проблем на дажбуването: много достойни елементи, един конвейер. Здравната икономика е решила същия проблем за здравните бюджети с класации на ценовата ефективност — подредете интервенциите по придобито здраве на паунд, финансирайте надолу по списъка, докато бюджетът се изчерпи. CD3 е идентичната логика за капацитета за доставка: полза на единица от *ограничения ресурс*, финансирана по ред на класиране. Правилното последователно подреждане са безплатни пари — същата работа, същият капацитет, по-малък общ разход на забавянето.

## Математиката

```
CD3  = Cost of Delay (£/week) / Duration (weeks)      — real units (Black Swan Farming)

WSJF = (user-business value + time criticality + risk reduction/opportunity
        enablement) / job size                         — SAFe's relative-scale proxy,
                                                        modified-Fibonacci scores
```

CD3 с истинска валута ([разход на забавянето](../разход-на-забавянето/)) е строго по-силен от безразмерните точки на WSJF — WSJF е за CD3 това, което многокритериалното оценяване е за пълния [анализ на разходите и полезността](../анализ-на-разходите-и-полезността/): използваем, когато монетизирането е непрактично, манипулируем, когато оценките нямат котва.

## Решен пример

Три функции, един екип:

```
Feature   CoD (£/wk)   Duration   CD3
A         30,000       10 wks     3,000
B         12,000       2 wks      6,000
C         5,000        1 wk       5,000
```

Ред по CD3: B, C, A. Сравнете общия разход на забавянето с „най-голям CoD първо“ (A, B, C):

```
CD3 order  (B,C,A): A waits 3 wks, C waits 2 → 30k×3 + 5k×2  = £100k delay cost
CoD order  (A,B,C): B waits 10, C waits 12   → 12k×10 + 5k×12 = £180k
```

Същите функции, същият екип — само последователността спестява £80 000. Интуицията: малките, спешни елементи вървят първи, защото освобождават разхода си на забавянето евтино; големият елемент губи малко, като почака за кратко.

## Връзка със софтуерното инженерство

За портфолиа от здравен софтуер изразявайте CoD в единиците, които това хранилище преподава: QALY/седмица × праг + оперативни £/седмица, и изоставащият работен списък става директно съизмерим с начина, по който здравната система класира всичко останало, което купува. Две практически бележки: (1) продължителността означава *календарно време, заемащо ограничението*, а не усилие — елемент с 2 седмици изтекло време, който изисква 2 дни от екипа на тясното място, е по-евтин, отколкото изглежда (вж. [оптимизиране на последващите ресурси](../оптимизиране-на-последващите-ресурси/)); (2) болниците прилагат същото правило имплицитно, когато подреждат операционните списъци по претеглена по спешност пропускателна способност — категориите за клинично приоритизиране са претеглен по тежест CD3 (вж. [дефицит на QALY и модификатори за тежест](../дефицит-на-qaly-и-модификатори-за-тежест/)).

## Често срещани грешки

- **Театър на WSJF оценките**: безразмерните дебати с Фибоначи се сближават към този, който спори най-силно; закответе поне елементите на върха на списъка в реален CoD.
- **Манипулиране на продължителността**: разделяне на елементи за раздуване на ранга по CD3 — наред, когато разделенията доставят стойност независимо, измама, когато не.
- **Игнориране на профилите на спешност**: CoD във формата на краен срок (регулаторни дати) нарушава допускането за постоянна скорост; планирайте ги по осъществимост на датата, после CD3 за останалото.
- **Постоянно прекласиране**: CD3 е за решения за последователност при момента на ангажимента, а не за ежедневно пренареждане на работа в процес (вж. [показатели за потока](../показатели-за-потока/) за WIP).
