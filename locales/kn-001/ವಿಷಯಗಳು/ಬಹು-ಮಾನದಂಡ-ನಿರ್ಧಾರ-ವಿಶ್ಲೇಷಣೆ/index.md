# ಬಹು-ಮಾನದಂಡ ನಿರ್ಧಾರ ವಿಶ್ಲೇಷಣೆ (MCDA)

ಬಹು-ಮಾನದಂಡ ನಿರ್ಧಾರ ವಿಶ್ಲೇಷಣೆ (MCDA) ಎಂದರೆ ಒಂದೇ ICER/ಪಾವತಿಸುವ-ಇಚ್ಛೆ ಮಿತಿ ನಿರ್ಧಾರ-ಕರ್ತೃ ಕಾಳಜಿ ವಹಿಸುವ ಎಲ್ಲವನ್ನೂ — ಸಮಾನತೆ, ಪೂರೈಸದ ಅಗತ್ಯ, ನಾವೀನ್ಯತೆ, ಬಜೆಟ್ ಪ್ರಭಾವ, ರೋಗ ತೀವ್ರತೆ — ಸೆರೆಹಿಡಿಯದಿದ್ದಾಗ ಆರೋಗ್ಯ ತಂತ್ರಜ್ಞಾನ ಮೌಲ್ಯಮಾಪನದಲ್ಲಿ ಬಳಸುವ ತೂಕದ-ಮೊತ್ತ ಅಂಕ ಮಾದರಿ. ಪ್ರತಿ ಮಾನದಂಡಕ್ಕೆ ಅದರ ಮಹತ್ವ ಪ್ರತಿಬಿಂಬಿಸುವ ತೂಕ (ಪಾಲುದಾರರಿಂದ ಪಡೆದದ್ದು, ತೂಕಗಳ ಮೊತ್ತ 1), ಪ್ರತಿ ಆಯ್ಕೆಗೆ ಪ್ರತಿ ಮಾನದಂಡಕ್ಕೆ ಸಾಮಾನ್ಯೀಕೃತ ಅಂಕ (ಸಾಮಾನ್ಯವಾಗಿ 0–1), ಮತ್ತು ಒಟ್ಟಾರೆ ಅಂಕ ತೂಕದ ಮೊತ್ತ — ಸಾಫ್ಟ್‌ವೇರ್ ಮಾರಾಟಗಾರ-ಆಯ್ಕೆ ಅಂಕಪಟ್ಟಿಯ ಅದೇ ಗಣಿತ ಆಕಾರ.

## ಇದು ಏಕೆ ಮುಖ್ಯ

MCDAಯನ್ನು EVIDEM ನಂತಹ ಚೌಕಟ್ಟುಗಳಲ್ಲಿ, ಮತ್ತು ಕಟ್ಟುನಿಟ್ಟಾದ ಪ್ರತಿ-QALY ವೆಚ್ಚ ಮಿತಿ ವಿಧಾನ ನಿರ್ಧಾರದ ಬಗ್ಗೆ ಮುಖ್ಯವಾದ ಎಲ್ಲವನ್ನೂ ಸೆರೆಹಿಡಿಯಲು ತುಂಬಾ ಕಿರಿದು ಎಂದು ಪರಿಗಣಿಸುವ ಅನಾಥ/ಅಪರೂಪದ-ರೋಗ ಮೌಲ್ಯಮಾಪನಗಳಿಗಾಗಿ ಕೆಲವು HTA ಸಂಸ್ಥೆಗಳು ಬಳಸುತ್ತವೆ. ISPOR MCDA Emerging Good Practices Task Force ತೂಕ ಮತ್ತು ಅಂಕಗಳನ್ನು ಸಮರ್ಥನೀಯವಾಗಿ ಪಡೆಯಲು ಉತ್ತಮ-ಅಭ್ಯಾಸ ಮಾರ್ಗದರ್ಶನವನ್ನು ಔಪಚಾರಿಕಗೊಳಿಸಿತು, ನಿಖರವಾಗಿ ಏಕೆಂದರೆ ಅನೌಪಚಾರಿಕವಾಗಿ ತೂಕ ಹಾಕಿದ ನಿರ್ಧಾರ ರಚಿಸಲು ಸುಲಭ ಮತ್ತು ತಿರುಚಲು ಸುಲಭ. ಆರೋಗ್ಯ ತಂತ್ರಜ್ಞಾನ ನಿಜವಾಗಿ ಒಂದೇ [ಪಾವತಿಸುವ-ಇಚ್ಛೆ ಮಿತಿ](../ಪಾವತಿಸಲು-ಇಚ್ಛೆಯ-ಮಿತಿಗಳು/) ಪ್ರತಿನಿಧಿಸಲಾಗದ ಮೌಲ್ಯ ಆಯಾಮಗಳನ್ನು — ತೀವ್ರತೆ, ನಾವೀನ್ಯತೆ, ಸಮಾನತೆ — ಹೊಂದಿರುವಾಗ, MCDA ನಿರ್ಧಾರ-ಕರ್ತರಿಗೆ ಅವನ್ನು ಸಂಯೋಜಿಸಲು ಹೇಳದ ತೀರ್ಪಿನ ಬದಲು ಸ್ಪಷ್ಟ, ಲೆಕ್ಕಪರಿಶೋಧನೆಗೆ ಯೋಗ್ಯ ರಚನೆಯನ್ನು ನೀಡುತ್ತದೆ.

## ಗಣಿತ

```
MCDA score = Σ_i (weight_i × score_i)

weights should sum to 1 (elicited via stakeholder methods such as swing
weighting or the Analytic Hierarchy Process)
```

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

HTA ಸಮಿತಿ ಡಿಜಿಟಲ್ ಚಿಕಿತ್ಸೆಗೆ ನಾಲ್ಕು ಮಾನದಂಡಗಳಲ್ಲಿ ಅಂಕ ನೀಡುತ್ತದೆ:

```
Criterion                          Weight   Score   Weight × Score
Clinical benefit                   0.4      0.8     0.32
Cost impact                        0.3      0.5     0.15
Disease severity / unmet need      0.2      0.9     0.18
Innovation                         0.1      0.6     0.06
                                    ─────                ─────
                                    1.0                  0.71
```

ತೂಕಗಳು 1.0 ಕೂಡುತ್ತವೆ (0.4 + 0.3 + 0.2 + 0.1), ಮತ್ತು MCDA ಅಂಕ 0.71 (0.32 + 0.15 + 0.18 + 0.06). ಸಮಿತಿ 0.71 ಅನ್ನು ಮುಂಚಿತ-ಒಪ್ಪಿದ ಮಿತಿಯ ವಿರುದ್ಧ ಹೋಲಿಸುತ್ತದೆ, ಅಥವಾ ಅದೇ ರೀತಿ ಅಂಕ ನೀಡಿದ ಸ್ಪರ್ಧಾತ್ಮಕ ತಂತ್ರಜ್ಞಾನಗಳ ವಿರುದ್ಧ ಶ್ರೇಣೀಕರಿಸುತ್ತದೆ.

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್‌ನೊಂದಿಗಿನ ಸಂಬಂಧ

ಇದು ತೂಕದ ಮಾರಾಟಗಾರ-ಆಯ್ಕೆ ಅಂಕಪಟ್ಟಿ, RFP ಮೌಲ್ಯಮಾಪನ ಮ್ಯಾಟ್ರಿಕ್ಸ್ ಅಥವಾ ವೈಶಿಷ್ಟ್ಯ-ಆದ್ಯತೆ ಅಂಕ ಮಾದರಿಯ ಅದೇ ಗಣಿತ — ಸಾಫ್ಟ್‌ವೇರ್ ಖರೀದಿಯಲ್ಲಿ ಶ್ರೇಷ್ಠ ತೂಕದ-ಅಂಕಪಟ್ಟಿ ಬಳಕೆ ಪ್ರಕರಣ [ನಿರ್ಮಿಸು vs ಖರೀದಿಸು](../ನಿರ್ಮಿಸು-vs-ಖರೀದಿಸು/) ನೋಡಿ. [WSJF ಮತ್ತು CD3](../wsjf-ಮತ್ತು-cd3/) ಜೊತೆಗೆ ಹೋಲಿಸುವುದೂ ಯೋಗ್ಯ: WSJF/CD3 *ಅನುಪಾತ*-ಆಧಾರಿತ ಆದ್ಯತೆ ವಿಧಾನ (ವಿಳಂಬದ ವೆಚ್ಚ ಭಾಗಿಸಿ ಕೆಲಸದ ಗಾತ್ರ ಅಥವಾ ಅವಧಿ), ಆದರೆ MCDA ತೂಕದ *ಮೊತ್ತ*. MCDA ಮತ್ತು WSJF/CD3 "ಸ್ಪರ್ಧಾತ್ಮಕ ಆಯ್ಕೆಗಳನ್ನು ಹೇಗೆ ಶ್ರೇಣೀಕರಿಸುವುದು" ಎಂಬುದಕ್ಕೆ ರಚನಾತ್ಮಕವಾಗಿ ಎರಡು ಭಿನ್ನ ಉತ್ತರಗಳು, ಮತ್ತು ನಿರ್ದಿಷ್ಟ ನಿರ್ಧಾರಕ್ಕೆ ನಿಜವಾಗಿ ಯಾವುದು ಬೇಕು ಎಂದು ತಿಳಿಯುವುದು — ಸ್ವತಂತ್ರ ಮಾನದಂಡಗಳಾದ್ಯಂತ ಸಂಕಲನ ಮೌಲ್ಯ vs ವಿರಳ ಸಾಮರ್ಥ್ಯದ ಪ್ರತಿ ಘಟಕಕ್ಕೆ ಮೌಲ್ಯ ಸಾಂದ್ರತೆ — ಯಾವ ಸೂತ್ರ ಹೆಚ್ಚು ಕಠಿಣವಾಗಿ ಕಾಣುತ್ತದೆ ಎಂಬುದಕ್ಕಿಂತ ಹೆಚ್ಚು ಮುಖ್ಯ.

## ಎಡವಟ್ಟುಗಳು

- **ತೂಕ ಪಡೆಯುವಿಕೆ ಪಕ್ಷಪಾತ**: ತೂಕ ನಿಗದಿಪಡಿಸುವವರು ಪರಿಣಾಮಕಾರಿಯಾಗಿ ಶ್ರೇಣಿಯನ್ನು ಮುಂಚಿತವಾಗಿ ನಿರ್ಧರಿಸುತ್ತಾರೆ, ಆದ್ದರಿಂದ "ಸೂತ್ರ" ರಾಜಕೀಯ ಅಥವಾ ವಾಣಿಜ್ಯ ನಿರ್ಧಾರವನ್ನು ವಸ್ತುನಿಷ್ಠ ಲೆಕ್ಕವಾಗಿ ತೊಳೆಯಬಹುದು. ತೂಕಗಳನ್ನು ಯಾರು ಮತ್ತು ಹೇಗೆ ನಿಗದಿಪಡಿಸಿದರು ಎಂದು ದಾಖಲಿಸಿ.
- **ಬೇರೆಡೆ ಈಗಾಗಲೇ ಸೆರೆಹಿಡಿದ ಮಾನದಂಡದ ದ್ವಿಗುಣ ಎಣಿಕೆ**: "ವೆಚ್ಚ-ಪರಿಣಾಮಕಾರಿತ್ವ"ಕ್ಕೆ ಒಂದು ಮಾನದಂಡವಾಗಿ ಅಂಕ ನೀಡುತ್ತಾ *ಜೊತೆಗೆ* "ವೆಚ್ಚ ಪ್ರಭಾವ"ಕ್ಕೆ ಪ್ರತ್ಯೇಕವಾಗಿ ಅಂಕ ನೀಡುವುದು ಯಾರೂ ಉದ್ದೇಶಿಸದೆ ಇತರ ಮಾನದಂಡಗಳಿಗೆ ಹೋಲಿಸಿದರೆ ಹಣಕ್ಕೆ ಅತಿಯಾದ ತೂಕ ನೀಡುತ್ತದೆ.
- **ಸುಳ್ಳು ನಿಖರತೆ**: ಎರಡು-ದಶಮಾಂಶ ತೂಕದ ಅಂಕ (0.71) ಆಧಾರವಾಗಿರುವ 0–10 ಪಾಲುದಾರ ರೇಟಿಂಗ್‌ಗಳು ನಿಜವಾಗಿ ಬೆಂಬಲಿಸುವುದಕ್ಕಿಂತ ಹೆಚ್ಚಿನ ಕಠಿಣತೆಯನ್ನು ಸೂಚಿಸುತ್ತದೆ, ಮತ್ತು ಆ ರೇಟಿಂಗ್‌ಗಳಲ್ಲಿನ ಅಂತರ-ರೇಟರ್ ವ್ಯತ್ಯಾಸ ಹೆಚ್ಚಾಗಿ ವರದಿಯಾಗುವುದೇ ಇಲ್ಲ.
