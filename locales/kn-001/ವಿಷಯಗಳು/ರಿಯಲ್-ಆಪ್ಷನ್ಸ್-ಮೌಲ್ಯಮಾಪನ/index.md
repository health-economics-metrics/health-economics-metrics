# ರಿಯಲ್ ಆಪ್ಷನ್ಸ್ ಮೌಲ್ಯಮಾಪನ

ರಿಯಲ್ ಆಪ್ಷನ್ಸ್ ಮೌಲ್ಯಮಾಪನವು ಹಣಕಾಸು ಆಪ್ಷನ್-ಬೆಲೆ ತರ್ಕವನ್ನು ನೈಜ (ಹಣಕಾಸು-ಮಾರುಕಟ್ಟೆಯಲ್ಲದ) ಹೂಡಿಕೆ ನಿರ್ಧಾರಗಳಿಗೆ ಅನ್ವಯಿಸುತ್ತದೆ — ನಿರ್ದಿಷ್ಟವಾಗಿ, ಯೋಜನೆ ಯಶಸ್ವಿಯಾದರೆ ನಂತರ ಅದನ್ನು *ವಿಸ್ತರಿಸುವ ಆಯ್ಕೆ*, ಅದಕ್ಕೆ ಬದ್ಧರಾಗದೆ. ಸರಳೀಕೃತ ಏಕ-ಅವಧಿ ದ್ವಿಪದ ಮಾದರಿ (Cox, Ross, Rubinstein, 1979) ಈ ನಮ್ಯತೆಗೆ ನೇರವಾಗಿ ಬೆಲೆ ಕಟ್ಟುತ್ತದೆ, "ಚಿಕ್ಕದಾಗಿ ಹೊರತಂದು ನೋಡೋಣ" ಎಂಬುದನ್ನು ಊಹೆಯಿಂದ ಬೆಲೆ-ಕಟ್ಟಿದ ಸಂಖ್ಯೆಯನ್ನಾಗಿ ಪರಿವರ್ತಿಸುತ್ತದೆ.

## ಇದು ಏಕೆ ಮುಖ್ಯ

ಸ್ಥಿರ NPV ಲೆಕ್ಕಾಚಾರ ಯೋಜನೆಯನ್ನು ಎಲ್ಲ-ಅಥವಾ-ಏನೂ-ಇಲ್ಲ ಪಣವಾಗಿ ಬೆಲೆ ಕಟ್ಟುತ್ತದೆ: ಇಂದಿನ ಪ್ರಮಾಣದಲ್ಲಿ, ಶಾಶ್ವತವಾಗಿ ಹಣ ನೀಡಿ ಅಥವಾ ಬೇಡ. ನೈಜ ಯೋಜನೆಗಳು — ವಿಶೇಷವಾಗಿ ಹಂತ ಹಂತದ ಡಿಜಿಟಲ್ ಆರೋಗ್ಯ ಹೊರತರುವಿಕೆಗಳು — ಅಪರೂಪವಾಗಿ ಹಾಗೆ ಪಣ ಕಟ್ಟಲ್ಪಡುತ್ತವೆ: ಆರೋಗ್ಯ ವ್ಯವಸ್ಥೆಯು ಚಿಕ್ಕ ಪೈಲಟ್‌ಗೆ ಹಣ ನೀಡಿ, ಏನಾಗುತ್ತದೆ ಎಂದು ನೋಡಿ, ಅದು ಕೆಲಸ ಮಾಡಿದರೆ ಮಾತ್ರ ಮುಂದಿನ ಹಣ ಬದ್ಧಗೊಳಿಸಬಹುದು. ಆ ನಮ್ಯತೆಗೆ ನಿಜವಾದ ಮೌಲ್ಯವಿದೆ, ಮತ್ತು ಅದನ್ನು ಕಡೆಗಣಿಸಿದರೆ ಹಂತ ಹಂತದ ಹೂಡಿಕೆಗಳನ್ನು ಒಂದೇ-ಬಾರಿಯವುಗಳಿಗಿಂತ ವ್ಯವಸ್ಥಿತವಾಗಿ ಕಡಿಮೆ ಮೌಲ್ಯೀಕರಿಸಿದಂತಾಗುತ್ತದೆ — ಸುರಕ್ಷಿತವೆಂದು ಕಾಣುವ ಹಂತ ಹಂತದ ಪ್ರಸ್ತಾವನೆಗೆ ಪ್ರತಿಫಲ ನೀಡಬೇಕಾದ ಖರೀದಿ ಪ್ರಕ್ರಿಯೆಗಳಿಗೆ ಇದು ನಿಖರವಾಗಿ ಉಲ್ಟಾ. ರಿಯಲ್ ಆಪ್ಷನ್ಸ್ ಮೌಲ್ಯಮಾಪನವು ನಮ್ಯತೆಗೇ ಬೆಲೆ ಕಟ್ಟುತ್ತದೆ, ಆದ್ದರಿಂದ ಹಂತ ಹಂತದ ಪ್ರಸ್ತಾವನೆಯನ್ನು ಮುಗ್ಧ NPV ಸಾಲಿನಲ್ಲಿ ಚಿಕ್ಕದಾಗಿ ಕಾಣುತ್ತದೆ ಎಂದು ದಂಡಿಸುವ ಬದಲು ಪೂರ್ಣ-ಬದ್ಧತೆಯ ಪರ್ಯಾಯದೊಂದಿಗೆ ನ್ಯಾಯಯುತವಾಗಿ ಹೋಲಿಸಬಹುದು.

## ಗಣಿತ

```
Risk-neutral probability of the "up" state:
  p = ((1 + risk_free_rate) − down_factor) / (up_factor − down_factor)

Expansion payoff in each state (floored at zero — expanding is optional):
  payoff_up   = max(project_value × up_factor   − expansion_cost, 0)
  payoff_down = max(project_value × down_factor − expansion_cost, 0)

Option value (discounted expected payoff):
  option_value = (p × payoff_up + (1 − p) × payoff_down) / (1 + risk_free_rate)

Expanded NPV = static_npv + option_value
```

ಯೋಜನೆಯ ಮೌಲ್ಯ ಮುಂದಿನ ನಿರ್ಧಾರ ಬಿಂದುವಿನ ವೇಳೆಗೆ ಏರುತ್ತದೆ (`up_factor`) ಅಥವಾ ಇಳಿಯುತ್ತದೆ (`down_factor`). ವಿಸ್ತರಣೆಯನ್ನು ಆ ಸ್ಥಿತಿಯಲ್ಲಿ ಲಾಭದಾಯಕವಾದರೆ ಮಾತ್ರ ಚಲಾಯಿಸಲಾಗುತ್ತದೆ — ಪ್ರತಿಫಲ ಸೊನ್ನೆಗೆ ಮಿತಿಯಾಗಿರುವುದೇ ಇದನ್ನು ಬಾಧ್ಯತೆಯಲ್ಲ, ನಿಜವಾದ *ಆಪ್ಷನ್* ಆಗಿಸುತ್ತದೆ. ಮೊದಲು ಮಾಹಿತಿ ಸಂಗ್ರಹಿಸುವ ಆಯ್ಕೆಗೆ ಬೆಲೆ ಕಟ್ಟಲು, ನಂತರ ವಿಸ್ತರಿಸುವ ಆಯ್ಕೆಯಲ್ಲ, [ಪರಿಪೂರ್ಣ ಮಾಹಿತಿಯ ನಿರೀಕ್ಷಿತ ಮೌಲ್ಯ](../ಪರಿಪೂರ್ಣ-ಮಾಹಿತಿಯ-ನಿರೀಕ್ಷಿತ-ಮೌಲ್ಯ/) ನೋಡಿ. ಆ ನಿರ್ಧಾರ ಕೈಗೊಳ್ಳಲು ಕಾಯುವ ವೆಚ್ಚಕ್ಕಾಗಿ [ವಿಳಂಬದ ವೆಚ್ಚ](../ವಿಳಂಬದ-ವೆಚ್ಚ/) ನೋಡಿ.

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

`project_value = £1,000,000` ಇರುವ ಡಿಜಿಟಲ್ ಸೇವಾ ಪೈಲಟ್, ಮುಂದಿನ ನಿರ್ಧಾರ ಬಿಂದುವಿನ ವೇಳೆಗೆ 1.5× ಗೆ ಏರುವ ಅಥವಾ 0.5× ಗೆ ಇಳಿಯುವ ಸಾಧ್ಯತೆ, 8% ಅಪಾಯ-ರಹಿತ ದರ, ಮತ್ತು £600,000 ವಿಸ್ತರಣಾ ವೆಚ್ಚ:

```
p = (1.08 − 0.5) / (1.5 − 0.5) = 0.58

payoff_up   = max(1,000,000 × 1.5 − 600,000, 0) =  900,000
payoff_down = max(1,000,000 × 0.5 − 600,000, 0) = max(−100,000, 0) = 0

The floor matters: the option would NOT be exercised if the market
disappoints — the £600,000 expansion cost exceeds the £500,000 the
project would be worth in the down state.

option_value = (0.58 × 900,000 + 0.42 × 0) / 1.08
             = 522,000 / 1.08
             ≈ £483,333.33
```

ಆಪ್ಷನ್‌ನ ಮೌಲ್ಯವನ್ನು £200,000 ಸ್ಥಿರ-NPV ಆಧಾರಕ್ಕೆ ಸೇರಿಸಿದರೆ: ವಿಸ್ತರಿತ NPV = 200,000 + 483,333.33 ≈ **£683,333.33**. ಈ ಆಪ್ಷನ್ ಮೌಲ್ಯವಿಲ್ಲದೆ ಕೇವಲ £200,000 ಸ್ಥಿರ NPV ವರದಿ ಮಾಡಿದರೆ ಹಂತ ಹಂತದ ಯೋಜನೆಯ ನಿಜವಾದ ಮೌಲ್ಯವನ್ನು ಎರಡು ಪಟ್ಟಿಗೂ ಹೆಚ್ಚು ಕಡಿಮೆ ಅಂದಾಜಿಸಿದಂತಾಗುತ್ತದೆ.

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್‌ನೊಂದಿಗಿನ ಸಂಬಂಧ

ಇದು "ಈಗ ಕನಿಷ್ಠ ಆವೃತ್ತಿ ಹೊರತನ್ನಿ, ಅದು ಜನಪ್ರಿಯವಾದರೆ ಮತ್ತಷ್ಟು ಹೂಡಿಕೆ ಮಾಡುವ ಆಯ್ಕೆ ಉಳಿಸಿಕೊಳ್ಳಿ" ಎಂಬುದರ ಔಪಚಾರಿಕ ರೂಪ — ಹಂತ ಹಂತದ ಡಿಜಿಟಲ್ ಆರೋಗ್ಯ ಉತ್ಪನ್ನ ಹೊರತರುವಿಕೆಗೆ ನೇರವಾಗಿ ಸಂಬಂಧಿಸಿದೆ, [ವಿಳಂಬದ ವೆಚ್ಚ](../ವಿಳಂಬದ-ವೆಚ್ಚ/) ಮತ್ತು [WSJF/CD3](../wsjf-ಮತ್ತು-cd3/)ಯ ಅನಿಶ್ಚಿತತೆಯಡಿ ಕ್ರಮಬದ್ಧಗೊಳಿಸುವ ಚೌಕಟ್ಟಿಗೆ ರಚನಾತ್ಮಕವಾಗಿ ಸಮಾನಾಂತರ, ಮತ್ತು [ಪರಿಪೂರ್ಣ ಮಾಹಿತಿಯ ನಿರೀಕ್ಷಿತ ಮೌಲ್ಯ](../ಪರಿಪೂರ್ಣ-ಮಾಹಿತಿಯ-ನಿರೀಕ್ಷಿತ-ಮೌಲ್ಯ/) ಹಾಗೂ [ಮಾದರಿ ಮಾಹಿತಿಯ ನಿರೀಕ್ಷಿತ ಮೌಲ್ಯ](../ಮಾದರಿ-ಮಾಹಿತಿಯ-ನಿರೀಕ್ಷಿತ-ಮೌಲ್ಯ/)ಕ್ಕೆ ಪೂರಕ — ಮೂರೂ ಅನಿಶ್ಚಿತತೆಯಡಿ ನಮ್ಯತೆ ಅಥವಾ ಮಾಹಿತಿಗೆ ವಿಭಿನ್ನ ಕೋನಗಳಿಂದ ಬೆಲೆ ಕಟ್ಟುತ್ತವೆ.

## ಎಡವಟ್ಟುಗಳು

- **ಅದು ಅವಲಂಬಿಸಿರುವ ವಹಿವಾಟು-ಆಸ್ತಿ ಊಹೆ ಇಲ್ಲದೆ ಅಪಾಯ-ತಟಸ್ಥ ಬೆಲೆಯನ್ನು ಎರವಲು ಪಡೆಯುವುದು**: ರಿಯಲ್ ಆಪ್ಷನ್ಸ್ ಮಾದರಿಗಳು ಹಣಕಾಸು ಆಪ್ಷನ್ ಬೆಲೆಯಿಂದ ಅಪಾಯ-ತಟಸ್ಥ ಸಂಭವನೀಯತೆಯನ್ನು ಎರವಲು ಪಡೆಯುತ್ತವೆ, ಅದು ಆಧಾರ ಮೌಲ್ಯವು *ವಹಿವಾಟಾಗುವ* ಆಸ್ತಿ ಎಂದು ಊಹಿಸುತ್ತದೆ — ನಿಜವಾಗಿ ವಹಿವಾಟಾಗದ ನೈಜ ಯೋಜನೆಗೆ ಇದು ಮಾದರಿ ಅನುಕೂಲ, ಅಕ್ಷರಶಃ ಮಾರುಕಟ್ಟೆ ಸತ್ಯವಲ್ಲ.
- **`up_factor`/`down_factor` ಅನ್ನು ಮುಕ್ತ ನಿಯತಾಂಕಗಳೆಂದು ಪರಿಗಣಿಸುವುದು**: ದ್ವಿಪದ ಏರಿಕೆ/ಇಳಿಕೆ ಇನ್‌ಪುಟ್‌ಗಳು ಸ್ವತಃ ಸಮರ್ಥನೆ ಬೇಕಾದ ಊಹೆಗಳು, ಬಯಸಿದ ಉತ್ತರ ಬರುವಂತೆ ಆರಿಸಿದ ಮುಕ್ತ ನಿಯತಾಂಕಗಳಲ್ಲ.
- **ಆಪ್ಷನ್ ಮೌಲ್ಯವನ್ನು ಮಾತ್ರ ವರದಿ ಮಾಡುವುದು**: ರಿಯಲ್ ಆಪ್ಷನ್ಸ್ ಮೌಲ್ಯವು ಸ್ವತಂತ್ರ ಯೋಜನೆಯ ಸ್ಥಿರ NPVಗೆ *ಸೇರಿಸಲ್ಪಡುತ್ತದೆ* — ಆಪ್ಷನ್ ಮೌಲ್ಯವನ್ನು ಮಾತ್ರ ವರದಿ ಮಾಡಿ ಮೂಲ ಪ್ರಕರಣವನ್ನು ಬಿಡುವುದು ಸಾಮಾನ್ಯ ತಪ್ಪು; ಸ್ಥಿರ NPV ಋಣಾತ್ಮಕವಾಗಿದ್ದರೆ ಅದು ಪ್ರಕರಣವನ್ನು ಉತ್ಪ್ರೇಕ್ಷಿಸುತ್ತದೆ, ಮತ್ತು ಸ್ಥಿರ NPV ಅನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಬಿಟ್ಟರೆ (ಮೇಲಿನ ಬಿಡಿಸಿದ ಉದಾಹರಣೆಯಂತೆ) ಕಡಿಮೆ ಅಂದಾಜಿಸುತ್ತದೆ.
