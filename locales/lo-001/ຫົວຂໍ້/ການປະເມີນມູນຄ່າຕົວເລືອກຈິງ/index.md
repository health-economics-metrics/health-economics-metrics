# ການປະເມີນມູນຄ່າຕົວເລືອກຈິງ

ການປະເມີນມູນຄ່າຕົວເລືອກຈິງນຳໃຊ້ຕັກກະການຕັ້ງລາຄາຕົວເລືອກທາງການເງິນກັບການຕັດສິນໃຈລົງທຶນຈິງ (ທີ່ບໍ່ແມ່ນຕະຫຼາດການເງິນ) — ໂດຍສະເພາະ *ຕົວເລືອກໃນການຂະຫຍາຍ* ໂຄງການພາຍຫຼັງຖ້າມັນສຳເລັດ, ໂດຍບໍ່ມີພັນທະ. ແບບຈຳລອງ binomial ຮອບດຽວແບບງ່າຍ (Cox, Ross, Rubinstein, 1979) ປະເມີນຄວາມຍືດຫຍຸ່ນນີ້ໂດຍກົງ, ປ່ຽນ "ມາສົ່ງມອບນ້ອຍກ່ອນແລ້ວເບິ່ງ" ຈາກຄວາມຮູ້ສຶກເປັນຕົວເລກທີ່ມີລາຄາ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ການຄິດໄລ່ NPV ສະຖິດຕັ້ງລາຄາໂຄງການເປັນການພະນັນທັງໝົດຫຼືບໍ່ມີ: ໃຫ້ທຶນຫຼືບໍ່, ທີ່ຂະໜາດມື້ນີ້, ຕະຫຼອດໄປ. ໂຄງການຈິງ — ໂດຍສະເພາະການເປີດໃຊ້ສຸຂະພາບດິຈິຕອນເປັນໄລຍະ — ບໍ່ຄ່ອຍຖືກພະນັນແບບນັ້ນ: ລະບົບສຸຂະພາບສາມາດໃຫ້ທຶນໂຄງການນຳຮ່ອງນ້ອຍ, ເບິ່ງສິ່ງທີ່ເກີດຂຶ້ນ, ແລະ ຜູກມັດເງິນເພີ່ມກໍຕໍ່ເມື່ອມັນໃຊ້ໄດ້ຜົນ. ຄວາມຍືດຫຍຸ່ນນັ້ນມີມູນຄ່າຈິງ, ແລະ ການເມີນເສີຍມັນປະເມີນການລົງທຶນເປັນຂັ້ນຕ່ຳເກີນໄປຢ່າງເປັນລະບົບເມື່ອທຽບກັບການລົງທຶນຄັ້ງດຽວ, ເຊິ່ງກົງກັນຂ້າມພໍດີກັບຂະບວນການຈັດຊື້ທີ່ໃຫ້ລາງວັນຂໍ້ສະເໜີເປັນໄລຍະທີ່ເບິ່ງປອດໄພກວ່າ. ການປະເມີນມູນຄ່າຕົວເລືອກຈິງຕັ້ງລາຄາຄວາມຍືດຫຍຸ່ນເອງ, ເພື່ອໃຫ້ຂໍ້ສະເໜີເປັນໄລຍະປຽບທຽບກັບທາງເລືອກຜູກມັດເຕັມໄດ້ຢ່າງຍຸຕິທຳ ແທນທີ່ຈະຖືກລົງໂທດທີ່ເບິ່ງນ້ອຍກວ່າໃນບັນທັດ NPV ແບບໄຮ້ດຽງສາ.

## ຄະນິດສາດ

```
Risk-neutral probability of the "up" state:
  p = ((1 + risk_free_rate) − down_factor) / (up_factor − down_factor)

Expansion payoff in each state (floored at zero — expanding is optional):
  payoff_up   = max(project_value × up_factor   − expansion_cost, 0)
  payoff_down = max(project_value × down_factor − expansion_cost, 0)

Option value (discounted expected payoff):
  option_value = (p × payoff_up + (1 − p) × payoff_down) / (1 + risk_free_rate)

Expanded NPV = static_npv + option_value
```

ມູນຄ່າຂອງໂຄງການຈະເພີ່ມ (`up_factor`) ຫຼື ຫຼຸດ (`down_factor`) ພາຍໃນຈຸດຕັດສິນໃຈຖັດໄປ. ການຂະຫຍາຍຖືກໃຊ້ສິດກໍຕໍ່ເມື່ອມີກຳໄລໃນສະຖານະນັ້ນ — ພື້ນຂອງຜົນຕອບແທນທີ່ສູນແມ່ນສິ່ງທີ່ເຮັດໃຫ້ມັນເປັນ *ຕົວເລືອກ* ແທ້ແທນທີ່ຈະເປັນພັນທະ. ສຳລັບການຕັ້ງລາຄາຕົວເລືອກໃນການເກັບຂໍ້ມູນກ່ອນ, ແທນຕົວເລືອກໃນການຂະຫຍາຍພາຍຫຼັງ, ເບິ່ງ [ມູນຄ່າທີ່ຄາດໄວ້ຂອງຂໍ້ມູນສົມບູນແບບ](../ມູນຄ່າທີ່ຄາດໄວ້ຂອງຂໍ້ມູນສົມບູນແບບ/). ສຳລັບຕົ້ນທຶນຂອງການລໍຖ້າເພື່ອຕັດສິນໃຈນັ້ນ, ເບິ່ງ [ຕົ້ນທຶນຂອງຄວາມລ່າຊ້າ](../ຕົ້ນທຶນຂອງຄວາມລ່າຊ້າ/).

## ຕົວຢ່າງການຄິດໄລ່

ໂຄງການນຳຮ່ອງບໍລິການດິຈິຕອນທີ່ມີ `project_value = £1,000,000`, ອາດເພີ່ມເປັນ 1.5× ຫຼື ຫຼຸດເປັນ 0.5× ໃນຈຸດຕັດສິນໃຈຖັດໄປ, ອັດຕາປາສະຈາກຄວາມສ່ຽງ 8%, ແລະ ຕົ້ນທຶນການຂະຫຍາຍ £600,000:

```
p = (1.08 − 0.5) / (1.5 − 0.5) = 0.58

payoff_up   = max(1,000,000 × 1.5 − 600,000, 0) =  900,000
payoff_down = max(1,000,000 × 0.5 − 600,000, 0) = max(−100,000, 0) = 0

The floor matters: the option would NOT be exercised if the market
disappoints — the £600,000 expansion cost exceeds the £500,000 the
project would be worth in the down state.

option_value = (0.58 × 900,000 + 0.42 × 0) / 1.08
             = 522,000 / 1.08
             ≈ £483,333.33
```

ການເພີ່ມມູນຄ່າຕົວເລືອກໃສ່ເສັ້ນຖານ NPV ສະຖິດ £200,000: NPV ຂະຫຍາຍ = 200,000 + 483,333.33 ≈ **£683,333.33**. ການລາຍງານ NPV ສະຖິດ £200,000 ຢ່າງດຽວ, ໂດຍບໍ່ມີມູນຄ່າຕົວເລືອກນີ້, ຈະປະເມີນມູນຄ່າແທ້ຂອງໂຄງການເປັນໄລຍະຕ່ຳເກີນກວ່າສອງເທົ່າ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ນີ້ແມ່ນຮຸ່ນທາງການຂອງ "ສົ່ງມອບເວີຊັນຂັ້ນຕ່ຳດຽວນີ້, ຮັກສາຕົວເລືອກທີ່ຈະລົງທຶນເພີ່ມຖ້າມັນໄປໄດ້ດີ" — ກ່ຽວຂ້ອງໂດຍກົງກັບການເປີດໃຊ້ຜະລິດຕະພັນສຸຂະພາບດິຈິຕອນເປັນໄລຍະ, ຄ້າຍຄືໃນໂຄງສ້າງກັບກອບການລຳດັບພາຍໃຕ້ຄວາມບໍ່ແນ່ນອນຂອງ [ຕົ້ນທຶນຂອງຄວາມລ່າຊ້າ](../ຕົ້ນທຶນຂອງຄວາມລ່າຊ້າ/) ແລະ [WSJF/CD3](../wsjf-ແລະ-cd3/), ແລະ ເສີມ [ມູນຄ່າທີ່ຄາດໄວ້ຂອງຂໍ້ມູນສົມບູນແບບ](../ມູນຄ່າທີ່ຄາດໄວ້ຂອງຂໍ້ມູນສົມບູນແບບ/) ແລະ [ມູນຄ່າທີ່ຄາດໄວ້ຂອງຂໍ້ມູນຕົວຢ່າງ](../ມູນຄ່າທີ່ຄາດໄວ້ຂອງຂໍ້ມູນຕົວຢ່າງ/) — ທັງສາມຕັ້ງລາຄາຄວາມຍືດຫຍຸ່ນ ຫຼື ຂໍ້ມູນພາຍໃຕ້ຄວາມບໍ່ແນ່ນອນ, ຈາກມຸມທີ່ແຕກຕ່າງ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ຢືມການຕັ້ງລາຄາ risk-neutral ໂດຍບໍ່ມີສົມມຸດຖານຊັບສິນທີ່ຊື້ຂາຍທີ່ມັນອາໄສ**: ແບບຈຳລອງຕົວເລືອກຈິງຢືມຄວາມນ່າຈະເປັນ risk-neutral ຈາກການຕັ້ງລາຄາຕົວເລືອກທາງການເງິນ, ເຊິ່ງສົມມຸດວ່າມູນຄ່າພື້ນຖານເປັນຊັບສິນທີ່ *ຊື້ຂາຍໄດ້* — ສຳລັບໂຄງການຈິງທີ່ບໍ່ຊື້ຂາຍແທ້ ນີ້ແມ່ນຄວາມສະດວກຂອງການສ້າງແບບຈຳລອງ, ບໍ່ແມ່ນຂໍ້ເທັດຈິງຕະຫຼາດຕາມຕົວອັກສອນ.
- **ຖື `up_factor`/`down_factor` ເປັນພາຣາມິເຕີອິດສະຫຼະ**: ຂໍ້ມູນເຂົ້າ binomial ຂຶ້ນ/ລົງເອງແມ່ນສົມມຸດຖານທີ່ຕ້ອງການເຫດຜົນ, ບໍ່ແມ່ນພາຣາມິເຕີອິດສະຫຼະທີ່ເລືອກເພື່ອໃຫ້ໄດ້ຄຳຕອບທີ່ຕ້ອງການ.
- **ລາຍງານສະເພາະມູນຄ່າຕົວເລືອກ**: ມູນຄ່າຕົວເລືອກຈິງ *ບວກເພີ່ມ* ເຂົ້າກັບ NPV ສະຖິດຂອງໂຄງການທີ່ຢືນຢູ່ເອງ — ຂໍ້ຜິດພາດທົ່ວໄປແມ່ນລາຍງານສະເພາະມູນຄ່າຕົວເລືອກແລ້ວຖິ້ມກໍລະນີພື້ນຖານ, ເຊິ່ງຄາດເກີນຖ້າ NPV ສະຖິດຕິດລົບ ແລະ ຄາດຕ່ຳ (ຄືໃນຕົວຢ່າງຂ້າງເທິງ) ເມື່ອລະ NPV ສະຖິດອອກທັງໝົດ.
