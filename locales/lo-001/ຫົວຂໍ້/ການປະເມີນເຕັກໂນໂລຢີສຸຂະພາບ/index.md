# ການປະເມີນເຕັກໂນໂລຢີສຸຂະພາບ (HTA)

HTA ແມ່ນຂະບວນການທີ່ເປັນທາງການ ແລະ ເປັນສະຖາບັນ ເຊິ່ງລະບົບສຸຂະພາບໃຊ້ຕັດສິນວ່າເຕັກໂນໂລຢີ — ຢາ, ອຸປະກອນ ຫຼື ຊອບແວ — ຄຸ້ມຄ່າທີ່ຈະຈ່າຍຫຼືບໍ່. ມັນລວມຫຼັກຖານປະສິດທິຜົນທາງຄລີນິກເຂົ້າກັບການປະເມີນດ້ານເສດຖະກິດ ພາຍໃຕ້ວິທີການທີ່ເຜີຍແຜ່ ແລະ ບັງຄັບໃຊ້.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ຖ້າທ່ານຂາຍເຂົ້າບໍລິການສຸຂະພາບແຫ່ງຊາດ, ອົງກອນ HTA ອາດຈະຕັດສິນການເຂົ້າເຖິງຕະຫຼາດຂອງທ່ານໂດຍກົງ. ການຮູ້ຂະບວນການໃນທ້ອງຖິ່ນຄືການຮູ້ຜູ້ຄວບຄຸມມູນຄ່າທີ່ແທ້ຈິງຂອງທ່ານ:

- **NICE (ອັງກິດ)**: ການປະເມີນຕາມກົດໝາຍພາຍໃຕ້ *reference case* ທີ່ກຳນົດໄວ້ — QALY ຈາກ [EQ-5D](../eq-5d/), [ມຸມມອງ](../ມຸມມອງຂອງການວິເຄາະ/) NHS+PSS, [ການຫຼຸດມູນຄ່າ](../ການຫຼຸດມູນຄ່າ-ແລະ-ຄວາມມັກດ້ານເວລາ/) 3.5%, ຕ້ອງມີ [PSA](../ການວິເຄາະຄວາມອ່ອນໄຫວແບບຄວາມນ່າຈະເປັນ/) — ຕັດສິນທຽບກັບ £20k–£30k/QALY ພ້ອມ [ຕົວປັບຄວາມຮຸນແຮງ](../ຊ່ອງຫວ່າງ-qaly-ແລະ-ຕົວປັບຄວາມຮຸນແຮງ/); ເຕັກໂນໂລຢີພິເສດສູງສູງເຖິງ £100k+ ພ້ອມການຖ່ວງນ້ຳໜັກ.
- **ICER (ສະຫະລັດ, ບໍ່ແມ່ນລັດຖະບານ)**: ບົດລາຍງານຫຼັກຖານພ້ອມ *ເກນມາດຕະຖານລາຄາຕາມຜົນປະໂຫຍດດ້ານສຸຂະພາບ* — ລາຄາທີ່ຜະລິດຕະພັນຈະຄຸ້ມຄ່າດ້ານຕົ້ນທຶນທີ່ $100k–$150k ຕໍ່ QALY/evLYG — ໃຊ້ເປັນອຳນາດຕໍ່ລອງ; ພ້ອມທັງ "ການແຈ້ງເຕືອນຄວາມສາມາດໃນການຈ່າຍ" ດ້ານຜົນກະທົບຕໍ່ງົບປະມານ.
- **ການາດາ (CADTH → CDA-AMC)**: ການທົບທວນການຊົດເຊີຍທີ່ປະມານ CAD$50k/QALY; ໃນອະດີດໄດ້ຮ້ອງຂໍໃຫ້ຫຼຸດລາຄາໃນປະມານ 95% ຂອງການສົ່ງຄຳຮ້ອງ.

## ຄະນິດສາດ

ພະລັງຂອງ HTA ບໍ່ແມ່ນສູດ ແຕ່ແມ່ນ **ວິທີການທີ່ບັງຄັບ**: ທຸກການສົ່ງຄຳຮ້ອງຄິດໄລ່ [ICER](../ອັດຕາສ່ວນຄວາມຄຸ້ມຄ່າດ້ານຕົ້ນທຶນສ່ວນເພີ່ມ/) ດຽວກັນພາຍໃຕ້ກົດ reference-case ດຽວກັນ, ດັ່ງນັ້ນຜົນຈຶ່ງປຽບທຽບໄດ້ລະຫວ່າງຜະລິດຕະພັນ ແລະ ປີຕ່າງໆ. reference case ກຳນົດມາດຕະການຜົນລັບ, ເຄື່ອງມືຄ່າປະໂຫຍດ, ມຸມມອງ, ການເລືອກຕົວປຽບທຽບ, ອັດຕາຫຼຸດມູນຄ່າ, ຂອບເຂດເວລາ ແລະ ການວິເຄາະຄວາມບໍ່ແນ່ນອນ — ກຳຈັດທຸກລະດັບຄວາມເສລີທີ່ຜູ້ສະໝັກອາດໃຊ້ຫຼິ້ນກົນ.

## ຕົວຢ່າງການຄິດໄລ່

ຢາດິຈິຕອນຍື່ນຂໍການປະເມີນແບບ NICE:

```
Model: ΔC = +£450/patient, ΔE = +0.03 QALYs → ICER = £15,000/QALY ✓ under £20k
Reference-case checks:
  utilities from EQ-5D-5L with UK value set              ✓
  comparator = current care pathway (not "no treatment") ✓
  PSA: 71% probability cost-effective at £20k            ✓ (reported)
  severity modifier: shortfall below ×1.2 bounds         — none claimed
Recommendation: routine commissioning, with real-world data collection.
```

ການວິເຄາະທີ່ຜູ້ສະໝັກມັກເອງສະແດງ £9,000/QALY; reference case ຍູ້ມັນເປັນ £15,000 ໂດຍບັງຄັບໃຫ້ໃຊ້ຕົວປຽບທຽບທີ່ຊື່ສັດ. ຊ່ອງຫວ່າງນັ້ນແມ່ນ *ເຫດຜົນ* ທີ່ມີ reference case.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ສິ່ງທີ່ນຳໄປໃຊ້ຕໍ່ໄດ້ແມ່ນ **reference case ພາຍໃນ**: ວິທີການບັງຄັບດຽວສຳລັບທຸກ business case ຂອງເຄື່ອງມື/ແພລດຟອມ — ຕົວປຽບທຽບທີ່ປະກາດ, ຕົ້ນທຶນຫົວໜ່ວຍມາດຕະຖານ (ເບິ່ງ [ອັດຕາແຫ່ງຊາດ ແລະ ຕົ້ນທຶນຫົວໜ່ວຍ](../ອັດຕາແຫ່ງຊາດ-ແລະ-ຕົ້ນທຶນຫົວໜ່ວຍ/) ສຳລັບແບບແຜນ), ອັດຕາຫຼຸດມູນຄ່າຄົງທີ່, ການວິເຄາະຄວາມອ່ອນໄຫວທີ່ຕ້ອງມີ, ແມ່ແບບມາດຕະຖານ. "AMCP-dossier ສຳລັບເຄື່ອງມື" ທີ່ສົ່ງເຖິງສະພາແພລດຟອມເຮັດໃຫ້ຂໍ້ສະເໜີປຽບທຽບກັນໄດ້ ແລະ ການຫຼິ້ນກົນເຫັນໄດ້ຊັດ, ຄືກັນກັບທີ່ HTA ເຮັດສຳລັບຢາ. ເລີ່ມຕົ້ນນ້ອຍກວ່າ NICE: ແມ່ແບບສອງໜ້າພ້ອມປຶ້ມລາຄາທີ່ເຜີຍແຜ່ ດີກວ່າບໍ່ມີມາດຕະຖານເລີຍ.

ສຳລັບວິທີທີ່ແບບຈຳລອງ HTA ຫຼາຍຮອບຖືກຈຳລອງຈິງແບບກຸ່ມຕໍ່ຮອບ, ເບິ່ງ [ການຈຳລອງກຸ່ມ Markov](../ການຈຳລອງກຸ່ມ-markov/).

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ເບິ່ງ HTA ເປັນພຽງພິທີຫຼັງການອະນຸມັດຕາມກົດລະບຽບ** — ການອະນຸມັດ CE/UKCA/FDA ບອກວ່າຜະລິດຕະພັນປອດໄພ; HTA ຕັດສິນວ່າມັນ *ຄຸ້ມຄ່າທີ່ຈະຊື້* ຫຼືບໍ່. ອຸປະສັກຕ່າງກັນ, ຫຼັກຖານຕ່າງກັນ.
- **ສ້າງແບບຈຳລອງເສດຖະກິດຫຼັງການທົດລອງ** — ການສ້າງຫຼັກຖານຄວນອອກແບບຍ້ອນຫຼັງຈາກຄວາມຕ້ອງການຂອງ reference case.
- **ເມີນເສີຍຄວາມແຕກຕ່າງລະຫວ່າງເຂດອຳນາດ**: ICER ທີ່ຈ່າຍໄດ້ໃນສະຫະລັດທີ່ $120k/QALY ຈະບໍ່ຜ່ານ NICE ທີ່ £30k; ວາງແຜນຫຼັກຖານ ແລະ ລາຄາຕາມແຕ່ລະຕະຫຼາດ.
