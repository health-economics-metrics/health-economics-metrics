# ເສດຖະສາດຫົວໜ່ວຍຂອງຄລາວ (FinOps)

ເສດຖະສາດຫົວໜ່ວຍຂອງຄລາວແປງລາຍຈ່າຍຄລາວດິບໃຫ້ເປັນ**ຕົ້ນທຶນຕໍ່ຫົວໜ່ວຍຜົນຜະລິດ** — ຕໍ່ລູກຄ້າ, ຕໍ່ທຸລະກຳ, ຕໍ່ກໍລະນີທີ່ແກ້ໄຂ, ຕໍ່ token. ມັນຄືຄວາມສາມາດຂອງ FinOps ທີ່ປ່ຽນ "ໃບບິນ AWS ຂອງພວກເຮົາແມ່ນ £400k/ເດືອນ" ເປັນ "ການບໍລິການຄົນເຈັບໜຶ່ງຄົນມີຕົ້ນທຶນ £0.83."

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ຕົວເລກລາຍຈ່າຍລວມຕອບຄຳຖາມທີ່ສຳຄັນບໍ່ໄດ້: ຜະລິດຕະພັນມີປະສິດທິພາບຂຶ້ນ ຫຼື ຫຼຸດລົງ? ການເຕີບໂຕປັບປຸງ ຫຼື ທຳລາຍກຳໄລ? ເຮົາຄວນຄິດຄ່າບໍລິການເທົ່າໃດ? ຕົ້ນທຶນຕໍ່ຫົວໜ່ວຍຕອບທັງສາມ. ສຳລັບສຸຂະພາບດິຈິຕອນໂດຍສະເພາະ "ຕົ້ນທຶນຕໍ່ກໍລະນີທີ່ແກ້ໄຂ" *ຄື*ຕົ້ນທຶນຫົວໜ່ວຍຂອງບໍລິການສຸຂະພາບ — ປຽບທຽບໄດ້ໂດຍກົງກັບຕົວເລກ[National Cost Collection](../ອັດຕາແຫ່ງຊາດ-ແລະ-ຕົ້ນທຶນຫົວໜ່ວຍ/)ທີ່ຜູ້ຊື້ບໍລິການໃຊ້ກັບທຸກບໍລິການອື່ນ ເຮັດໃຫ້ມັນເປັນພາສາທຳມະຊາດສຳລັບການຕີລາຄາເສັ້ນທາງດິຈິຕອນທຽບກັບແບບດັ້ງເດີມ.

## ຄະນິດສາດ

```
Unit cost = total allocated cost (incl. shared/platform costs) / units delivered

Two families:
  resource-efficiency units: cost/GB stored, cost/vCPU-hour, cost/token,
                             cost/build-minute
  business units:            cost/customer, cost/transaction, cost/consultation,
                             cost/case-resolved

Marginal vs average discipline applies (marginal-vs-average-cost.md):
committed/reserved spend makes marginal unit cost ≈ 0 until the next
commitment step — price expansion decisions at marginal, efficiency
trends at average.
```

## ຕົວຢ່າງການຄິດໄລ່

ບໍລິການຄັດແຍກຄົນເຈັບດິຈິຕອນ: ລາຍຈ່າຍຄລາວ £62,000/ເດືອນ (ການຄຳນວນ £30k, ຂໍ້ມູນ £18k, ການຈັດສັນແພລດຟອມຮ່ວມ £14k) ຈັດການກໍລະນີຄັດແຍກ 380,000 ກໍລະນີ/ເດືອນ:

```
Average cost per episode = 62,000 / 380,000 ≈ £0.163

Commissioner comparison: telephone triage ≈ £8–12/call, GP consultation ≈ £42
→ digital episode runs at ~2% of the cheapest human alternative — the
channel-shift economics of gds-service-metrics.md, from the cost side.

Trend check: last year £0.21/episode at 240k episodes → improving scale
economics (fixed platform costs amortizing), worth a headline in the QBR.
```

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ເສດຖະສາດຫົວໜ່ວຍແມ່ນບ່ອນທີ່ທາງເລືອກດ້ານວິສະວະກຳກາຍເປັນສິ່ງທີ່ການເງິນອ່ານອອກ: ສະຖາປັດຕະຍະກຳທີ່ຫຼຸດຕົ້ນທຶນຕໍ່ກໍລະນີເຄິ່ງໜຶ່ງແມ່ນຂໍ້ໄດ້ປຽບດ້ານລາຄາ; ອັນທີ່ຂະຫຍາຍເກີນເສັ້ນຊື່ແມ່ນລະເບີດເວລາທີ່ເຫັນໄດ້ສະເພາະໃນຕົວຊີ້ວັດນີ້. ການປະຕິບັດທີ່ຖ່າຍທອດຈາກການຄິດຕົ້ນທຶນດ້ານສຸຂະພາບ: **ເຜີຍແຜ່ກົດການຈັດສັນ** (ຕົ້ນທຶນຮ່ວມບິດເບືອນຕົວເລກຕໍ່ຫົວໜ່ວຍຈົນກວ່າ PLICS ຈະມາດຕະຖານຄິດຕົ້ນທຶນລະດັບຄົນເຈັບ — ການຈັດສັນຕົ້ນທຶນແພລດຟອມຂອງທ່ານຕ້ອງການຄວາມເຂັ້ມງວດດຽວກັນ); **ເລືອກຫົວໜ່ວຍທີ່ຜູ້ຊື້ຄິດ** (ຜູ້ຊື້ບໍລິການຊື້ກໍລະນີ ບໍ່ແມ່ນ vCPU); ແລະ ປ້ອນຕົ້ນທຶນຕໍ່ຫົວໜ່ວຍເຂົ້າທຸກແບບຈຳລອງ [ICER](../ອັດຕາສ່ວນຄວາມຄຸ້ມຄ່າດ້ານຕົ້ນທຶນສ່ວນເພີ່ມ/) ແລະ [ຜົນກະທົບຕໍ່ງົບປະມານ](../ການວິເຄາະຜົນກະທົບຕໍ່ງົບປະມານ/) ເປັນຕົວຫານຕົ້ນທຶນທີ່ເຊື່ອຖືໄດ້. ສຳລັບຄຸນສົມບັດ AI ຫົວໜ່ວຍແມ່ນ token — ເບິ່ງ[ເສດຖະສາດຫົວໜ່ວຍຂອງການອະນຸມານ](../ເສດຖະສາດຫົວໜ່ວຍຂອງການອະນຸມານ/).

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ລະເລີຍຕົ້ນທຶນຮ່ວມ**: ຕົ້ນທຶນຕໍ່ຫົວໜ່ວຍທີ່ບໍ່ລວມການຈັດສັນແພລດຟອມ/ຄວາມປອດໄພ/on-call ຕ່ຳກວ່າຈິງ 30–50% ແລະ ລົ້ມເມື່ອກວດສອບ.
- **ຕົວຫານເພື່ອຄວາມງາມ**: "ຕົ້ນທຶນຕໍ່ API call" ເບິ່ງດີ; "ຕົ້ນທຶນຕໍ່ກໍລະນີຄົນເຈັບທີ່ສຳເລັດ" ໃຫ້ຂໍ້ມູນ.
- **ກຳນົດລາຄາຕາມຕົ້ນທຶນສະເລ່ຍສຳລັບການຕັດສິນໃຈສ່ວນເພີ່ມ**: ຄິດຄ່າທີມຕາມຕົ້ນທຶນຫົວໜ່ວຍສະເລ່ຍສຳລັບການໃຊ້ທີ່ຟຣີໃນສ່ວນເພີ່ມ ຂັບເຄື່ອນລະຄອນການຫຼີກລ່ຽງຄວາມສິ້ນເປືອງ (ເບິ່ງ[ລາຄາແຫ່ງຊາດ](../ອັດຕາແຫ່ງຊາດ-ແລະ-ຕົ້ນທຶນຫົວໜ່ວຍ/) ສຳລັບສະບັບ NHS ຂອງບັກແຮງຈູງໃຈນີ້).
