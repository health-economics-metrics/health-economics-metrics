# Продуктивност на разработчиците с ИИ

Показатели за това, което ИИ помощта при писане на код действително прави с инженерната продукция: честота на приемане на предложения, ускорения от контролирани проучвания, пропускателна способност на PR и задържане на код. Доказателствената база е наистина противоречива — което я прави идеален казус за разграничението ефикасност срещу ефективност, за чието справяне е създадена здравната икономика.

## Защо е важно

Двете най-цитирани контролирани проучвания сочат в противоположни посоки:

- **Peng et al. 2023 (RCT на GitHub Copilot)**: разработчиците завършиха нова задача за HTTP сървър **с 55,8% по-бързо** с Copilot (1 ч 11 мин срещу 2 ч 41 мин, n=95).
- **METR 2025 RCT**: опитни разработчици с отворен код, работещи по *собствените си зрели хранилища*, бяха **с 19% по-бавни** с ИИ инструментите от началото на 2025 г. (16 разработчици, 246 задачи) — докато *вярваха*, че са с 20% по-бързи.

И двете са добри проучвания. Противоречието е самото откритие: ефикасността при нови задачи не се пренася към ефективността в зряла кодова база, а *възприеманата* полза не може да замести измерената. Медицината има имена за двата феномена (обяснителни срещу прагматични изпитвания; проблемът с плацебото) и инструментариум за справянето с тях.

## Математиката

```
Acceptance rate  = accepted suggestions / shown suggestions
                   (GitHub telemetry ~30% avg; varies: SQL 45%, Python 35%, JS 28%)
Retention rate   = AI code surviving to merge / accepted AI code (~88% reported)
Speedup          = (t_control − t_AI) / t_control  (from controlled comparison ONLY)
Throughput delta = Δ merged PRs/dev/week (GitHub/Accenture field data: +8.7%)

Value model     = devs × time saved × loaded rate × utilization factor
                  — every term needs local measurement; see the tornado in
                  sensitivity-analysis.md, where time-saved dominates all
                  other parameters combined
```

## Решен пример

Организация с 500 разработчици пилотира асистент с подходящ контрол (съпоставени екипи, 3 месеца, предварително регистрирани показатели):

```
Pilot result: PR cycle time −18%; merged PRs +6%; CFR unchanged;
              self-reported time saved 45 min/day; measured task-level ≈ 15 min/day

Value the MEASURED number: 500 × 0.25h × 220d × £60 × 0.6 utilization
                          ≈ £990,000/year capacity (non-cash-releasing)
Cost: 500 × £39/mo × 12 ≈ £234,000/year
Net capacity ratio ≈ 4:1 — fundable, at one-third the self-reported claim.
```

Трикратната разлика между възприетото и измереното е констатацията на METR в реалния свят; бюджетирането по самоотчет би утроило реда с ползите.

## Връзка със софтуерното инженерство

Вносът от здравната икономика за всеки, който оценява ИИ инструменти: провеждайте **прагматични изпитвания** (вашата кодова база, вашите инженери, реални задачи — не демо задачи на доставчика); третирайте **честотата на приемане като прокси, не като резултат** (тя е [PPV](../оценка-на-клиничния-ии/) на предложенията от гледна точка на разработчика — високо приемане с ниско задържане е свръхдиагностика); свързвайте всяко увеличение на пропускателната способност с **проверка на стабилността** (DORA 2025: ИИ повишава пропускателната способност, вреди на стабилността — интервенция с нежелани ефекти изисква анализ на нетната полза, според [показателите DORA](../показатели-dora/)); и класифицирайте честно ползата като капацитет ([освобождаващи парични средства срещу неосвобождаващи](../спестявания-освобождаващи-парични-средства-срещу-неосвобождаващи/)).

## Често срещани грешки

- **Трансплантиране на проучвания на доставчици**: числа от RCT за нови проекти, приложени към работа по наследени кодови бази — точно грешката, която проучването на METR разкри.
- **Самоотчетът като измерване**: 20-процентният пункт разлика във възприятието е най-голямото известно отклонение в тази литература.
- **Раздуване на активността**: повече PR и повече код са активност, не резултати ([SPACE](../space-и-devex/)); съчетавайте с преработка и CFR.
- **Игнориране на кривата на учене**: измервания през втората седмица улавят ефекти на новостта в двете посоки; измервайте в установено състояние ([времеви хоризонт](../времеви-хоризонт/)).
